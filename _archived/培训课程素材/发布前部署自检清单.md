# 发布前部署自检清单（Pre-Deploy Checklist）

> 来源：部署 SOP（2026-08-15）。每次 push 前 + 部署后逐项勾选。
> 信条：**推了 ≠ 构建成功 ≠ 线上真生效**。每一项都要可度量、可硬验证。

## 一、提交前门禁（本地）
- [ ] `tsc --noEmit` 通过（退出码 0，零错误）
- [ ] `next build --webpack` 通过（Windows 必带 `--webpack`，Turbopack junction bug）
- [ ] `seo-critic` / `code-critic` 门禁通过（改动涉及内容/SEO 时）
- [ ] `node scripts/git-sync-check.mjs` PASS（本地 HEAD == 远端 main），或 `git ls-remote origin main` 比对 SHA

## 二、推送（SSH 直推避坑）
- [ ] 确认无 insteadOf 偷改协议：`git config --global --get-regexp 'url\.'` 不含 `https://github.com/.insteadof`
- [ ] 用显式 ssh URL 直推（绕过 insteadOf + 陈旧锁）：
  ```
  env -u HTTP_PROXY -u HTTPS_PROXY \
    GIT_SSH_COMMAND="ssh -o IdentitiesOnly=yes -o StrictHostKeyChecking=accept-new" \
    git push ssh://git@github.com/doujianwen/bookconv-frontend.git main
  ```
- [ ] 推送后本地 HEAD == 远端 main（再跑一次 git-sync-check）

## 三、部署与线上硬验证
- [ ] 等 75~90s（Vercel 生产构建 + 边缘生效）
- [ ] `curl` 生产站 `HTTP 200`
- [ ] `curl` 遇 500 先排除冷启动（≥60s 复测），再判 bug
- [ ] **抓线上 JS chunk grep 关键字符串**确认代码真落地（不只看 200）：
  ```
  curl -s "https://www.bookconv.com/convert/mobi-to-epub" -o page.html
  grep -oE '/_next/static/[^"]+\.js' page.html | sort -u > chunks.txt
  while IFS= read -r c; do
    curl -s "https://www.bookconv.com$c" -o chunk.js
    grep -qE '你的关键字符串' chunk.js && echo "MATCH -> $c"
  done < chunks.txt
  ```
- [ ] 验证 DOM 剥离 `<script>` 块后再 grep（RSC flight payload 污染匹配）

## 四、后台配置（代码改完 ≠ 有数）
- [ ] GA4 事件名对齐（代码事件名 vs 后台建的自定义事件名一致）
- [ ] 在 GA4 Admin → Events 把关键事件「标记为关键事件」
- [ ] （可选）GA4 Realtime / DebugView 看事件流确认触发
