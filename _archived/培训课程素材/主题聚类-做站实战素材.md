### 典型工作内容（课程可引用）
- **soft-404**：phantom conversion pages 返回 200 → 改为从 CONVERSION_MAP 派生 sitemap + `dynamicParams=false` + `notFound()`。
- **hreflang**：middleware 保留 epub-to-docx→epub-to-word 301；localePrefix as-needed；canonical 不硬编码 `/en`。
- **内部链接**：87 内容页 / 185 编辑内链 / 通用锚文本 0；P0/P1/P2 修复断链。

### 可复用经验（写课要点）
1. soft-404 是收录杀手——phantom 页必须 404，否则 Google 视为低质。
2. 一页吃整簇：同意图变体合并到最强词页，禁止每个变体一页（cannibalization）。
3. canonical / hreflang / sitemap 必须单一数据源派生，杜绝手写出错。
4. 新站天花板：页面优化约 30–40 名，上首页靠外链 + 域名权威。

- **8/04~**：错误校正 / critic agent（conversion-verifier）：魔数 / 内容丢失 / 乱码 / 图片丢失校验，queue 自动内联。

### 典型工作规划（课程可引用）
- "先确定 auto-run vs manual 运行模式再落地 critic agent；按 ROI 优先级推进。"

### 典型工作内容（课程可引用）
- 同步转换：`0bc2b77` run conversion synchronously in-request on Vercel (no Redis/worker)。
- Calibre 后端委派：`607fa10` delegate to Calibre backend when `CONVERSION_BACKEND_URL` set。
- 输出验证：`verifyConversion` 纯纠错层，CRITICAL 一票否决。

### 可复用经验（写课要点）
1. Serverless 上别硬上常驻 worker/Redis——同步转换 + 可选后端委派更稳。
2. 输出验证 > 输入验证：200 响应可能藏着静默失败（乱码/丢图）。
3. critic agent 用确定性规则即可，不必上 LLM。

- **8/15 GA4 埋点修复**（commit `ecf9ad5`）：根因 = 全代码库只有 `gtag('config')` 初始化、**无任何 `gtag('event')` 调用** → 8/10 建的 file_upload/conversion_complete 事件永不触发。修复 = 新增 `src/lib/ga.ts` 的 `trackGAEvent` 助手（SSR/无 GA 时 no-op），接入两条转换主链路（ToolPageClient 单文件主路径 + BatchUpload 批量），上传前/成功/失败三处触发。随 `28c1e45` 上线，**curl 抓线上 JS chunk 确认事件字符串已落地**（slug chunk + batch chunk 均含 `conversion_complete`/`file_upload`）。

### 典型工作规划（课程可引用）
- "GSC 拉数前先定维度（query vs date），否则增长曲线算错。"
- "GA4 自定义事件要前后端对齐：后台建事件 + 前端 `gtag('event')` 触发 + 标记为关键事件，三步缺一不可。"

### 可复用经验（写课要点）
1. GSC API 拉数必须固定维度（query vs date），混用会算错增长曲线。
2. 有排名关键词数 = 最诚实的爬坡指标，比展示量稳。
3. 数据不可用即报 unknown，绝不伪造（曾用 Math.random 填数骗自己）。
4. **GA4 事件空 = 不是后台没建，是前端没触发**：只 `gtag('config')` 初始化永远不出事件，必须显式 `gtag('event')`。验证用 GA4 Realtime/DebugView，不是看报表。
5. **线上生效要硬验证**：curl 抓 `/_next/static/*.js` chunk grep 关键字符串，比"部署成功"提示可靠。

### 可复用经验（写课要点）
