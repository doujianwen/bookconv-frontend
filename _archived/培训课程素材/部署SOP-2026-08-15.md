# 部署 SOP：bookconv.com 一键部署 + 线上生效验证

> 整理自 2026-08-15 实战。适用：一人站点的「push → 部署 → 真验证」闭环。
> 核心信条：**推了 ≠ 构建成功 ≠ 线上真生效**。每一步都要可度量、可硬验证。

---

## 0. 为什么需要这份 SOP（背景坑）

一人开发最容易踩的部署错觉：**看到 "Deployment ready" 就以为线上有你的代码**。

本项目真实踩过的坑：
- **Vercel Git 关联错配**：Vercel 项目 `ebook-converter-ymfg` 的 Git 曾指向**旧仓库** `doujianwen/ebook-converter`（main=`e76e43d`），而真实代码在 `doujianwen/bookconv-frontend`（main=`af5434b`）。推送 `bookconv-frontend` 永不触发 Vercel 构建，且点 Redeploy 会从旧仓重建、覆盖 Pro 修复。
- **本地 tracking ref 不落盘**：Windows 下 `git rev-list HEAD..origin/main` 的 behind/ahead 依赖本地 tracking branch，该 ref 可能写不进磁盘 → 产出 **FALSE behind=0 假象**（曾误判已同步，实则远程是孤儿分支）。
- **冷启动**：Vercel 函数冷启动首访可能 60s+，curl 遇 500 先排除冷启动再判 bug。

**修复后的正确架构**（现状）：仓库根 `.github/workflows/vercel-deploy.yml` 在 push→main 时调 Vercel API，明确锁定：
- `name=ebook-converter-ymfg`
- `repoId:1312872088`（bookconv-frontend，正确仓库）
- `target:production`
- `sha=${{github.sha}}`

→ 部署的是正确仓库，不再从旧仓重建，也不会覆盖 Pro 修复。

## 1. 提交前门禁（本地必做，先过再推）

| 步骤 | 命令 | 通过标准 |
|---|---|---|
| 类型检查 | `node node_modules/typescript/bin/tsc --noEmit -p tsconfig.json` | 退出码 0，零错误 |
| 构建复现（Windows 必带 `--webpack`） | `NODE_OPTIONS="--use-system-ca" npx next build --webpack` | 构建成功 |
| 同步硬验证 | `node scripts/git-sync-check.mjs` | PASS（本地 HEAD == 远端 main） |

> 纪律：AI 代码未过 tsc/build 不得合入。本项目另有 seo-critic / code-critic 门禁，改动涉及内容/SEO 时一并跑。

## 2. Push（SSH 直推，避开 insteadOf 坑）

### 2.1 先查 insteadOf 陷阱
```bash
git config --global --get-regexp 'url\.'
```
若含 `url.https://github.com/.insteadof git@github.com:`，会**偷偷把 SSH 改写回 HTTPS** → 直连 HTTPS 被 reset / TLS 错。需先 unset：
```bash
git config --global --unset url.https://github.com/.insteadof
```

### 2.2 用显式 ssh URL 直推（绕过 insteadOf + 陈旧锁）
```bash
env -u HTTP_PROXY -u HTTPS_PROXY \
  GIT_SSH_COMMAND="ssh -o IdentitiesOnly=yes -o StrictHostKeyChecking=accept-new" \
  git push ssh://git@github.com/doujianwen/bookconv-frontend.git main
```
- 显式 `ssh://` 前缀不被 insteadOf 改写，真正走 SSH 22 直连。
- `env -u` 排除代理 env 干扰（本机 HTTPS 推送与代理 TLS 协商不兼容）。
- `id_ed25519` 已在沙箱且无需 passphrase 时非交互成功。

## 3. 触发部署（自动）

push 到 main 后，`.github/workflows/vercel-deploy.yml` **自动触发** Vercel 部署。
- 本地**无法手动重触发**（VERCEL_DEPLOY_TOKEN 是 GitHub Secret，本地无此 token）。
- 等 **75~90s** 再验证（Vercel 生产构建 + 边缘生效需要时间）。

## 4. 线上生效验证（关键！不能只信 "部署成功"）

### 4.1 连通性
```bash
curl -s -o /dev/null -w "HTTP %{http_code} time=%{time_total}s\n" \
  --max-time 20 "https://www.bookconv.com/convert/mobi-to-epub"
```
预期 `HTTP 200`。

### 4.2 硬验证：抓线上 JS chunk 确认你的代码真的进去了
不能只看页面 200——要用 **grep 线上 JS bundle** 确认特定字符串（如本次的 GA4 事件名）确实存在。

```bash
mkdir -p C:/Users/29537/_verify && cd C:/Users/29537/_verify
# 取页面里所有 /_next/static/*.js chunk
curl -s --max-time 30 "https://www.bookconv.com/convert/mobi-to-epub" -o page.html
grep -oE '/_next/static/[^"]+\.js' page.html | sort -u > chunks.txt
# 逐个 chunk 抓回，grep 你的事件字符串
while IFS= read -r c; do
  curl -s --max-time 30 "https://www.bookconv.com$c" -o chunk.js
  if grep -qE 'conversion_complete|file_upload|trackGAEvent|conversion_failed' chunk.js; then
    echo "MATCH -> $c ($(wc -c < chunk.js) bytes)"
  fi
done < chunks.txt
```

**本次实测结果**：
| 触发路径 | 路由 chunk | 结果 |
|---|---|---|
| 单文件转换（主路径） | `app/[locale]/convert/[slug]/page-c456ae9bf02cc886.js` | ✅ 含 `conversion_complete`/`file_upload`/`trackGAEvent` |
| 批量转换 | `app/[locale]/batch/page-fab4a31fb9270d15.js` | ✅ 含同事件字符串 |

→ 两条埋点路径都已进生产，GA4「关键事件数」报表会在下次真实用户转换后出数。

### 4.3 验证 DOM 必须剥离 `<script>` 块
Next/React 的 RSC flight payload 内嵌在 `<script>` 里。`curl | grep 'xxx'` 命中 ≠ 页面真渲染了该内容。正确姿势：
```bash
html=$(curl -s "https://www.bookconv.com/xxx")
echo "$html" | sed -e 's/<script[\s\S]*<\/script>//g' | grep '目标文案'
```

## 5. 常见踩坑清单（写课可直接引用）

1. **FALSE behind=0**：本地 tracking ref 写不进磁盘 → 永远用 `git ls-remote origin main` 比对真实 SHA，或跑 `node scripts/git-sync-check.mjs`（直接问 GitHub）。
2. **insteadOf 偷改协议**：每次接手新机器先查 `git config --global --get-regexp 'url\.'`。
3. **Vercel Git 关联旧仓**：在 Vercel 后台把 Git 仓库改关联为正确仓库，或用「项目级 token 触发部署」workflow 锁定 repoId。
4. **冷启动误判 500**：首访 ≥60s 复测，排除冷启动再定 bug。
5. **沙箱 push 可行**：只要不依赖改本地 config，用显式 ssh URL 直推即可绕过 insteadOf + 陈旧锁 `.git/config.lock`。
6. **本地无法手动重触发部署**：VERCEL_DEPLOY_TOKEN 是 GitHub Secret。

## 6. 给课程的启示（AI 实战开发课程素材）

- **部署可度量的人设**：不要只说"我部署好了"。展示 `git-sync-check` 硬验证 + curl 抓线上 bundle 确认代码落地——这才是可信的"可度量建站"。
- **自动化门禁四道闭环**：seo-critic（内容/死链）→ code-critic（重复块/规范）→ conversion-verifier（转换输出纠错）→ git-sync-check（部署一致性）。每一道都是确定性的，不靠"我记得"。
- **诚实展示踩坑 = 课程卖点**：Vercel Git 错配、FALSE behind=0、insteadOf 陷阱——这些不是缺陷，是"用 AI 建站"真实过程的价值。显式点出 AI 做了什么、哪里翻车、人怎么补位。
- **push ≠ 线上生效**：这一条最该写进第一课。学员最容易的错觉就是这一步。

## 7. 一键复现清单（发布前自检）

```
[ ] tsc --noEmit 通过
[ ] next build --webpack 通过（Windows）
[ ] git-sync-check PASS（或 git ls-remote 比对 SHA）
[ ] push 走 SSH 显式 URL（确认无 insteadOf 改写）
[ ] 等 75~90s
[ ] curl 生产站 HTTP 200
[ ] grep 线上 JS chunk 确认关键字符串存在
[ ] （可选）GA4 Realtime / DebugView 看事件流
```
