# 6. 产品技术 & 变现

**一句话职责**：让转换功能可用、付费链路通畅、用户体验不拖后腿。

**核心工作**：
- 转换引擎：Calibre/CloudConvert 管线、输入/输出格式验证、输出文件完整性。
- 用户系统：注册/登录/会话、JWT、用户存储持久化。
- 订阅计费：LemonSqueezy / Stripe checkout、webhook、Pro 状态查询、`/batch` 等 Pro 门禁。
- 性能与稳定性：Core Web Vitals、构建门禁、tsc、seo-critic、部署流水线。
- 变现 CRO：定价页、Pro 价值主张、转化漏斗优化。

**典型交付物**：
- API 路由、组件、状态模块、支付接入文档、`docs/upstash-setup-guide.md` 类部署清单。

**不做什么**：
- 不生产 SEO 内容正文（交给 3.内容生成）。
- 不直接做外链（交给 5.外链推广）。

**协作规则**：
- 所有代码必须过 `tsc --noEmit`、`seo-critic`、`next build --webpack` 三重门禁才能 push。
- 新建转换页前必须先确认后端能真实转换该格式对，避免软 404。
- Pro/支付相关改动需同步更新 4.数据分析 的监控指标和 7.增长监测&自动化 的健康检查。

## 跨模块通用纪律（适用于所有模块）

1. **入口唯一**：同一个需求不要同时在两个任务里聊；先在对应模块里闭环，再跨模块同步。
2. **数据不回传则不算完成**：内容上线 → 4 追踪；外链发出 → 4 追踪；代码上线 → 7 验证 → 4 追踪。
3. **破坏性操作必须先清单再确认**：删除文件、大规模改 URL、改支付逻辑，必须列影响范围并得用户确认。
4. **远程同步规则**：
   - 有价值文档必须 commit + push。
   - 临时素材（竞品截图、一次性脚本、本地 txt）原则上不进 git，定期由 7 清理。
   - push 后必须等 Vercel 部署并做真渲染验证。
5. **自我进化**：任何跨模块踩坑，触发纠错智能体，把教训沉淀为 MEMORY.md 硬规则。
