# 1. 用户意图洞察

**一句话职责**：搞清楚目标用户在搜什么、为什么搜、搜的时候处于哪个阶段。

**核心工作**：
- 搜索意图分类：Informational / Commercial Investigation / Transactional / Navigational。
- 关键词聚类：按格式、设备、场景、问题类型分组。
- SERP 意图验证：对同一关键词做「裸词 + 事务变体 + 西语/多语言」三视角复搜，避免误判。
- 痛点长尾挖掘：围绕转换失败、格式不兼容、设备不支持等真实痛点建词库。

**典型交付物**：
- 关键词×URL×排名追踪表、意图地图、缺口词清单、SERP 竞品分析报告中的「意图」章节。

**不做什么**：
- 不直接写内容正文（交给 3.内容生成）。
- 不直接改代码或页面（交给 2.SEO&GEO 或 6.产品技术 & 变现）。

**协作规则**：
- 产出的「意图词 + 优先级」是 2.SEO&GEO 和 3.内容生成 的输入。
- 发现的新缺口词需经 6.产品技术 & 变现 确认后端可转换后再建页。

## 跨模块通用纪律（适用于所有模块）

1. **入口唯一**：同一个需求不要同时在两个任务里聊；先在对应模块里闭环，再跨模块同步。
2. **数据不回传则不算完成**：内容上线 → 4 追踪；外链发出 → 4 追踪；代码上线 → 7 验证 → 4 追踪。
3. **破坏性操作必须先清单再确认**：删除文件、大规模改 URL、改支付逻辑，必须列影响范围并得用户确认。
4. **远程同步规则**：
   - 有价值文档必须 commit + push。
   - 临时素材（竞品截图、一次性脚本、本地 txt）原则上不进 git，定期由 7 清理。
   - push 后必须等 Vercel 部署并做真渲染验证。
5. **自我进化**：任何跨模块踩坑，触发纠错智能体，把教训沉淀为 MEMORY.md 硬规则。
