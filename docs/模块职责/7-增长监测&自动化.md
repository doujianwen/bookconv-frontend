# 7. 增长监测 & 自动化

**一句话职责**：让前面的模块可持续运行、可预警、可复盘。

**核心工作**：
- 部署与版本同步：git push、Vercel 构建验证、剥离 `<script>` 的真渲染检查。
- 健康检查自动化：Pro 链路门禁、关键页面可访问性、/api/health。
- 监控与告警：Sentry、GSC 异常、排名大幅下降、死链。
- 数据看板 / Looker Studio / 自动化报告。
- 仓库卫生：死配置文件清理、依赖管理、未提交临时文件清理。

**典型交付物**：
- 自动化任务配置、部署验证脚本、监控告警规则、每周健康报告。

**不做什么**：
- 不替代业务模块做决策，只负责「把状态和风险报出来」。

**协作规则**：
- 7 发现的问题按模块派单：渲染问题 → 6，内容更新 → 3，排名问题 → 2，数据异常 → 4。
- 自动化报告结果回写 `{项目}/.workbuddy/memory/YYYY-MM-DD.md`。

---

## 跨模块通用纪律（适用于所有模块）

1. **入口唯一**：同一个需求不要同时在两个任务里聊；先在对应模块里闭环，再跨模块同步。
2. **数据不回传则不算完成**：内容上线 → 4 追踪；外链发出 → 4 追踪；代码上线 → 7 验证 → 4 追踪。
3. **破坏性操作必须先清单再确认**：删除文件、大规模改 URL、改支付逻辑，必须列影响范围并得用户确认。
4. **远程同步规则**：
   - 有价值文档必须 commit + push。
   - 临时素材（竞品截图、一次性脚本、本地 txt）原则上不进 git，定期由 7 清理。
   - push 后必须等 Vercel 部署并做真渲染验证。
5. **自我进化**：任何跨模块踩坑，触发纠错智能体，把教训沉淀为 MEMORY.md 硬规则。
