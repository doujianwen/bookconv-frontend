## 为什么 v2 被归档

v2.1 开篇原话：

> 替代 `ai-automation-plan-v2.md`（v2 方向正确但脱离地基，本版拉回地面）

v2 的问题不是方向错误 —— 它的闭环、分级、KPI 框架是成立的。问题是**架构野心与地基现实脱节**：v2 描绘的是 Kafka/Pulsar + 强化学习 + 向量库 RAG + K8s 自动伸缩的 AIOps 蓝图，而当时项目的真实状况是审计脚本连 `require('fs')` 都缺、用 `Math.random()` 冒充队列长度、日志换行都是错的。

v2.1 基于实地诊断重写，把方案拉回可落地的地面。

## 为什么放在 archive/ 而不是直接删

v2 的框架思路仍是 v2.1 的骨架，且记录了一次「先设计后诊断」走偏的完整过程 —— 对后续做架构规划有参考价值：**先验证地基，再谈架构**。
