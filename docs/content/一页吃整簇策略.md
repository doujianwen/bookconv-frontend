# 一页吃整簇（One Page, One Cluster）——关键词簇合并策略

> 定位：内容策略方法论（新人必读）
> 适用范围：博客 / 指南 / 转换页的内容规划，与「一页一词长尾」互补
> 更新：2026-08-10

## 一、什么是「一页吃整簇」

**核心定义**：当多个关键词共享同一个搜索意图时（构成一个"簇"），不要为每个词各建一页，而是**建一个内容足够深的页面，把整簇所有变体吃下来**。

这是「一页一词」策略的反向补充，两者适用场景不同：

| 策略 | 适用场景 | 关键词关系 |
|------|---------|-----------|
| 一页一词长尾 | 词与词意图**不同** | 独立意图，各自成页 |
| **一页吃整簇** | 词与词意图**相同** | 同一意图的变体，合并成页 |

## 二、为什么要用（一页一词的三大坑）

以 `azw3 vs mobi` 簇为例，下面 5 个词在 Google 眼里是**同一个意图**（Kindle 用户想知道选哪个格式）：

- `azw3 vs mobi`
- `mobi vs azw3`（词序变体）
- `azw3 or mobi`（选择变体）
- `mobi or azw3 for kindle`（场景变体）
- `does azw3 work on kindle`（疑问变体）

如果建 5 个页面分别打，会踩三个坑：

1. **内容同质化**：5 篇都讲「AZW3 支持 CSS、MOBI 老、选 AZW3」→ Google 判定重复内容，互相蚕食（cannibalization）
2. **权重分散**：每个页面只分到 1/5 的权重，谁也排不上去——权重被稀释而不是集中
3. **权威不够**：新站域名权威本来就低，5 个薄页 = 5 个「权威不足」页面，一个都上不了首页

**一页吃整簇的好处**：
- **权重集中**：簇内所有词都指向同一 URL，累积的权威是 5 页分散的 5 倍
- **主题权威（topical authority）**：一篇文章把主题讲透，符合 Google 对「专业回答」的判断
- **内链好做**：一个枢纽页，其他页面都能自然链进来
- **内容成本低**：一篇深度文 vs 五篇浅文，SEO 收益更高

## 三、怎么落地（分层覆盖法）

建页时按意图层次组织内容，让每个变体词都能命中：

| 内容元素 | 吃掉的变体 |
|---------|-----------|
| 主标题含主词（X vs Y） | 正反词序：`X vs Y` / `Y vs X` |
| 对比表格 + 明确结论段 | 选择意图：`X or Y` / `Y or X` |
| 场景段落（"Which should I use for my Kindle?"） | 场景变体：`for kindle` / `for kobo` 等 |
| FAQ 结构化字段（`faqs` → FAQPage JSON-LD） | 疑问变体：`does X work on...` / `can X read...` |
| 西语 / 多语言版 | 对应语言的查询变体 |

**操作要点**：
- 主 H1 用最强词（搜索量大 + 竞争适中的那个）
- 对比表用真实 `<table>`（渲染器已支持）——featured snippet 首选结构
- FAQ 用结构化 `faqs` 字段，自动发 FAQPage JSON-LD
- 词序变体靠标题 + 正文自然重复覆盖，**不要堆砌**（keyword stuffing 是违规）

## 四、判断标准：该合并还是该分开

**✅ 该吃整簇**（意图相同）：
- 对比类：`X vs Y`、`Y vs X`、`X or Y`、`compare X Y`
- 选择类：`X or Y for Z`、`which is better X or Y`
- 疑问类：`does X work on Z`、`can X read Y`、`what is X`

**❌ 不该合并**（意图不同）：
- `convert mobi to epub`（**交易意图**：想转换，用工具）vs `mobi vs epub`（**信息意图**：想了解，用博客）——不能硬并
- `epub-to-zip` 工具页 vs 「what is zip」博客页——工具页与科普页是两个意图
- 事务性词（带 buy / download / free converter）与信息性词分开

**判断口诀**：问自己"搜这个词的用户，点进来想要什么？"——答案相同就合并，答案不同就分开。

## 五、本站实战验证（2026-08-10 GSC 数据）

| 页面 | 策略 | 结果 |
|------|------|------|
| `/blog/azw3-vs-mobi`（英文） | 一页吃 azw3/mobi 对比整簇 | 簇 29 展示（15.9%）、位置 **21.4** |
| `/es/blog/azw3-vs-mobi`（西语） | 同上 + 西语查询 | 45 展示、位置 **15.2**（全站最佳） |
| `/convert/epub-to-zip` | 内容深化（一页吃 epub↔zip 变体） | 词位置 **9.7**、页面位置 19.5（进前 20） |
| `mobi→epub` 簇（对照） | 分散在多个页面，未成枢纽 | 53 展示但位置 **69.7**（权重分散的反例） |

**对照结论**：同样是大簇，azw3/mobi 靠一页吃整簇进入前 20，mobi→epub 分散多页深在 70——**权重集中 vs 分散，是能不能进前 20 的关键变量之一**。

## 六、新人自检清单（写页前过一遍）

- [ ] 这个关键词有哪些变体？（词序 / 场景 / 疑问 / 语言）
- [ ] 这些变体的搜索意图**相同**吗？（同 → 合并；不同 → 分开）
- [ ] 目标页面是簇内最强词吗？（搜索量大 + 竞争适中）
- [ ] 页面结构覆盖所有变体？（标题 / 对比表 / 场景段 / FAQ）
- [ ] FAQ 用结构化 `faqs` 字段了吗？（自动发 FAQPage JSON-LD）
- [ ] 对比表用真实 `<table>` 了吗？（featured snippet 捕获）
- [ ] 是否避免堆砌关键词？（自然重复即可）
