## 第 1 章 体系概览

### 1.1 我们在运营什么
- **站点**：bookconv.com（电子书格式转换站），规范域名 `www.bookconv.com`，Google Search Console 用网域属性 `sc-domain:bookconv.com`。
- **商业模式**：免费工具 + Pro 订阅（LemonSqueezy / Stripe 收银）。核心引擎 Calibre，部分格式（epub→pdf/mobi）经 CloudConvert。
- **内容规模（截至编制时快照，持续增长）**：87 个内容页 = 36 博客 + 21 指南 + 30 转换页；覆盖 15 种格式 / 26 个转换对。
- **站龄**：2026-07-26 上线，处于新站 SEO 爬坡期。

### 1.2 运营目标（务必对齐）
- 核心指标：**注册率 / 付费转化率 / 留存**。不是 PV、不是弹窗。
- 内容策略：**一页一词长尾，小词先行**；不外链弹窗；权重集中、主题权威。
- 增长靠**外链**把新站推上首页（页面优化天花板约 30–40 名，上首页靠域名权威 + 外链）。

### 1.3 运营体系的 8+1 模块
- **7 个业务模块**：1 用户意图洞察 · 2 SEO&GEO · 3 内容生成 · 4 数据分析 · 5 外链推广 · 6 产品技术&变现 · 7 增长监测&自动化
- **1 个横向支撑**：0 纠错智能体（流程错了 / 规则没被执行时触发复盘，把教训沉淀成硬规则）
- 协作心法：**单源（Single Source of Truth）→ 自动派生 → 数据闭环 → 自我进化**。

### 逐模块要点

**1 用户意图洞察**
- 意图四分类：Informational / Commercial Investigation / Transactional / Navigational。
- 关键词聚类（格式 / 设备 / 场景 / 问题类型）；同一词做「裸词 + 事务变体 + 西语」三视角复搜。
- 痛点长尾：围绕转换失败、格式不兼容、设备不支持建词库。
- 产出是 2 和 3 的输入；新缺口词需经 6 确认后端可转换再建页。

**2 SEO&GEO**
- 技术 SEO：索引健康、渲染 bug、软 404、canonical/hreflang、sitemap、死链、Core Web Vitals。
- 内容 SEO：标题 / H 结构、内链、schema（FAQPage / HowTo / SoftwareApplication / Article）、精选摘要。
- GEO：llms.txt、robots 放行 AI 爬虫（GPTBot / ClaudeBot / CCBot）、FAQ 结构化、E-E-A-T、实体 / 作者信息。
- 所有新页发布前必须过 seo-critic 门禁；上线 2–4 周由 4 做 GSC 复测再调优。

**3 内容生成**
- 博客：格式科普、对比、troubleshooting、设备指南。指南：深度教程、场景选型、Calibre / CloudConvert 说明。转换页：hero + sections + FAQ，英文无反引号，内链走真实 slug。
- 新建内容前确认目标页已被 6 确认可转换（避免软 404）；发布后由 2 做技术检查、4 追踪排名。

**4 数据分析**
- GSC 监控（词 / 展示 / 点击 / 位置 / 新词掉词）；转化漏斗（注册 / 付费 / 留存 / Pro 健康）；排名追踪表（关键词×URL，周 / 双周更新）。
- **统计显著性门槛**：≥10 展示或 ≥3 点击才判趋势，避免噪声决策。
- 是 1/2/3/5/6 的「裁判」：数据异常 → 派单对应模块；所有趋势结论须附时间窗口、样本量、置信度。

**5 外链推广**
- 资源发掘：目录站、资源页、PR、评测博客、工具目录；数字 PR / HARO / Connectively 专家评论与数据故事；未链接品牌提及转化、坏链修复。
- **铁律**：首页外链这轮完成前，落地 URL 指向首页，不擅自指内页（用户明确）。该轮已完成、用户确认后，内页外链可执行，落地可指内页（如 /convert/mobi-to-epub），按 ROI 优先、不滥用。
- 外链素材必须回流本仓库（避免与 Codex 状态漂移）；流量 / 排名变化由 4 追踪。
- 禁黑帽 / 购链 / 链接农场。

**6 产品技术&变现**
- 转换引擎（Calibre / CloudConvert 管线、输入 / 输出验证、输出完整性）；用户系统（注册 / 登录 / JWT / 存储持久化）；订阅计费（LemonSqueezy / Stripe、webhook、Pro 状态、`/batch` Pro 门禁）；性能与门禁（CWV、tsc、seo-critic、build）；变现 CRO（定价页、Pro 价值、漏斗）。
- 所有代码过 `tsc --noEmit` + `seo-critic` + `next build --webpack` 三重门禁才能 push；新建转换页前先确认后端能真实转换该格式对。

**7 增长监测&自动化**
- 部署与同步：git push、Vercel 构建验证、剥离 `<script>` 的真渲染检查。
- 健康检查自动化：Pro 链路门禁、关键页可访问性、`/api/health`。
- 监控告警：Sentry、GSC 异常、排名大跌、死链；数据看板（Looker Studio / 自动化报告）；仓库卫生（死配置清理、依赖、未提交临时文件）。
- 发现问题按模块派单：渲染 → 6，内容 → 3，排名 → 2，数据 → 4。

**0 纠错智能体（横向）**
- 触发：流程走错、结论被推翻、规则未被执行、反复踩坑。
- 机制：纠正捕获 → 反思复盘（self-improving，追问根因）→ 教训晋升（1 次候选 → 2 次观察 → 3 次用户确认升级硬规则）→ 固化到 `~/.workbuddy/MEMORY.md` 或 `{项目}/.workbuddy/memory/MEMORY.md`。
- 任何跨模块踩坑都触发它。

## 第 3 章 跨模块通用纪律（5 条铁律）

**【铁律 1】入口唯一**
同一需求不要同时在两个任务里聊；先在对应模块闭环，再跨模块同步。

**【铁律 2】数据不回传则不算完成**
内容上线 → 4 追踪；外链发出 → 4 追踪；代码上线 → 7 验证 → 4 追踪。没回流数据，任务不算完。

**【铁律 3】破坏性操作先清单再确认**
删除文件、大规模改 URL、改支付逻辑——必须列影响范围并得用户确认。

**【铁律 4】远程同步规则**
- 有价值文档必须 `commit + push`。
- 临时素材（竞品截图、一次性脚本、本地 txt）原则上不进 git，定期由 7 清理。
- push 后必须等 Vercel 部署并做**真渲染验证**（见 7.4）。

**【铁律 5】自我进化**
任何跨模块踩坑，触发纠错智能体，把教训沉淀为 MEMORY.md 硬规则。

## 第 5 章 端到端标准作业流（新人最常走的 5 条主线）

### 主线 A：新增一个内容页（博客 / 指南 / 转换页）
1. **1 用户意图洞察**：确认目标词意图与优先级；新缺口词先经 6 确认后端可转换。
2. **3 内容生成**：按规范写数据文件（路径见 7.2），正文全英文、无反引号、内链走真实 slug；填结构化 `faqs`。
3. **2 SEO&GEO**：发布前过 `seo-critic` 门禁；检查 schema（FAQPage 等）、canonical / hreflang、CTA URL（必须是 `/convert/{src}-to-{tgt}`，漏 `to` 会 500）。
4. **6 产品技术&变现**：注册到 `index.ts` / `CONTENT_MAP`，确认不触发软 404；过 tsc + seo-critic + build 三重门禁。
5. **7 增长监测&自动化**：`git push` → 等 Vercel 75–90s → 真渲染验证。
6. **4 数据分析**：上线后追踪排名；2–4 周 GSC 复测再调优。
7. **一致性校验**：sitemap / llms.txt / 列表页 三数一致。

### 主线 B：排名掉了 / 不收录 诊断修复
1. **4 数据分析**：用 GSC 数据定位（哪个 URL、哪个词、掉多少、样本量够不够）。
2. **2 SEO&GEO**：查软 404、canonical、死链、渲染 bug、CWV；剥离 `<script>` 后看真渲染。
3. 修复后 **7** 验证 → **4** 复测（accrual ≥10 展示再判趋势）。

### 主线 C：外链推广每周循环（weekly loop）
- 权威 SOP：`docs/weekly-guide-loop-2026-08-10.md`（本地，被 .gitignore 忽略）。
- 核心：**A 轨** 深化高展示老页（mobi-to-epub 为 P0） / **B 轨** 建 GSC 验证缺口页。
- 门禁：seo-critic 0/0 + tsc 0；部署后 curl 验；素材回流仓库。
- 落地 URL 按 ROI 优先，不滥用内页指向。

### 主线 D：代码改动上线（三重门禁 + 部署验证）
```bash
# 1) 本地门禁
npx tsc --noEmit
node scripts/seo-critic.mjs      # 退出码 1 = 门禁失败，必须修
node scripts/code-critic.mjs
NODE_OPTIONS="--use-system-ca" npx next build --webpack   # Windows 必须 --webpack

# 2) 提交与部署
git fetch && git status          # 确认 behind=0、无未提交
git push origin main             # HTTPS + Credential Manager，绝不强推

# 3) 等 75–90s Vercel 构建后真渲染验证（剥离 <script> 再断言）
curl -s https://www.bookconv.com/目标路径 | sed 's/<script[\s\S]*?<\/script>//g' | grep '预期内容'
```

### 主线 E：数据复盘与派单（GSC 周报）
- **4 数据分析** 出周报：展示 / 点击 / 位置 / 新词 / 掉词 + 转化漏斗。
- 趋势结论必须附 **时间窗口、样本量、置信度**；噪声（<10 展示或 <3 点击）不判趋势。
- 异常按第 4 章路由派单。

### 主线 E 实操：GA4 转化漏斗（怎么看转化断点）
> 前置：GA4 自定义关键事件（file_upload / conversion 类）已于 2026-08-10 新建，转化漏斗分析现已可做；此前只能看到页面互动层。完整导出规范见 `geo/GA4用户行为分析数据导出指南.md`。

1. **4 数据分析** 进 GA4 → 探索 → 漏斗探索，步骤按序设：转换页浏览（`/convert/*` 着陆）→ 上传点击 → 转换完成 →（可选）注册 / 付费。
   - 建议事件名（以 GA4 后台实际配置为准）：`file_upload_start` / `file_upload_complete` / `conversion_start` / `conversion_complete` / `conversion_error`。
2. **导出**：漏斗步骤表导出 CSV（探索 → 右上角导出）；新事件需累积数日才有样本，埋点当天不判趋势。
3. **复盘**：看每步「放弃率」——卡在「转换完成」说明后端 / 体验问题（派单 6）；卡在「上传点击」说明 CTA / 首屏引导弱（派单 3）；`conversion_error` 高说明格式 / 大小校验报错（派单 6）。
4. **与 GSC 交叉**：GA4 看"进来后干嘛"，GSC 看"怎么搜进来"，按着陆页 / 查询词对齐 = 完整图景；自然搜索着陆页表现（GA4 → 参与度 → 着陆页，筛 organic）直接决定内容深化 / 外链权重优先级。
5. **统计纪律**：同主线 E，趋势结论附时间窗口、样本量、置信度；新事件样本不足（<10 展示 / <3 点击）不判趋势。

## 第 7 章 环境与工具须知（新人必读的坑）

### 7.1 仓库与部署
- Git 根：`E:/一人公司/电子书格式转换站/`（ebook-converter 是子目录，提交路径带前缀）；`?? ../xxx` 是兄弟目录勿提交。
- 部署 = `git push origin main`（HTTPS + Credential Manager，绝不强推）；推送前 `git fetch` 确认 behind=0。
- Vercel 托管；push ≠ 构建成功，等 75–90s 再 curl 验证。
- 本地复现构建：`NODE_OPTIONS="--use-system-ca" npx next build --webpack`（**Windows 必须 --webpack**，Turbopack junction bug）。

### 7.2 内容系统（单源）
- 数据驱动自动派生：博客 `src/data/blog/*.ts`、指南 `src/data/guides/*.ts`、转换页 `src/data/content/*.ts` 的 `CONTENT_MAP`；注册到各自 `index.ts` → 列表 / sitemap / rss 自动派生。
- 全局导航在根 `src/app/layout.tsx`；内链 helper 全在 `src/lib/internal-links.ts`。
- 正文全英文（硬约束），禁反引号，内链用真实 slug；转换页无 es 字段（西语回退英文）。

### 7.3 i18n / canonical / CTA
- next-intl v4：`messages/en.json` 与 `es.json` 同步加同名键。
- localePrefix as-needed：英文无前缀，西语 `/es`；middleware 把 `/en/*` rewrite → 301。
- 链接 / canonical / hreflang **绝不硬编码 `/en`**；canonical 一律 `locale === 'es' ? '/es' : ''`，只由页级 `generateMetadata` 输出。
- **CTA URL 铁律**：写 `/convert/{src}-to-{tgt}`（带 `to`），非 `CONVERSION_MAP` 键 `{src}-{tgt}`；漏 `to` → 500。

### 7.4 门禁与验证
- `scripts/seo-critic.mjs`：退出码 1 = 门禁（博文注册 / llms.txt / 死链 / ES 键 / hreflang）。
- `scripts/code-critic.mjs`：重复块 / `.mdx` 违规。
- **验证 DOM 必须剥离 `<script>` 块**（RSC flight payload 会污染 grep 匹配）。
- **数据不可用即报 unknown，绝不伪造**。

### 7.5 Windows / Git Bash 路径坑
- 无 `sleep` / `seq`（用 `node -e "setTimeout(...)"`）。
- `/tmp` 对原生 Python 不可见；Write 的 `/tmp` 与 Bash 的 `/tmp` 不是同一物理路径 → 脚本 / 数据一律用 `C:/Users/29537/` 绝对路径。
- `[locale]` 方括号路径在 git pathspec 是通配符（用 `./` 或 `:(literal)`）。
- **agent-browser / 任何调用前置 `MSYS_NO_PATHCONV=1`**，且用 `C:/Users/...` 绝对路径，避免 `/c/` 被转成 `e:\c\`。**
- 出网代理用 `--proxy http://127.0.0.1:7897`（Chromium 在 Windows 不读环境变量代理）。

## 第 8 章 已知雷区与待办（新人要知道的坑）

**【雷区 1】不实声明**：pricing 写 Pro「Up to 50MB」，但 `convert-handler.ts` 硬编码 10MB。新文案**不得复述 50MB**。

**【雷区 2】用户存储不持久化**：`storage.ts` 用户表是内存 Map，Vercel 不跨请求 → 登录偶发失败。需持久化重构（待办 #4，未动）。改登录相关先想清楚。

**【雷区 3】Pro 链路前置依赖**：付费 → Pro 链路（webhook 用 `custom_data.email` 作订阅键、`/batch` Pro 门禁）前置条件：Vercel 须设 `REDIS_URL`=Upstash `rediss://`。E2E 验证待 Upstash 就绪（待办 #5）。

**【雷区 4】删除文件禁用 git rm / rm**：本沙箱 safe-delete 包装器会拦截 unlink 并**连带删除整个父目录**（实测 git rm 单文件 → blog/+content/+guides/ 整树被删，靠 git checkout HEAD 救回）。删博客 / 数据文件改用 `git mv 文件 ../_archived/`；彻底删除让用户本地做，AI 不动。

**【雷区 5】一页吃整簇**：同意图变体（对比 / 选择 / 疑问 / 场景 / 多语言）合并到最强词页面，禁止每个变体各建一页（cannibalization 让谁都排不上）；但交易意图 `convert X to Y` 与信息意图 `X vs Y` 必须分开。

**【雷区 6】软 404 / 幽灵页**：sitemap + generateStaticParams 从 CONTENT_MAP 派生 + dynamicParams=false + notFound()；middleware 保留 epub-to-docx→epub-to-word 301。新增转换对必须走单源注册。
