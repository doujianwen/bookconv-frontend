# 新人指导 — SERP 竞品分析与页面优化方法论（v2）

> **版本**：v2（2026-08-09 修订，修订来源 = `docs/审计-SERP竞品分析方法论-2026-08-09.md`）
> **用途**：拿到一批关键词后，如何在 Google 上逐批查询、记录竞品、分析对方排名优势、对照我们的页面找差距并产出改进建议。
> **适用场景**：关键词排名追踪表（`geo/关键词URL排名追踪表-*.md`）中的任意一批词。
> **前置条件**：先读 GSC 授权/培训文档（会拉 GSC 数据）+ `docs/新人指导-内链优化规则.md`（懂内链规范）。

---

## 0. 一句话流程（v2）

**选词 → 验基线 → 搜索(记参数) → 深析 Top3 + 扫 Top10(含 AI 概览/意图匹配/权威分层) → 对照(含 E-E-A-T/体验) → 评分定优先级 → 改进清单 → 实施 → 复测**

> **核心理念（给新人的一句话）**：竞品分析不是为了抄竞品，而是为了理解 Google / AI 认为什么样的页面最满足用户意图——然后在那个基础上做得更好。但在动手前，先确认我们自己的页面没坏。

---

## 1. 分批策略（不要一次全搜）

关键词追踪表通常有 60-100 个词。一次全搜既慢又难聚焦，按优先级分 3 批：

| 批次 | 范围 | 词数 | 目的 | 时机 |
|---|---|---:|---|---|
| **第 1 批** | P0/P1 核心追踪词 | ~15 | 最大杠杆先做（mobi→epub / azw3 / zip / txt 簇） | 立即 |
| **第 2 批** | P2 监测词 + 缺口词 | ~15 | 看竞品怎么承接这些意图，为建页/优化找方向 | 第 1 批完成后 |
| **第 3 批** | 用户意图词（GSC 暂无数据） | ~20 | 高量级词（djvu-to-pdf / pdf-to-epub 等），看 SERP 格局 | 按需 |

**选词原则**：
- 同一簇的词放一起搜（如 mobi→epub 簇 18 个词一次搜完），方便交叉对比
- 先搜已有 GSC 展示的词（有数据支撑），再搜纯意图词
- 缺口词（站上无页）单独搜——目的是看 SERP 门槛，决定是否建页
- **多语言**：本项目 `/es` 页有真实排名（如 `es/blog/azw3-vs-mobi` 位置 15.1）。西语目标词要**另搜西语 SERP**，不能只信英文 SERP
- **记录搜索参数**（P2 项，必做）：每批记 `locale`（如 en-US）、`设备`（桌面/移动）、`日期`、`工具`，保证结果可复现

## 2. 分析维度（10 项固定清单）

每个竞品页都查这 10 项，形成标准化对比（v1 是 6 项，v2 新增 §2.1 AI 概览、§2.4 意图匹配、§2.7 E-E-A-T、§2.8 体验、§2.9 内链 hub）。

### 2.1 SERP 特征
- **AI Overview（🔴 新增）**：2026 年大量 informational / commercial-investigation 查询顶部已是 AI 概览。必须记录：
  - 该词是否出现 AI Overview？
  - 它**引用了哪些域名/页面**（这些就是 GEO 竞品）？
  - 我们的目标页是否被引用？若否，差距在哪（实体清晰度？结构化数据？定义块够不够精炼）？
  - 行动：若竞品被 AI 引用而我们不是，把"提升被 AI 引用概率"写入改进清单（加 FAQPage/HowTo schema、加清晰定义段、加实体标注、部署/校验 llms.txt）。
- **精选摘要（Featured Snippet）**：有没有？是谁的？什么格式（段落/表格/列表）？
- **People Also Ask（PAA）**：记下前 3-4 个问题（这些就是 FAQ 目标）
- **图片包 / 视频包 / 知识面板**：通常 ebook 转换词知识面板 N/A，避免空等
- **其他经典特征（补全）**：sitelinks、评论星标、People also search for、Top Stories、Local pack、Shopping——逐项标 有/无/N/A
- **行动**：有精选摘要 → 我们要抢（同格式但更优内容）；有 PAA → FAQ 要覆盖；有 AI 概览 → 抢 GEO 引用

### 2.2 内容深度
- **字数**：竞品页大约多少字？（工具页 500-1000 字 / 内容页 1500-3000 字 / 综合指南 3000+ 字）
- **H2/H3 层级**：覆盖了哪些子话题？（记下标题大纲）
- **结构化元素**：有没有对比表 / 步骤列表 / FAQ / 代码块 / 截图？
- **行动**：如果竞品 2000 字我们 800 字 → 内容深度是主要差距

### 2.3 标题策略
- **title 标签**怎么写的？关键词在第几位？用了什么修饰词（Free / Online / Best / No Install）？
- **H1** 和 title 一样还是不同？
- **Meta description** 怎么写的？有没有 CTA？
- **标题模式对齐（P2 新增）**：识别 Top10 的**模态标题模式**（如 "[SRC] to [TGT] Converter — Free Online"），我们的标题应与之对齐——除非有差异化角度（如我们主打 "No Sign-up"）
- **行动**：若竞品标题是 "Free MOBI to EPUB Converter Online — No Install" 而我们是 "MOBI to EPUB" → 标题优化是快赢

### 2.4 内容格式（含意图-格式匹配，P1 新增）
- **页面类型**：工具页（中心是转换器 widget）/ 内容页（长文 + CTA）/ 混合页（工具在上半屏，内容在下半屏）
- **意图-格式匹配（🔴 P1 核心判定）**：
  1. 先判定查询意图：**T**=事务(我要转) / **C**=商业调研(比一比) / **I**=信息(我想懂) / **N**=导航
  2. 再看 Top10 格式分布
  3. 标注"**格式错配 = 超车机会**"：
     - 事务词却全是内容页 → 我们做工具页有机会
     - 信息词却全是工具页 → 我们做内容页（博客/指南）有机会
- **行动**：如果 Top 5 全是混合页而我们只有工具页 → 缺内容层；如果全是工具页而我们内容太多 → 可能过度

### 2.5 差异化卖点
竞品写了什么我们没有的？逐条记录：
- 隐私/安全承诺（SSL、自动删除文件、不上传服务器）
- 批量转换入口
- CLI / API 文档
- 设备兼容表（哪些 Kindle / Kobo / Nook 支持什么格式）
- 对比表（vs Calibre / vs CloudConvert / vs Zamzar）
- 用户评价 / 信任徽章
- DRM 说明
- **行动**：把竞品有、我们没有的列成清单，按性价比排序补上

### 2.6 URL 结构
- 是**子域**（converter.cloudconvert.com）还是**子目录**（cloudconvert.com/mobi-to-epub）还是**独立域名**（mobitoepub.com）？
- 路径深度：几层？
- **行动**：记录但通常不改我们的 URL 结构——这是架构决策，不是内容优化

### 2.7 信任与实体信号（E-E-A-T，P1 新增）
informational / commercial 词 Google 重 expertise/trust，必须评：
- **作者署名**：有作者吗？有资质/简介吗？
- **引用与来源**：引用了权威来源（Wikipedia / ISO / 官方文档）吗？
- **更新日期**：页面有 Last updated 吗？
- **品牌实体**：竞品是知名实体（Amazon / Calibre）还是匿名工具站？
- **About / 编辑政策**：有可查的实体背书吗？
- **行动**：若竞品有作者+引用+日期而我们全无 → E-E-A-T 是差距，优先补（本项目靠 llms.txt + 结构化数据 + 准确的格式事实建立信任）

### 2.8 页面体验 / 技术指标（P2 新增）
- **CWV**：LCP / INP / CLS（本项目 Next.js 通常快，可作差异化卖点）
- **移动端友好**：viewport / 触控区 / 字体可读性
- **HTTPS**：是否全站加密
- **行动**：若我们体验明显优于竞品，把"更快/更轻"写入信任卖点

### 2.9 内链 hub 观察（P2 新增）
- 竞品是否围绕"格式 hub"做内链聚类（如 azw3 页链到 mobi/kfx/epub 相关页）？
- **行动**：反哺本项目 `docs/新人指导-内链优化规则.md`——记录可借鉴的 hub 模式

## 3. 操作步骤（照做即可）

### 步骤 1：搜索并记录 SERP（含参数）

```
对每个关键词：
1. 用 WebSearch 搜索（英文主流量在英文；西语目标词另搜西语 SERP）
2. 记录搜索参数：locale / 设备 / 日期 / 工具
3. 记录 Top 10 有机结果：位置 / URL / 标题 / 描述
4. 记录 SERP 特征：AI Overview？引用了谁？精选摘要？PAA？图片包？视频包？
5. 标注我们的页面是否出现、在第几位
```

**输出格式**（每个关键词一行）：

| 位置 | URL | 域名 | 标题 | 类型 | 意图 | 我们的？ |
|---:|---|---|---|---|---|---|
| 1 | ... | ... | ... | 工具页/内容页/混合 | T/C/I | ❌ |
| 2 | ... | ... | ... | ... | ... | ❌ |
| ... | | | | | | |
| 8 | bookconv.com/convert/mobi-to-epub | bookconv | ... | 工具页 | T | ✅ |

### 步骤 2：深度分析 Top 3 + 扫描 Top 10

```
对 Top 3 竞品页：
1. 用 WebFetch 抓取页面内容
2. 按 §2 的 10 维度逐项分析
3. 记录到竞品分析卡
对 Top 4-10：
4. 用 WebSearch 结果 + 选择性 WebFetch 扫描，找格局模式（谁霸屏、什么格式主导）
```

**竞品分析卡模板**（每个竞品一张）：

```markdown
### 竞品 #[N]：[域名] — [URL]
- **位置**：#[N]
- **类型**：工具页 / 内容页 / 混合页
- **权威层级**：品牌站 / 中型工具站 / 博客 / UGC / 匿名工具站
- **意图匹配**：查询意图=T/C/I；Top10 格式分布=__；格式错配？__ 
- **字数**：约 [X] 字
- **标题**：[完整 title]（是否对齐 Top10 模态模式：__）
- **H1**：[完整 H1]
- **H2/H3 大纲**：
  - H2: ...
- **结构化元素**：□ 对比表 □ 步骤列表 □ FAQ □ 代码块 □ 截图 □ 视频
- **Schema**：□ FAQPage □ HowTo □ Article □ Breadcrumb □ 无
- **信任/实体信号**：□ 作者署名 □ 引用权威源 □ 更新日期 □ 品牌实体 □ 隐私承诺
- **差异化卖点**：
  - [卖点1]
- **SERP 特征**：□ AI Overview(引用__/未引我们) □ 精选摘要 □ PAA □ 图片包 □ 视频包
- **体验**：CWV≈__ / 移动端__ / HTTPS__
- **我们缺什么**：[具体差距]
```

### 步骤 2.5：基线体检（🔴 P0 前置，必做）

> 本项目历史上有渲染 bug 与软 404（`/convert/epub-to-word` 误链 404、`data/content` 嵌套未解包致 27 页走默认模板）。**用坏基线做差距分析会全盘错**，所以对照前必须先验我们的页活着：

```
对每个我们的目标页：
1. GSC URL Inspection 或 site:bookconv.com/convert/xxx 确认已收录
2. 确认 canonical 指向自身（非误指向 /en 或首页）、无软 404
3. 剥离 <script> 后确认正文真实渲染（RSC flight payload 会污染 grep——用 html.replace(/<script[\s\S]*?<\/script>/g,'') 后再查）
4. seo-critic.mjs 门禁 0 致命
→ 不健康的页先修，再比差距
```

### 步骤 3：对照我们的页面（含 E-E-A-T / 体验）

```
对我们的目标页：
1. 用 WebFetch 抓取其渲染后内容（先过步骤 2.5）
2. 同样按 §2 的 10 维度分析
3. 与 Top 3 竞品逐项对比（重点：信任信号、体验、结构化数据）
4. 列出差距清单
```

### 步骤 4：评分定优先级（go/no-go，P1 新增）

每词打分，避免新人凭感觉排优先级：

```
意图匹配(0-2) × 难度缺口(0-2) × 权威差距(0-2) × 内容缺口(0-2) → 总分(0-16)
- 12-16 = 高优先级（立即做）
- 6-11  = 中优先级（排期做）
- 0-5   = 低优先级（暂缓/放弃，看 ROI）
```

### 步骤 5：实施与复测（闭环，P1 新增）

```
1. 按改进清单落地（内容/结构化数据/内链/标题）
2. 等 2–4 周（让 Google 重新抓取+评估）
3. 复跑 GSC，对比位置/展示/点击
4. 更新 `geo/关键词URL排名追踪表-*.md`
5. 确认位移 → 未动则回到步骤 2 重析（可能竞品也变了）
```

## 4. 交叉分析（跨关键词找规律，含权威分层）

单批词分析完后，做一次交叉总结：

### 4.1 竞品格局（含权威分层，P1 新增）
- **谁在霸屏**？记录反复出现的域名
- **他们用什么策略**？按权威层级分别总结：
  - **品牌站**（Amazon / CloudConvert / Calibre）：靠域名权威，内容未必深
  - **中型工具站**（AnyConv / FreeFileConvert / MegaConvert）：靠工具 widget + 内容层
  - **博客/UGC**（formatdrop / blog.fileformat）：靠内容深度 + 长尾
- **DA 门槛**：诚实——我们拿不到精确 DA，但可看域名知名度+页面深度推断

### 4.2 SERP 特征规律
- 哪些词有 AI Overview？引用了谁？→ 抢 GEO 引用机会
- 哪些词有精选摘要？什么格式？→ 抢摘要机会
- 哪些词有 PAA？问题是什么？→ FAQ 目标
- 哪些词 SERP 全是工具页（无内容页）？→ 内容页有机会超车
- 哪些词格式错配？→ 超车信号（见 §2.4）

### 4.3 内容深度基准
- Top 5 竞品的平均字数是多少？→ 我们的目标字数
- 哪些子话题被多个竞品覆盖？→ 必须有的段落
- 哪些子话题只有 1 个竞品覆盖？→ 差异化机会

### 4.4 我们的定位（go/no-go）
- 哪些词我们完全没排名？→ 要么建页，要么放弃（看 ROI 评分 §3 步骤4）
- 哪些词我们排名差但竞品不强？→ 优化机会
- 哪些词竞品全是 DA 80+ 大站？→ 短期不打，等权威起来

## 5. 工具能力与限制（诚实版）

### 能做的
- **WebSearch**：搜索 Google，拿到 SERP 结果列表（位置 / URL / 标题 / 描述）+ 部分 AI Overview 线索
- **WebFetch**：深入抓取竞品/我们页面的实际渲染内容，分析 10 维度结构
- **GSC API**：拉取我们的真实展示/位置/点击（90 天窗口；可用"平均数"近似判断量级）

### 做不到的（需外部工具补充）
- **反向链接 / DA / DR**：需要 Ahrefs / SEMrush / Moz。有导出数据补进分析更完整
- **精确搜索量**：GSC 只给展示量（我们自己的），不给市场总量。需 Keyword Planner / Ahrefs
- **个性化 SERP**：因地区/语言/登录状态有差异。英文搜接近美国默认 SERP；西语词须另搜
- **实时排名追踪**：GSC 数据有 2-3 天延迟；实时排名需第三方工具

## 7. 常见误区（新人必读，含统计显著性正向阈值）

1. **不要只看谁排第 1**——要看 Top 10 整体格局。第 1 可能是 DA 90 大站我们短期打不过，但第 5-10 可能是 DA 30 小站我们可以超。所以"深析 Top3 + 扫 Top10"。
2. **不要只分析工具页**——很多词 SERP 里内容页排名比工具页好。Google 认为用户要"了解"而非直接"转换"。
3. **不要忽视 PAA / AI Overview**——PAA 问题是 FAQ 目标；AI 概览引用源是 GEO 竞品，覆盖它们能抢引用。
4. **不要照抄竞品内容**——分析结构与卖点，但用我们自己的数据和角度写。E-E-A-T 要求原创性。
5. **统计显著性阈值（正向定义）**：本项目 GSC 仅 66 词/148 展示，很多词 <10 展示。**达标阈值：90 天 ≥10 展示 或 ≥3 个数据点方可视为有效位置；否则标 low-confidence，仅作线索，不据此做重大决策。**
6. **改进清单要可执行**——不要写"提升内容质量"。要写"在 H2 'How to convert' 下新增 3 步操作列表 + 1 张对比表"。
7. **不要跳过基线体检（步骤 2.5）**——页面没收录/渲染坏就比差距，结论必错。本项目已有此教训。
