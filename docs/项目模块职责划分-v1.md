# ebook-converter 项目工作模块职责划分 v1

> 生效日期：2026-08-09  
> 对应左侧任务树：纠错智能体 / 1.用户意图洞察 / 2.SEO&GEO / 3.内容生成 / 4.数据分析 / 5.外链推广 / 6.产品技术 & 变现 / 7.增长监测&自动化  
> 核心纪律：**任何新需求只进一个模块入口**；跨模块产物通过文档/提交记录同步，避免在多个任务里重复讨论同一件事。

---

## 0. 纠错智能体（横向支撑层）

**一句话职责**：当流程走错、结论被推翻、规则未被执行时，触发复盘并把教训沉淀为可复用规则。

**核心工作**：
- 纠正捕获：识别 AI/流程中的错误、矛盾、遗漏。
- 反思复盘：用 self-improving 流程追问根因，不满足于表面修复。
- 教训晋升：1 次候选 → 2 次观察 → 3 次用户确认后，升级为跨项目或项目级硬规则。
- 规则固化：写入 `~/.workbuddy/MEMORY.md` 或 `{项目}/.workbuddy/memory/MEMORY.md`。

**典型交付物**：
- 踩坑学习报告、审计报告、规则修订 PR、流程 SOP 更新。

**不做什么**：
- 不替代任何业务模块的具体执行（不写代码、不做外链、不生成内容）。
- 不在没有事实证据的情况下定罪。

**触发词**：不对 / 搞错了 / 又这样 / 反思一下 / 你学到了什么 / 这个问题第几次了 / 自我进化 / 复盘。

## 1. 用户意图洞察

**一句话职责**：搞清楚目标用户在搜什么、为什么搜、搜的时候处于哪个阶段。

**核心工作**：
- 搜索意图分类：Informational / Commercial Investigation / Transactional / Navigational。
- 关键词聚类：按格式、设备、场景、问题类型分组。
- SERP 意图验证：对同一关键词做「裸词 + 事务变体 + 西语/多语言」三视角复搜，避免误判。
- 痛点长尾挖掘：围绕转换失败、格式不兼容、设备不支持等真实痛点建词库。

**典型交付物**：
- 关键词×URL×排名追踪表、意图地图、缺口词清单、SERP 竞品分析报告中的「意图」章节。

**不做什么**：
- 不直接写内容正文（交给 3.内容生成）。
- 不直接改代码或页面（交给 2.SEO&GEO 或 6.产品技术 & 变现）。

**协作规则**：
- 产出的「意图词 + 优先级」是 2.SEO&GEO 和 3.内容生成 的输入。
- 发现的新缺口词需经 6.产品技术 & 变现 确认后端可转换后再建页。

---

## 2. SEO & GEO

**一句话职责**：让搜索引擎和 AI 引擎能抓取、理解、信任并引用我们的页面。

**核心工作**：
- 技术 SEO：索引健康、渲染 bug、软 404、canonical/hreflang、sitemap、死链、Core Web Vitals。
- 内容 SEO：标题/H 结构、内链架构、schema（FAQPage / HowTo / SoftwareApplication / Article）、精选摘要优化。
- GEO：llms.txt、robots 放行 AI 爬虫、FAQ 结构化、E-E-A-T 信号、实体/作者信息。
- SERP 竞品方法论：定义分析维度、评分框架、复测节奏。

**典型交付物**：
- 技术 SEO 审计报告、SERP 竞品分析方法论、内链规则文档、schema 规范、GEO 优化清单。

**不做什么**：
- 不直接生产长内容正文（交给 3.内容生成）。
- 不处理支付/账号等技术功能（交给 6.产品技术 & 变现）。

**协作规则**：
- 所有新建/修改的页面在发布前必须过 seo-critic 门禁（死链、ES 键对齐、llms.txt 同步等）。
- 新页上线后 2–4 周由 4.数据分析 做 GSC 复测，再反馈给 2.SEO&GEO 调优。

---

## 3. 内容生成

**一句话职责**：按意图和 SEO 规范生产高质量、可排名的英文内容。

**核心工作**：
- 博客：格式科普、对比、 troubleshooting、设备使用指南。
- 指南：深度教程、场景化选型、Calibre/CloudConvert 使用说明。
- 转换页：hero + sections + FAQ，英文无反引号，内链走真实 slug。
- 内容更新：根据 GSC/SERP 审计结果优化现有页面。

**典型交付物**：
- `src/data/blog/*.ts`、`src/data/guides/*.ts`、`src/data/content/*.ts` 数据文件；内容发布检查清单。

**不做什么**：
- 不做关键词研究（由 1.用户意图洞察 输入）。
- 不调整 URL/路由/canonical（由 2.SEO&GEO 定规范）。
- 不处理后端转换能力问题（由 6.产品技术 & 变现 确认）。

**协作规则**：
- 新建内容前确认目标页已被 6.产品技术 & 变现 确认可转换（避免软 404）。
- 发布后由 2.SEO&GEO 做技术/结构化数据检查，由 4.数据分析 追踪排名。

---

## 4. 数据分析

**一句话职责**：用数据判断优先级、验证假设、发现异常，让其他模块的决策有依据。

**核心工作**：
- GSC 监控：关键词、展示、点击、位置、新词/掉词。
- 转化漏斗：注册率、付费率、留存、Pro 链路健康。
- 排名追踪：关键词×URL 对应表，每周/每两周更新。
- 统计显著性：设定门槛（如 ≥10 展示或 ≥3 点击才判定趋势），避免用噪声做决策。

**典型交付物**：
- GSC 周报/月报、关键词追踪表、转化漏斗看板、数据异常告警。

**不做什么**：
- 不替代业务模块做内容或代码。
- 不凭空给出优化建议（必须带数据证据）。

**协作规则**：
- 是 1/2/3/5/6 的「裁判」输入：数据异常 → 派发对应模块处理。
- 所有「 we saw X trend」类结论必须附时间窗口、样本量、置信度说明。

---

## 5. 外链推广

**一句话职责**：在首页外链优先的节奏下，提升域名权威和自然引用。

**核心工作**：
- 外链资源发掘：目录站、资源页、PR、评测博客、工具目录。
- 数字 PR / HARO / Connectively：专家评论、数据故事。
- 未链接品牌提及转化、损坏链接修复。
- 外链作战清单维护与 SOP 化。

**典型交付物**：
- `docs/ops/外链资源完整清单.md`、外链 outreach 模板、每周 loop SOP。

**不做什么**：
- 不做黑帽/购买链接/链接农场。
- 首页外链这轮完成前，落地 URL 指向首页，不擅自指内页（用户明确铁律）。

**协作规则**：
- 外链素材（截图、清单、SOP）必须回流到本仓库，避免 Codex 与本仓库状态漂移。
- 外链带来的流量/排名变化由 4.数据分析 追踪。

---

## 6. 产品技术 & 变现

**一句话职责**：让转换功能可用、付费链路通畅、用户体验不拖后腿。

**核心工作**：
- 转换引擎：Calibre/CloudConvert 管线、输入/输出格式验证、输出文件完整性。
- 用户系统：注册/登录/会话、JWT、用户存储持久化。
- 订阅计费：LemonSqueezy / Stripe checkout、webhook、Pro 状态查询、`/batch` 等 Pro 门禁。
- 性能与稳定性：Core Web Vitals、构建门禁、tsc、seo-critic、部署流水线。
- 变现 CRO：定价页、Pro 价值主张、转化漏斗优化。

**典型交付物**：
- API 路由、组件、状态模块、支付接入文档、`docs/upstash-setup-guide.md` 类部署清单。

**不做什么**：
- 不生产 SEO 内容正文（交给 3.内容生成）。
- 不直接做外链（交给 5.外链推广）。

**协作规则**：
- 所有代码必须过 `tsc --noEmit`、`seo-critic`、`next build --webpack` 三重门禁才能 push。
- 新建转换页前必须先确认后端能真实转换该格式对，避免软 404。
- Pro/支付相关改动需同步更新 4.数据分析 的监控指标和 7.增长监测&自动化 的健康检查。

---

## 7. 增长监测 & 自动化

**一句话职责**：让前面的模块可持续运行、可预警、可复盘。

**核心工作**：
- 部署与版本同步：git push、Vercel 构建验证、剥离 `<script>` 的真渲染检查。
- 健康检查自动化：Pro 链路门禁、关键页面可访问性、/api/health。
- 监控与告警：Sentry、GSC 异常、排名大幅下降、死链。
- 数据看板 / Looker Studio / 自动化报告。
- 仓库卫生：死配置文件清理、依赖管理、未提交临时文件清理。

**典型交付物**：
- 自动化任务配置、部署验证脚本、监控告警规则、每周健康报告。

**不做什么**：
- 不替代业务模块做决策，只负责「把状态和风险报出来」。

**协作规则**：
- 7 发现的问题按模块派单：渲染问题 → 6，内容更新 → 3，排名问题 → 2，数据异常 → 4。
- 自动化报告结果回写 `{项目}/.workbuddy/memory/YYYY-MM-DD.md`。

## 跨模块通用纪律

1. **入口唯一**：同一个需求不要同时在两个任务里聊；先在对应模块里闭环，再跨模块同步。
2. **数据不回传则不算完成**：内容上线 → 4 追踪；外链发出 → 4 追踪；代码上线 → 7 验证 → 4 追踪。
3. **破坏性操作必须先清单再确认**：删除文件、大规模改 URL、改支付逻辑，必须列影响范围并得用户确认。
4. **远程同步规则**：
   - 有价值文档必须 commit + push。
   - 临时素材（竞品截图、一次性脚本、本地 txt）原则上不进 git，定期由 7 清理。
   - push 后必须等 Vercel 部署并做真渲染验证。
5. **自我进化**：任何跨模块踩坑，触发纠错智能体，把教训沉淀为 MEMORY.md 硬规则。
