## 一、直接回答「是不是要加 hreflang」

**分页面类型，答案不同：**

| 页面类型 | hreflang 状态 | 需要做什么 |
|---|---|---|
| `/es/blog/*` | ✅ 三行齐全（en / es / x-default） | **不用加** |
| `/es/convert/*` | ✅ 三行齐全 | **不用加** |
| **`/es/guide/*`** | ❌ **缺 `hrefLang="es"`，只有 en + x-default 两行** | **要修** |

**上一轮我说「hreflang 完全正确」是错的**——当时只验证了 blog 页，没验证 guide 页。这次扫全站才发现 guide 路由漏传了参数。

## 二、核心 Bug：guide 路由漏传 `hasEsVersion`

### 2.1 代码定位

`src/app/[locale]/guide/[slug]/page.tsx:60`（修复前）：

```tsx
const { canonical, languages } = buildAlternates({
  locale: locale,
  slugPath: `/guide/${g.slug}`,
  pageType: 'leaf',
  // ← 缺少 hasEsVersion
})
```

对比 blog 页（`src/app/[locale]/blog/[slug]/page.tsx`）是正确的：

```tsx
const hasEsVersion = !!post.es
const { languages } = buildAlternates({ locale, slugPath, pageType: 'leaf', hasEsVersion })
```

`buildAlternates` 只有在 `hasEsVersion === true` 时才输出完整三件套，否则只输出 en + x-default。所以 **所有 `/es/guide/*` 页面都缺少 `hrefLang="es"` 声明**。

### 2.2 后果：被 Google 判为「英文版的替代页」

GSC 实测对比：

| URL | Coverage State | 含义 |
|---|---|---|
| `/es/guide/calibre-vs-online-converter`（真西语译文） | **Alternate page with proper canonical tag** | Google 认为它是英语版的替代页，**不单独索引** |
| `/es/guide/azw3-vs-mobi`（英文兜底） | Discovered - currently not indexed | 连抓取都没发生 |
| `/es/convert/epub-to-doc`（真西语译文） | URL is unknown to Google | 未发现 |
| `/es/blog/azw3-vs-mobi`（真西语译文） | Crawled - currently not indexed | 抓了但拒绝索引 |

**关键证据**：`/es/guide/calibre-vs-online-converter` 的线上 hreflang 实测：

```html
<link rel="alternate" hrefLang="en"        href="https://www.bookconv.com/guide/calibre-vs-online-converter"/>
<link rel="alternate" hrefLang="x-default" href="https://www.bookconv.com/guide/calibre-vs-online-converter"/>
<!-- 没有 hrefLang="es" -->
```

canonical 是自指的（指向 `/es/` 自己），但 hreflang 里没有声明「我是西语版本」。Google 因此无法确认这是一个独立的语言版本，只能把它当作英语页的镜像。

**这解释了为什么 11 个西语 guide 页全部无法正常索引。**

### 2.3 已修复

```tsx
const { canonical, languages } = buildAlternates({
  locale: locale,
  slugPath: `/guide/${g.slug}`,
  pageType: 'leaf',
  hasEsVersion: !!g.es,   // ← 新增
})
```

同时更新了 `src/lib/seo/alternates.ts` 里过时的注释（原文写「guide 全部无 es」，实际已有 10 篇西语译文）。

**影响面**：10 个有西语译文的 guide 页会从两行 hreflang 变为三行；16 个无译文的保持两行（正确）。

### 3.2 三类问题

**A. blog 页 CTA 硬编码英语（3 页）**

| URL | 问题 |
|---|---|
| `/es/blog/azw3-vs-mobi` | `Ready to Convert?` + `Try our free online converter` |
| `/es/blog/ebook-formats-explained` | 同上 |
| `/es/blog/mobi-to-epub` | 同上 |

代码根因：`src/app/[locale]/blog/[slug]/page.tsx:254-255` 完全没有 `isEs` 判断。

**已修复**：

```tsx
<h2>{isEs ? '¿Listo para convertir?' : 'Ready to Convert?'}</h2>
<p>{isEs ? 'Prueba nuestro conversor online gratuito:' : 'Try our free online converter:'}</p>
```

**B. guide 页整页英语兜底（1 页）**

`/es/guide/azw3-vs-mobi` —— `src/data/guides/azw3-vs-mobi.ts` 没有 `export const es`，所以 `/es/` 版本渲染英语正文，但 `<html lang="es">`。

这是**语言错配**，但属于「无译文」的客观情况，不是代码 bug。修复 hreflang 后它仍只有两行（正确，因为它确实没有西语版）。

**C. convert 页残留英文短语（2 页）**

`/es/convert/epub-to-doc`、`/es/convert/epub-to-txt` 正文是西语，但含 `No registration` 英文串。影响轻微，未处理。
