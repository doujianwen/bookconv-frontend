# 生产环境转换管线故障诊断（2026-08-04）

## 现象
对线上 `https://www.bookconv.com` 做端到端转换测试时，发现**所有需要 Redis 的接口都挂死，Vercel 返回 504 FUNCTION_INVOCATION_TIMEOUT**。

| 探测 | 方法 | 结果 |
|------|------|------|
| `GET /api/convert` | 仅方法检查，不碰 Redis | **405**（秒回，API 可达）✅ |
| `POST /api/convert`（epub→zip） | 入队 BullMQ（碰 Redis） | **504** / 客户端 20s 超时 ❌ |
| `GET /api/health` | `client.ping()` 探 Redis | **20s 超时无响应** ❌ |

三个点一致：凡碰 Redis 的路由全挂，不碰的秒回。

## 根因
1. **`REDIS_URL` 在 Vercel 上指向一个网络不可达的 Redis。**
   - `src/lib/redis.ts`：`getRedisClient()` 在 `REDIS_URL` 配置时返回 ioredis 实例（`lazyConnect:true`、`connectTimeout:3000`、`maxRetriesPerRequest:null`）。
   - `maxRetriesPerRequest:null` + ioredis 默认无限重连 → 对不可达主机，`ping()`/`connect()` 永远重试、**Promise 永不 resolve**。
   - 因此 `/api/health` 的 `Promise.all([checkRedis,...])` 永远卡住 → 函数超时。
2. **Vercel serverless 上根本没有常驻 worker 能消费队列。**
   - `queue.ts` 的 `startWorker()` 仅在 dev（及非 edge 运行时）自启；Vercel Node 函数虽会 import 触发它，但函数返回后即被冻结/回收，**job 永远不会被处理**。
   - 即便 Redis 通了，入队的 job 也会堆着无人消费，结果轮询会一直 202。
3. 结论：**BullMQ + Redis + 常驻 worker 这套异步架构在 Vercel serverless 上天然不成立**。当前 `REDIS_URL` 多半仍指向 VPS（或配置错误），Vercel 网络连不到 → 整条 Redis 链路挂死。

## 影响范围
- **生产环境 100% 转换失败**（全部 26 个格式，含刚做的 epub→zip）。
- 之前修的「下载 base64 桥接 + epub→zip 透传」代码本身正确，但**当前无法被触发**（POST 在入队阶段就挂了）。
- 用户早前「站看起来不太对劲」大概率正是此因。

## 修复方向（待用户拍板）
**方案 A（推荐，最快让产品可用）：Vercel 上改为「请求内同步转换」**
- POST 处理器直接调用 `executeConversion()` 跑 Calibre / epub→zip 透传，结果随响应内联返回（小文件走 `data:` base64，大文件落 R2/本地后给下载 URL）。
- **彻底移除对 Redis / 常驻 worker 的依赖**，在 Vercel 上自包含可跑。
- 代价：受 Vercel 函数超时约束（hobby 10s / pro 60s）。epub→zip 透传瞬时完成；常规小体积电子书 Calibre 转换通常在 60s 内；超大 PDF 等可能超限（可后续引入异步分片或专用 worker 服务）。

**方案 B：把后端搬到有状态平台**
- 用 Upstash Redis + 常驻 worker（VPS / Railway / Fly / Trigger.dev），Vercel 只做前端与 SSR，转换走后端 API。
- 保留原异步架构，但多一套部署与运维。

**方案 C（仅缓解，不够）：只把 `REDIS_URL` 配对**
- 能让 POST 入队成功返回 202，但**没有常驻 worker 消费**，job 仍堆着、结果轮询无限 202。**不能单独解决问题。**

## 代码层可顺带加固（无论选哪条路）
- ioredis 加 `maxRetriesPerRequest` 上限 + 有限 `retryStrategy`，让 Redis 不可达时**快速失败**（返回 503/清晰错误）而非挂死 504，避免雪崩式函数超时。

## 下一步
等用户确认走 A 还是 B。若选 A，改动集中在 `src/app/api/convert/route.ts`（同步执行 + 内联返回）与 `executeConversion` 的调用方式，epub→zip 透传与 base64 交付逻辑已就绪可复用。
