## 2. 分期重算结果（口径先行）

**窗口**：`2026-10-04 ~ 2026-11-03`，**31 天**（不是 30 天）。**所有 `file_upload` / `conversion_complete` / `conversion_failed` 均为事件数**，不是人、不是会话、不是任务。

| 指标（口径） | PRE 10-04~10-26 (23天) | POST 10-27~11-03 (8天) | 变化 |
|---|---:|---:|---|
| 日均活跃用户（`activeUsers`） | 13.13 | 17.25 | +31%（8天样本） |
| 日均上传（事件） | 8.04 | 11.50 | +43% |
| 上传 / 完成 / 失败（事件） | 185 / 117 / 71 | 92 / 72 / 48 | — |
| **完成率 = 完成/上传（事件比）** | **63.2%** | **78.3%** | +15.1pp ⚠️ 假象 |
| **终态成功率 = 完成/(完成+失败)** | **62.2%** CI[55.1, 68.9] | **60.0%** CI[51.1, 68.3] | −2.2pp，**Fisher p=0.720 不显著** |
| 前置失败（未发 `file_upload`） | 23 | 33 | — |
| 未归因 `(not set)` | **44（占失败 62%）** | 0 | 埋点差异 |
| 引擎失败 / 引擎侧成功率 | 48 / **UNKNOWN** | 15 / 82.8% | **不可比** |

**为什么完成率提升是假象**：前置失败（FILE_TOO_LARGE / QUOTA / 直传族）不发 `file_upload`，被排除在分母外。POST 期 48 次失败中 33 次是前置失败 → `完成+失败 = 120 > 上传 92`。用 `完成/上传` 比较，等于把「分母被削掉多少」当成了「能力变强多少」。改用终态口径后两期几乎相同（p=0.720）。

**为什么「引擎侧成功率 70.9%→82.8%（p=0.0466）」也不能用**：PRE 期 44/71 失败的 `error_code` 与**原始 error 文本**双双为 `(not set)`（两套维度实测均如此，集中在 10-04~10-11），它们既不在前置集合里，就被默认算成「引擎失败」，PRE 的 `engineFailed=48` 有 44 个是污染量 → **PRE 引擎侧成功率标 UNKNOWN**，两期不可比。即便忽略污染，本轮 2 次主检验的 Bonferroni α=0.025，p=0.0466 也未过校正，只能称「提示性」。

**稳健性**：POST 期 10-31 单日贡献 27 次上传（占该期 29.3%）。去掉该日后完成率 78.3%→**72.3%**、终态 60.0%→58.8%，改善幅度进一步缩水。

**三段敏感性**：S1 完成率 63.2% / 终态 62.2%；S2（迁移窗口 5天）85.7% / 61.0%；S3（稳定期 3天）72.0% / 59.0%。S2 的高完成率来自 20 次前置失败被排除在分母外，**不是引擎变好**。

**独立通道复核**：三份日快照（end=11-01/11-02/11-03）重叠日期 **0 不一致**；`daily_events` / `os_events` / `source_events` / `failed_by_format` / `failed_by_date_error_code` 五表合计全部闭合于 **277 / 189 / 119**；GA4 API 原始重取 31 天逐日与本地快照 **0 差异**。⇒ 数据本身可靠，**错的是口径与分期**。

### 新发现（非断言，登记）

- **B1**：`customEvent:error_code` **不带 `date` 维度**时只返回 `{null:2}`，不可用（探针 Q3 留证）。今后任何 error_code 聚合必须带 date 或按日累加。
- **B2**：Macintosh POST 期 `conversion_complete=3 > file_upload=2`，**物理不可能**（小样本事件归属/重复计数）。该行所有比率作废，标 UNKNOWN，不得入表。
- **B3**：独立探针首版按 header 字面量映射自定义维度，导致全部返回 `null`（**假阴性**）。已改为按位置取值并复跑，error_code 与主分析完全一致。教训：独立通道自身也要验维度映射，否则「独立复核」会反过来制造假证据。

## 5. Fact / Assumption / Unknown 与残余

**Fact**：31 天窗口与全部逐日数值；五表闭合；三快照 0 差异；独立 API 通道 0 差异；5 个变更点的文档/git 证据；所有 Fisher p 值、Wilson CI、z 值、file_size 分布。

**Assumption**：①10-27 作为用户指定分界（已用三段敏感性缓解）；②`PRE_UPLOAD_CODES` 归类沿用 `scripts/lib/ga-error-codes.mjs` 单一事实源（探针镜像，未 import）；③属性时区沿用现有 advanced 脚本的 dateRanges（未单独复验，11-04 曾实测 ≈UTC+2）。

**Unknown（不得当 Fact 引用）**：
- PRE 期 44 次 `(not set)` 的真实成因（埋点缺失 vs 事件参数丢失）——两套维度同时缺失，无法反解。
- PRE 期引擎侧成功率 → **UNKNOWN**；「引擎能力提升」不可判定。
- Macintosh POST 期 complete>upload 的归属异常（B2）。
- 任务级成功率：需 `job_id` 写入事件参数，当前 GA4 只有事件数。
- 各 OS / 来源分期的差异均未做多样本校正后显著性检验，全部为「样本不足 / 提示性」。

**残余风险（P1/P2，不阻断关闭）**：POST 期仅 8 天、PRE 23 天，样本不对等；10-31 单日权重过大；11-01 后 error_code 口径与前期不可比；`failed_by_date_format` 无「该格式上传总量」分母，故所有格式结论只能是**失败绝对数**，不能称**失败率**（上一轮正是踩了这个坑，本报告 §4 P1-1 已改述为「复测」而非「失败率高」）。
