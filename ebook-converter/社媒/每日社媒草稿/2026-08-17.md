## r/SideProject
**标题**：I automated my daily SEO data pull with AI — then lost a day to a self-check that trusted baidu's 200

**正文**：
Solo-building an ebook converter with AI writing most of the code. Today's war story is pure tooling, and it's a good cautionary tale about trusting AI-generated health checks.

**What AI did**
Wrote the whole GSC fetch pipeline (Python + google-api-python-client) and a "connectivity self-check" that pings a proxy and reports green/red. Also scaffolds my daily report + SVG. Fast, clean, looked correct.

**Where AI failed**
The self-check probed baidu. Baidu returned 200 (it's reachable in my region), so the script said "proxy fine." But my actual data path is Google APIs — and those were blocked (000). The 200 told the truth about baidu, a lie about what I cared about. I chased code bugs for hours on a non-bug.

**What I fixed**
- Changed the probe to oauth2.googleapis.com/token (the real auth endpoint). Target 200.
- Learned GET /token returns 404 — that's expected; only POST is accepted, and a 404 means TLS reached Google. So 404 = reachable, not broken.
- Root cause was Google traffic routed to direct instead of proxy; flipped it, data flowed.
- Turned the whole trap into a reusable skill so I never repeat it.

**The numbers that finally came through**
262 ranked keywords (+12), 1,413 impressions (+147), avg rank 49.5, 0 clicks. Early, but the pipeline is honest now.

**Takeaway**
An AI-written "it works" check only checks what you told it to. Verify the probe targets the thing you actually depend on.

Anyone else had an AI-generated health check pass green while the real dependency was down?
