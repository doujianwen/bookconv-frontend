**标题**：I automated my daily GSC pull with an AI-written script — and learned Google quietly rewrites yesterday's numbers

**正文**：
Sharing a data-reading lesson, not a tool review. The bug wasn't in my code; it was in how I trusted AI's automation.

**Site**: a small Next.js converter site, launched late July, ~3 weeks live, mostly AI-written.

**What AI did**: Wrote a Python script using google-api-python-client to pull my Search Console stats daily — ranked keywords, impressions, clicks, avg position. Charts the growth curve. Hands-off, fast.

**Where AI failed**: I compared two pulls 24h apart. The same day's keyword count jumped from 229 to 250. Google had released low-traffic terms from a hidden "(other)" privacy bucket it holds back for days. My "stall" was just the threshold catching up.

Second trap: one morning showed 0 searches. I almost panicked. Then remembered GSC lags 2-3 days. The day wasn't dead; the data was late.

**What I fixed (no code change)**:
1. Count keywords from query dimension only — drop (other)
2. Count impressions/clicks from date dimension (true total), never by summing keywords (that under-reports ~2x)
3. Read the 7-day trend, not any single snapshot
4. Note the pull timestamp on every report

**Honest numbers as of Aug 16**: 250 keywords, 1,266 impressions, 0 clicks, avg position 48.7. Early, but the curve is climbing.

I turned these lessons into 10 course files for my upcoming AI build-course. The skill isn't prompting AI to pull data — it's knowing when to trust the automation and when to read between the lines.

## r/webdev
**标题**：I let AI write my GSC API script — and spent 2 hours debugging a proxy bug that wasn't in my code

**正文**：
Small war story about trusting AI-generated code without verifying assumptions.

**What I'm building**: A Next.js ebook converter on Vercel, Calibre engine, 15 formats, 26 pairs. Mostly AI-assisted. I added a daily GSC pull to track ranking growth.

**What AI did**: Wrote a Python script using google-api-python-client to fetch search data daily via OAuth. It looked correct. I ran it. It hung on ETIMEDOUT.

**Where AI failed**: I assumed the script would pick up my system proxy automatically. On Windows, HTTP clients don't read environment proxy vars — they need explicit proxy configs. The script tried a直连 to oauth2.googleapis.com and timed out.

Second layer: even after I set HTTPS_PROXY in the environment, httplib2's ProxyInfo class (used internally by google-api-python-client) broke silently. ProxyInfo("HTTP", ...) doesn't exist in version 0.32.0. The script appeared to run but went直连 anyway.

**What I fixed**:
1. Switched to pure `requests` with explicit proxies dict
2. Set os.environ HTTPS_PROXY before every call
3. Added a TCP connectivity test (node net command) before running the script
4. Documented the proxy gotcha for future daily pulls

The script now works. But I lost 2 hours to bugs that weren't in my logic — they were in AI's assumptions about my environment.

**Takeaway**: AI writes correct code for ideal conditions. Your job is to verify those conditions exist. Always test connectivity before running API scripts.

How do you handle proxy/env assumptions when AI generates network-dependent code?
