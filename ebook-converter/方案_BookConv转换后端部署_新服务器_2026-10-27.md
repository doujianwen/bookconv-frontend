## 0. 一句话结论

**放 Calibre 转换后端（经既有 `CONVERSION_BACKEND_URL` 委派），前端继续留 Vercel。** 这把"路线 B"从被卡住的 Oracle（需国际信用卡）落地到自有机——且 x86 无 ARM 风险。但**不是配置一下就有**：代码侧 failover 缺失（P0），且部署目标形态需先定（worker 不能直接当后端）。

## 2. 架构决策一：同驻 vs 隔离（需你拍板）

### 方案甲：同驻（后端放 HK 2C4G，与 GEO 同机，内存上限隔离）
- **优点**：$0 边际成本；一机管理。
- **风险**：4GB 与 GEO 官网 + 增长后台 + 渠道控制台 +（可能）GEO DB 抢内存；Calibre 转 EPUB→PDF/大书瞬时 0.5–1GB。
- **缓解**：转换容器硬内存上限（docker `--memory` 或 systemd slice ≤1.5GB）+ 并发=1 + `CONVERSION_DIR` 挂 tmpfs 限大小 + 临时文件自动清理；为 GEO 留 ≥2GB。

### 方案乙：隔离（专用廉价盒，如硅谷 1核2GB，只跑转换后端）
- **优点**：RAM 不争（#1 风险消除）；硅谷对 BookConv 欧美用户延迟更低（转换是 server-to-server）；天然可作 failover/溢出目标。
- **风险**：多一台 + 小钱；1核2GB 转重 PDF 有 OOM 风险 → 靠并发=1 + 内存上限 + failover 到 CC 兜底。
- **你之前问的"荧光云 1核2GB 硅谷能行吗"**：能，但**必须专用、并发=1、且不与 GEO 同驻**；位置反而优于 HK。

**推荐**：流量尚小 → 甲起步，验收 RAM 吃紧即切乙；若追求低运维/低险，直接乙（隔离路线把"转换拖垮 GEO"的物理风险归零）。

## 3. 架构决策二：后端形态（代码层，须暴露 HTTP `/api/convert-internal` + 密钥）

| 选项 | 形态 | RAM | 新码量 | 适合 |
|---|---|---|---|---|
| **A 全 app 容器** | 部署 `docker-compose.yml`（Next+Redis） | ≈1.5–2GB | 0 | 兜底；但 4GB 同驻吃紧 |
| **B slim 独立 HTTP（推荐）** | 轻量服务包 `worker/src/converters/calibre.ts` + 密钥校验 + `/health` | ≈100–200MB | 少量 | 4GB 同驻首选，省 RAM |

> **关键纠正**：仓库有 BullMQ worker 代码 ≠ 同步 `/api/convert` 已走队列限流。`/api/convert` 是同步转发到 `/api/convert-internal`（`convertAndStream` 直接跑，无队列）。故并发控制须在后端**新增**（见 WP1）。

## 4. 实施工作包（可验收，按序）

- **WP1 后端 slim 服务（新）**：express/fastify 包 `calibre.ts`；实现 `POST /api/convert-internal`（密钥校验复用 `convert-internal` 逻辑）、`GET /health`；**进程内并发信号量**（2C4G→2，1C2GB→1）；`CONVERSION_DIR` tmpfs + 清理；超时 120s；DRM 友好错误。
- **WP2 镜像与部署**：`Dockerfile`（alpine + `calibre imagemagick ghostscript`；**裁剪 `libreoffice`/`djvulibre`** 除非要 doc/djvu）；`docker run --memory` 上限；v1 不用 BullMQ 则省略 Redis。
- **WP3 安全暴露（P0）**：Cloudflare Tunnel 或防火墙仅放 Vercel 出口 IP + TLS + 密钥；**绝不公网裸 3001**。
- **WP4 failover（P0，改 Vercel 侧 `route.ts`）**：缓冲上传体（或改 `upload_key` 模式）；后端 5xx/超时/网络错 → 回退 `convertAndStream`（Vercel 本地 → CloudConvert）；加**熔断**（连续失败 N 次 → 冷却期直走 CC，避免每次 30–60s 超时）。
- **WP5 格式白名单**：Calibre 能转的走后端（epub→mobi/azw3/pdf/txt 等），不能转的（doc/djvu/图片等）保持 CloudConvert。
- **WP6 接线与配置**：Vercel 设 `CONVERSION_BACKEND_URL` + `CONVERSION_INTERNAL_SECRET`（与后端一致）；**先 Preview 后 Production**。
- **WP7 监控与告警**：复用飞书 `backend-unavailable` 告警；加后端 `/health` 探活 + 转换耗时/峰值内存日志。

## 7. 回滚

- Vercel **取消 `CONVERSION_BACKEND_URL`**（或置空 `INTERNAL_SECRET`）→ 立即回退纯 CloudConvert/本地路径（即现状）。一键、可逆。
- ⚠️ **WP4 failover 实现前**，停后端会导致 503；故回滚前须先实现 failover，或暂保持现状不接线。

---

## 8. 残余风险（诚实披露）

- 4GB 同驻 RAM 争用为最大 Unknown；验收不过则切方案乙（隔离）。
- 1核2GB 专用盒重 PDF OOM → failover 到 CC 兜底（仍可能 402 优雅降级）。
- Calibre 升级致缓存陈旧已由 `CACHE_SCHEMA_VERSION` 防，但后端镜像版本须随 bump。
- 新服务器**未做生产压测**；采购 ≠ 生产就绪（Notion 原话）。
- BookConv 是英文全球站，后端为 server-to-server，HK/硅谷延迟可接受；若将来迁前端则需重新评估全球延迟。
