## 4. 门禁与验收

### 🔴 先分清：真门禁 vs 假门禁

| 脚本 | 实际扫描范围 | 覆盖 .md/配置？ |
|---|---|---|

| `find-duplicate-headings.mjs` | 同上两目录 `.ts` | ❌ **否** |

> **改文档或配置类任务，禁止引用这两个脚本作为验收证据**（覆盖率 0）。
> 这正是本项目已知的**头号失败模式**：脚本静默假成功。

### 各类任务的正确验收

| 任务类型 | 验收方式 |
|---|---|
| 内容改动（A / B / D3） | `audit-content-integrity` + `find-duplicate-headings` + `npm run build` + 线上断言 |
| 文档/配置改动（D1 / D2 / D6） | 逐条 grep 断言 + 数字与代码实测比对 + `npx jest` 全通过 |
| 代码删除（D5） | `npx jest` 全通过（**必须**，queue.ts 被 5+ 测试 require）+ `npm run build` |
| 线上生效 | URL Inspection / curl 断言，**不能只看"站点能打开"** |

### 通用纪律（沿用，不变）

- 每次提交 ≤3 页；间隔 ≥24h；改完必跑门禁；**不自动 push**（commit 后人工复核）
- 重定向走既有 `BLOG_REDIRECTS`（`src/middleware.ts`），不新造机制
- 正文禁尖括号标签；批量脚本只做替换/定点更新，**禁止追加整块**
- 引用量 ≠ 流量：Bing AI 引用 9,012 次对应 GA4 仅 2 会话，对外材料禁止把引用当流量承诺
