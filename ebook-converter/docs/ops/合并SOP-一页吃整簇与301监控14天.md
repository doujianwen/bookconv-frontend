# 合并 SOP —— 一页吃整簇 + 301 后监控 14 天

> 沉淀自 R1（epub-vs-azw3-vs-mobi → ebook-formats-explained）、R2（mobi-vs-azw3 三页）、R4（epub-to-azw3 博客→指南）、R5（kindle-formats 支柱集权）四轮实战。
> 目的：把"同意图页面合并"从每次临时方案，固化为可复用的判定与执行纪律，**尤其补上过去缺失的"301 上线后如何验收、何时回滚"**。
> 适用范围：bookconv.com 内容页（blog/guide/convert）的意图内耗治理。

---

## 0. 铁律前置（违反即废本轮）

1. **严禁 `git rm` / `rm` 删源文件** → 一律 `git mv` 到 `src/data/_archived/`，避免沙箱 safe-delete 钩子连带删父目录（曾实测 blog/+content/+guides/ 被整树删）。
2. **死链目标必须 CONVERSION_MAP 核验** → `/convert/{src}-to-{tgt}`（带 to），非 CONVERSION_MAP 键 `{src}-{tgt}`；漏 to 或拼错键 → 死链 → 500/seo-critic CRITICAL。
3. **CTA URL 铁律**：内链写 `/convert/{src}-to-{tgt}`，不是 CONVERSION_MAP 键。
4. **不重复 schema**：转换页已含 FAQPage+SoftwareApplication+HowTo，合并时**只并败者独有 FAQ**，不整体复制（重复 schema 有惩罚风险）。
5. **门禁不过不推送**：tsc 0 → seo-critic 0 → code-critic 0 → 才 git-sync-check。

---

## 1. 一页吃整簇原则（为什么合并）

- 同意图的关键词变体（对比 X vs Y / 选择 X or Y / 疑问 does X work / 场景 for kindle / 多语言）**合并到最强词页面**，禁止每个变体各建一页——内容同质化 + 权重分散（cannibalization）会让谁都排不上去。
- **意图分层是硬边界**：交易意图 `convert X to Y`（落在 `/convert/*`）与信息意图 `X vs Y`（落在 `/blog/*` 或 `/guide/*`）**必须分开**，不能合并到一页。混淆意图 = 谁都不讨好。
- 新站权重集中优先：位置 60–80 是域名权威问题，页面优化天花板约 30–40，上首页靠权重集中 + 外链。

---

## 2. 两种合并模式判定

| 模式 | 适用场景 | 动作 | 案例 |
|---|---|---|---|
| **A. 301 收敛** | 两页抢**同一意图 + 同一类型**（如两个博客都讲 `X vs Y` 工具步骤） | 立权威页，败者 301 → 胜者，独有资产并入，源文件归档 | R1、R2、R4 |
| **B. pillar 集权** | 多页**意图相关但互补**（指南 + 卫星博客 + 钱页），无直接内耗 | 立支柱页，卫星页内链指向支柱，hub-and-spoke，**不删页不 301** | R5（kindle-formats 支柱） |

**判定口诀**：搜这个词的用户点进来想要什么？答案相同就合并（模式 A）；答案互补（一个讲概念、一个讲工具、一个讲场景）就集权（模式 B）。

---

## 3. 模式 A：301 收敛 八步 Checklist

> 前置：先 `grep` 全仓 `src/` 确认败者**无入链**（除 index.ts import 与自身 slug 外）→ 无入链死链风险才动手。

- [ ] **Step 1 — 胜者判定**：按以下优先序定胜者
  1. 内容更完整（段数/FAQ 更多、含独有资产）
  2. 已 de-facto 互链败者（hub 信号）
  3. 注册最早（accumulation 信号多）
  4. 带西语版（i18n 完整，301 保留覆盖）
- [ ] **Step 2 — 合并独有资产**：只并**败者独有、胜者缺**的内容段；FAQ 不重复并（胜者已覆盖的意图跳过）。
- [ ] **Step 3 — 注册表移除败者**：`src/data/{blog,guides,content}/index.ts` 删 import + 从数组移除。
- [ ] **Step 4 — llms.txt 同步**：删败者行（seo-critic 查博客↔llms.txt 同步，漏删 CRITICAL）。
- [ ] **Step 5 — middleware 加 301**：`src/middleware.ts` 的 `BLOG_REDIRECTS` / `GUIDE_REDIRECTS` 加 `{败者}: {胜者}`（locale 保留逻辑自动带上 `/es`）。
- [ ] **Step 6 — 归档源文件（非删除）**：
  ```bash
  cd E:/一人公司/电子书格式转换站
  git mv ebook-converter/src/data/{blog,guides,content}/{败者}.ts ebook-converter/src/data/_archived/{败者}.ts
  ```
- [ ] **Step 7 — 门禁**：`tsc --noEmit` 0 · `seo-critic.mjs` 0 · `code-critic.mjs` 0。
- [ ] **Step 8 — 构建 + 部署 + 核验**：`next build --webpack` → 推送 → 等 75–90s → 剥离 `<script>` 断言：
  - 败者 URL → **301** 且 `location` 指向胜者（含 `/es` 变体）
  - 胜者 200 + 正文含并入段 + 新增 FAQ
  - 胜者既有内链存活
  - `node scripts/git-sync-check.mjs` PASS（remote main == local HEAD，**绝不信任 behind=0**）

## 4. 模式 B：pillar 集权（不删页）

- 立 `/guide/*` 或 `/blog/*` 为支柱页，新增「Related guides」「Start converting now」段，内链指向卫星页与钱页。
- 卫星页 intro/修复段加指向支柱的内链（EN + ES）。
- **风险最小**：无 noindex/301，不影响索引，仅增内链。
- 门禁同 Step 7–8（但无 301 核验项）。

## 5. 301 后监控 14 天纪律（核心，过往缺失）

> **这是 SOP 最关键的新增项**：301 上线不等于成功，必须按窗口验收，承接不足即回滚。R6（epub-to-azw3 博客→指南，2026-08-24 部署）是当前首个按本纪律监控的实战案例。

### 5.1 数据释放节奏
- **GSC 延迟 = 2 天**（实测，非 3 天）：END=t → 末有效日=t-2。
- 判持平前先验末有效日是否前进；**缺失日绝不插值**。

### 5.2 监控窗口
- 以 301 部署日 D0 起算，监控 **D+2 至 D+14**（覆盖 GSC 延迟 + 权重重算）。
- 对比基准：败者 301 前 14 天的「目标查询」展示/位置 vs 301 后 14 天胜者同查询。

### 5.3 验收判据（承接率）
- **保留 301 的条件**：胜者承接 **≥80%** 败者原有展示，且胜者目标查询平均位置**不降反升**（或持平于可接受区间）。
- **回滚触发（任一）**：
  1. 胜者目标查询展示 < 败者原有 80%（流量流失）
  2. 胜者位置显著下滑（如从 40 跌到 70+）且 14 天窗口内无回升迹象
  3. GSC 覆盖率报告持续报胜者异常（非临时波动）

### 5.4 回滚预案
```bash
# 1. 撤 301
#    编辑 src/middleware.ts 删 REDIRECTS 该项
# 2. 恢复源文件
git mv ebook-converter/src/data/_archived/{败者}.ts ebook-converter/src/data/{blog,guides,content}/{败者}.ts
# 3. 恢复 index.ts import + 数组项、llms.txt 败者行
# 4. 撤胜者合并内容（Step 2 改动）
git add -A && git commit && git push && node scripts/git-sync-check.mjs
```

### 5.5 验收记录模板（每个 301 必填）
```
301 案例：{败者} → {胜者}
部署日：YYYY-MM-DD (commit {hash})
GSC 复测日：YYYY-MM-DD（末有效日 YYYY-MM-DD，延迟已计入）
败者原展示（前14天）：{n}
胜者承接展示（后14天）：{n} → 承接率 {x}%
胜者位置变化：{before} → {after}
结论：✅ 保留 / 🔄 回滚 / ⏳ 续观（理由）
```

## 6. 关联纪律（跨文档一致）

- **CTA / 死链**：所有新增内链先过 CONVERSION_MAP 核验（见铁律 2）。
- **语言错配**：西语页 `title` 必须是**真西语**，不可与英语页同标题（混淆 hreflang 翻译对，已被 R6-2 实证导致英语查询被 /es 截流）。
- **GSC 复测**：accrual ≥10 展示再判趋势；单条改动不急于下结论（域权威积累 1–3 月）。
- **溯源**：每轮合并在 `docs/ops/SEO改动溯源.md` 追加条目；本轮合并方案存 `docs/ops/R{n}合并方案-*.md`。

---

## 7. 反模式（踩过的坑，勿重犯）

- ❌ 用 `git rm` 删败者 → 父目录整树消失。
- ❌ 合并时整体复制败者 FAQ → 重复 FAQPage schema 惩罚。
- ❌ 把交易意图页与信息意图页强行合并 → 意图混淆，排名双输。
- ❌ 301 上线即宣布成功、不复测 → 流量流失 14 天后才发现。
- ❌ 内链拼 `/convert/epub-to-word`（应为 `epub-to-docx`）→ 死链。
- ❌ 西语页 title 抄英语页 → 语言错配内耗。
