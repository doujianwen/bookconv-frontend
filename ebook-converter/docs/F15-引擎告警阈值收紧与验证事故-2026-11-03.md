# F15 引擎告警阈值收紧 · 决策记录 + 验证事故 + 红队审计（2026-11-03）

> 来源：待办_2026-10-31 §七 F15（11-01 引擎真实失败 4 次未触发日报引擎告警阈值）。
> 配套脚本：`scripts/ga-inspection.mjs`。

## 一、问题定位（实测）

`ga-inspection.mjs` 引擎主告警判据（line 185）：
`abnormal = engineFailed > 完成数 || 成功率 < 50%`。

- 11-01：引擎失败 4 次、完成 153 次 → `4 > 153` 假、`153/227=67% < 50%` 假 → **主告警不触发**。
- 既有"检测盲区"软警告（line 352 旧）：`systemSide.total >= 2 && !abnormal` → 输出 `🔍 检测盲区` 建议人工核对，但**仅 ⚠️ 软提示，非 🚨 硬告警**。
- 真实 11-02 数据：系统侧(引擎类)= UNKNOWN:3 + INTERNAL_ERROR:2 = **5 次**，同样只落软警告。

结论：低流量站上"引擎失败数 < 完成数且成功率 > 50%"天然成立，主阈值对**反复出现的引擎类失败**系统性漏判。

## 二、决策（收紧）

将"系统侧(引擎类)失败 ≥3 次"升级为 **🚨 硬告警**（不再只是软警告），主阈值保持不变（避免对低流量站误报）。
- 引擎类 = `classifyFailureSides` 的 systemSide（已排除直传 INFRA / 客户端拦截 / 额度，落 userSide）。
- 硬告警阈值 **≥3**：低流量站单日 ≥3 次引擎类失败（含 INTERNAL_ERROR / UNKNOWN / 超时 / CORRUPT_INPUT）已属异常，值得立即核查；<3 仍走软警告，防正常波动误报。
- 硬告警纳入汇总 `hasFail`，结论落到"巡检发现异常 ⚠️"。

## 三、反向验证（实测，含事故，见第四节）

- 场景 A（11-01 同构：引擎类失败 4 次）：✅ **触发 🚨 引擎硬告警**，汇总"巡检发现异常"。
- 场景 B（正常日：系统侧 0）：✅ **不触发**，汇总"全绿 ✅"。
- 真实 11-02 数据：✅ 触发硬告警（系统侧 5 次，合理非误报）。
- 注入回归：11-01 真实数据（有 DIRECT_UPLOAD 系列落 userSide）未误判为系统侧。

## 四、⚠️ 验证事故（数据污染 + 真实 ga4-live.json 丢失，已恢复）

**事故**：为做第三节反向验证，先 `cp` 备份 `_wb_tmp/ga4-live.json` 到 `/tmp`，注入场景 A/B 后还原。
但首轮验证用 `node ... | grep` 且 `&&` 串联——grep 无匹配 exit 1 使链式中断，**未执行还原**；后续又在 `_wb_tmp` 已被场景 A 覆盖（且脚本崩溃未还原）的状态下，把污染的 254 字节场景 A 重新 `cp` 进 `/tmp` 备份，**污染了唯一备份**。导致今早真实的 197KB / 2026-11-02 `ga4-live.json` 被覆盖、磁盘不可恢复。

**恢复**：`scripts/fetch-ga4-daily.mjs 2026-11-02 --write` 经代理重拉 GA4 Data API，成功写回真实 2026-11-02 数据（events 21/14/8，failedByErrorCode 与丢失前一致）。`ga-inspection` 跑真实数据验证硬告警正确触发。

**根因（红队）**：
1. 验证流程缺陷——`&&` 串联把"还原"挂在 grep 成功之后，grep 无匹配即断链，还原不执行。
2. 备份时机错误——在 `_wb_tmp` 已被污染后做备份，覆盖了干净备份。
3. 违反本项目的"先备份再改、验证后必还原、不可污染唯一备份"纪律。

**整改**：① 恢复真实数据（已完成）；② 本次后所有注入验证一律用**临时副本 + `;` 串联保证还原**，绝不在真实数据源上就地覆盖；③ 真实 `ga4-live.json` 当前已为正确 2026-11-02 数据，无需再动。

## 五、红队审计（F15 阈值收紧）

**断言**
1. 主阈值对低流量站引擎类失败系统性漏判（实测 11-01/11-02）。
2. ≥3 次引擎类失败升级硬告警可修复盲区，且对正常日不误报。
3. 改动仅新增硬告警层级，不破坏主阈值/分流口径。
4. 验证过程不污染真实数据。

**攻击 / 反证**

- A4（验证污染真实数据）：**事故已发生并恢复**，见第四节；整改已落地。🔴（已补救）

**裁定**：通过（阈值收紧合理、反向验证成立、真实数据已恢复）。
