## 案例 1：Google Spam Update 断崖归因与修复

### 背景
- 上线时间：2026-07-26
- 高位期：8/9–8/21，日均印象 160.8
- 低位期：8/22–9/5，日均印象 16.6（−89.7%）
- Google 官方确认 2026-08-18 Spam Update

### 归因过程（四步排查法）

| 轮次 | 假设 | 验证方法 | 结果 |
|---|---|---|---|
| 第一轮 | 内容质量问题 | 审计 112 个 /es 页 | 发现 99 页是英文正文 + lang="es" 矛盾 |
| 第二轮 | 抓取预算被占 | 检查 223 URL 覆盖 | 44% URL 是重复的 /es 伪西语页 |
| 第三轮 | 核心页未重抓 | 检查 lastCrawl 日期 | `/convert/epub-to-mobi` 37 天未重抓 |
| 第四轮 | 结构层问题 | 卡方检验页面类型与零引用关系 | 暗页率 convert 90% / blog 72% / guide 20% |

### 核心结论
- **病灶在结构层不在内容层**：前 3 轮审计全漏
- 223 URL（44% 重复）→ 质量信号稀释 + 抓取预算被占 → 核心页 37 天不重抓 → 旧快照重排
- 首页豁免 86%（快照新）解释了为何改内容无用

### 可复用方法
1. 先穷举维度再验证（内容层 → 结构层 → 技术层）
2. API 字段语义先反例证伪再当判据
3. 维度决定结论——同一数据不同维度得出不同结论

## 案例 2：双渠道背离证实非全站惩罚

### 数据对比（重叠期 8/27–9/5）

| 指标 | GSC (Google) | Bing 传统 | Bing AI |
|---|---:|---:|---:|
| 总印象 | 127 | 288 | — |
| 总点击 | 5 | 9 | — |
| CTR | 3.94% | 3.13% | — |
| 平均排名 | ~20-30 | 5.3 | — |
| 引用/页面 | 0 | 0 | 2,190 cites / 264 pages |

### 关键洞察
1. **Bing 印象是 GSC 的 2.27 倍**，但 **CTR 相近**
2. **Bing 优势在于排名更靠前**（avg pos 5.3 vs GSC 约 20-30）
3. **AI 引用 >> 传统点击**：2,190 cites vs 17 clicks
4. **Google 断崖 ≠ Bing 断崖**：Bing 未出现 GSC 式的 −88%
5. **双渠道背离证实非全站惩罚**：Google spam update 影响 > Bing

### 策略转向
从"修复 Google 断崖" → "放大 Bing AI 引用"

## 案例 4：苏格拉底式审计方法论

### 审计清单（7 项质疑）

| # | 质疑点 | 验证结果 |
|---|---|---|
| Q1 | GSC CTR=0.3% 是否准确？ | ❌ 错误（基线裁剪，实际 2.41%） |
| Q2 | Bing 平均排名 ~5.0 是否准确？ | ⚠️ 近似正确（实测 5.3） |
| Q3 | AI Overview "波动而非断崖" 是否准确？ | ⚠️ 需精确化（高位震荡） |
| Q4 | AI 引用/印象比 453% 是否有意义？ | ❌ 误导性（维度不同） |
| Q5 | HP IP 策略结论是否成立？ | ✅ 验证通过 |
| Q6 | 页面类型分布计算是否正确？ | ✅ 验证通过 |
| Q7 | Bing vs GSC 可比性？ | ⚠️ 需注明维度差异 |

### 审计原则
1. **所有声明必须可验证**——每个数字都要有数据来源
2. **跨渠道比较必须同周期同维度**——禁止维度错配
3. **比值指标需验证语义对等**—— impressions vs citations 不可比
4. **基线裁剪是常见误导手段**——检查是否用了全站累计值

## 案例 5：IP 内容扩展计划（防 Google 惩罚）

### 发布纪律
| 规则 | 执行标准 |
|---|---|
| 速率控制 | 每周最多 1-2 篇新博客 |
| 质量优先 | 每篇 ≥ 1500 词 + 实用表格 + FAQ |
| 内链闭环 | 新博客必须链接到 2+ 现有高引用博客 |
| 间隔发布 | 相邻 IP 博客间隔 ≥ 3 天 |
| 增量验证 | 每篇发布后观察 3-5 天 Bing AI 引用变化 |

### 阶段规划

| 阶段 | 时间 | IP | 预期 cites |
|---|---|---|---|
| Phase 1 | 9/8-9/11 | LotR, Narnia | 20-30, 10-15 |
| Phase 2 | 9/15-9/18 | Twilight, Hunger Games, Sherlock | 8-12, 5-10, 5-8 |
| Phase 3 | 9/22-9/30 | 横向主题（fantasy ebooks guide, device sync） | 10-15, 15-20 |

### 风险控制
1. 不批量创建——每次只生成 1 篇
2. 不重复内容——每篇聚焦不同查询角度
3. 优先公共领域 IP——规避版权风险
4. 监控指标——低于预期则调整策略

## 案例 6：GA4 引用垃圾识别

### 背景
- seobotai.com 出现 15 sessions，引发"外部流量高峰"误判

### 识别方法
| 特征 | 判断依据 |
|---|---|
| 首次互动来源 | 0 users（唯一可靠判据） |
| 代码库关联 | 无集成 |
| 网站内容关联 | 无提及 |
| 用户行为 | 无事件记录 |

### 结论
- **GA4 referral spam 判定**：仅会话来源有记录，首次互动无 = 爬虫/机器人
- **建议操作**：在 GA4 中设置过滤规则排除 `app.seobotai.com`

## 案例 7：Bing WMT 提交策略

### 提交通道区分
| 工具 | 性质 | 效果 |
|---|---|---|
| IndexNow | 被动等待爬取 | 缓慢 |
| SubmitUrlBatch | 强制抓取 | 快速 |

### 提交前体检清单
1. HTTP 200（无 301/404）
2. 在 sitemap 中
3. 无 noindex 标签
4. canonical 自指

### 限流应对
- Bing WMT 持续 `ThrottleHost` 限流
- 触发后不短期自愈
- 批量脚本必须增量落盘 + `--resume`
- `--delay` 不低于 3000ms
