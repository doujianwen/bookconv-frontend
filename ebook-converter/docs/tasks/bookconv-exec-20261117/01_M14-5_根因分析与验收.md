## 2. 根因判定（每类独立归因，不做单因归并）

- **A（已修复）直传 PUT 失败**：10-29→11-05 的 45 次失败发生在 CSP 未放行 R2 host 时代（`327f640` 2026-11-06 10:45 修复）；GA4 中出现 `PUT:NETWORK:on=1:<1s` / `>15s` 判别标签本身是 R-2 代码（`8c597c9` 11-06）已上线的**行为证据**。修复后残余 2 次（11-10）符合网络类瞬时失败+3 次退避重试的预期分布。
- **B（已修复）FILE_TOO_LARGE 客户端拦截**：`upload-capability` 探测重构（cap 从常量 4MB 改为服务端权威能力）后，10-31 起再无客户端误拦；presign 413（>100MB）30 天内 0 次。
- **C（残余，非上传链路）convert 阶段 `Failed to fetch`**：F20 代码上线后，直传失败必然携带 `This file (X)…` 类型化消息，而裸 `Failed to fetch` 在 11-06 后仍持续 ⇒ 这 14 次来自 `/api/convert` POST 或 blob 下载的网络中断，不是直传 PUT。**修复上限受用户网络物理约束**；自动重试 convert 有重复消耗转换额度风险，本轮不实施，登记 P2。
- **D（UNKNOWN）**：直传失败用户的地理/网络成因无 GA4 地理维度佐证，不推测。
