## 1. 为什么不新建系统

- 任务 ID 一律复用 `data/seo-geo-board.json`（校验器强制：`taskId` 不在台账即 FAIL `E03`），不另建任务体系。
- 注册表只存「实验元数据」，不存任务、不存调度、不存数据；数据仍来自既有 GSC/GA4/SERP 快照。
- 校验器只读，不改台账、不触发采集、不碰生产。

## 2. 字段契约（缺一即 FAIL）

| 字段 | 必填内容 | 关键约束 |
|---|---|---|
| `baseline` | metric / value / unit / window{start,end,days} / source / capturedAt / caveat | `days` 必须等于日期差（窗口造假即 `E05`） |
| `hypothesis` | 可证伪的陈述 | 空即 `E04` |
| `change` | type / authorized / description / productionTouched | `PRODUCTION`+`authorized` 但无 `approvalRef` → `E07` |
| `control` | type / description / randomized / limitation | `randomized` 必须显式声明 |
| `observationWindow` | start / end / minDays | 不足 7 天 → `E09` |
| `execution` | status / evidence / note | `EXECUTED` 必须附证据；`BLOCKED` 必须写解阻条件 |
| `effect` | status / attribution / metric / value / delta / measuredAt / windowDays | 见 §4 |

## 3. 两个真实实验

### GE-001｜Bing 每日定向 URL 提交 → 索引与曝光（execution=RUNNING，effect=PENDING）

- 任务挂接：`M8-6`（台账既有条目）。
- 基线：GSC 近 7 天（2026-11-08~11-14）**45 展示 / 0 点击**，来源 `数据分析/GSC_API_date_2026-11-14_d30.json`。
- 假设：同内容下 Bing 侧（每日提交 sitemap URL）曝光不低于 Google 侧；若显著更低，说明提交链路未生效或索引受限。
- 对照：`CHANNEL_HOLD_OUT`——Google 侧零提交。`randomized=false` ⇒ 结论最高只能到 CORRELATIONAL。
- 执行证据：`automation_runs` 中 `7ecd345e` 近 14 天 14 次运行（sqlite 只读查询）。
- 观察窗：2026-11-17~12-01（15 天）。
- 失败条件（kill criteria）：14 天后 Bing 侧曝光为 0 且提交回执正常 → 判定提交对曝光无效。

### GE-002｜可引用数据页 → 外部引用（execution=BLOCKED，effect=NOT_STARTED）

- 任务挂接：`M4-2`（doing）。
- 基线：外部引用 0 域名，窗口 2026-10-15~11-14。**caveat 已写明：0 是「未观测到」，不是「确证为 0」**，因为引用监测通道本身不完整（G08 BLOCKED）。
- 改动类型 `PRODUCTION`、`authorized=false` ⇒ 校验器要求 `execution` 必须是 `BLOCKED`/`NOT_STARTED`，本条目正是如此。
- 解阻条件：CEO 授权发布 + 引用监测通道可用。

## 4. 「执行成功 ≠ 经营效果」的工程约束

1. `execution` 与 `effect` 是两组独立枚举，不能互相推导。
2. `execution=EXECUTED` 且 `effect=NOT_STARTED` → **FAIL `E14`**：执行完了却没建观测口径，不允许。
3. `effect=MEASURED` 必须有 metric/value/delta/measuredAt/windowDays；`windowDays` 必须等于基线窗口 → 否则 `E12`（禁跨口径相减，复用 GEO 可比性纪律）。
4. `measuredAt` 早于观察窗结束 → `E12`（防提前宣布结果）。
5. `attribution=CAUSAL` 仅在 `control.randomized=true` 时允许 → 否则 `E13`（相关≠因果）。
