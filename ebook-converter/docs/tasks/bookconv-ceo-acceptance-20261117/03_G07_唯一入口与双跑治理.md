## 3. 唯一执行入口（新建的是「入口」，不是「调度器」）

`scripts/growth-daily-entry.mjs` 不含任何定时逻辑，只负责「今天这一次」：

1. 用幂等键 `daily-ops@YYYY-MM-DD` 抢锁；抢不到 → **exit 3，零步骤执行**；
2. 按固定顺序调既有门禁（不复制逻辑）：数据新鲜度 → 机会资格 → 台账唯一 → 实验注册表 → GEO 可比性 → 内容完整性；
3. 落 `_wb_tmp/growth-daily-run-<date>.json`（每步真实退出码 + 耗时 + 输出尾行）；
4. 释放锁并写终态 `SUCCESS/FAILED/UNKNOWN`。

职责边界：辅助自动化只做「采集/提交/摘要」，**不得自行判定经营结论**；一切结论以入口的运行记录为准。

## 4. 重复执行保护测试（真实执行）

| # | 场景 | 预期 | 实测 |
|---|---|---|---|
| 1 | 自检 11 用例（含锁 6 态） | PASS | `SELFTEST PASS` exit 0 |
| 2 | 首次 acquire | 0 | `ACQUIRE attempt=1` exit 0 |
| 3 | 立即二次 acquire | 3 | `SKIP(SKIP_DUPLICATE)` exit 3 |
| 4 | release success | 0 | `RELEASED → SUCCESS` exit 0 |
| 5 | 完成后再 acquire | 3 | `SKIP(SKIP_DONE)` exit 3 |
| 6 | 未持锁 release | 1 | `FAIL: 未持有锁，拒绝写入结果` exit 1 |
| 7 | 超时锁（心跳 120min > TTL 90min） | 接管 | `TIMEOUT_TAKEOVER` → `ACQUIRE attempt=2` exit 0 |
| 8 | 上次 FAILED 后 acquire | 允许重试 | `RETRY attempt=3` exit 0 |
| 9 | 每日入口连跑两次 | 第二次 3 | `SKIP ... 不执行任何步骤` exit 3 |

超时与 UNKNOWN 的处理不是「超时就当成功」：旧的 RUNNING 会写入 `TIMEOUT_TAKEOVER` 事件并累计 `attempts`，终态由 release 显式写 `SUCCESS/FAILED/UNKNOWN`；未 release 的锁只会随时间过期被接管，不会被当成 PASS。
