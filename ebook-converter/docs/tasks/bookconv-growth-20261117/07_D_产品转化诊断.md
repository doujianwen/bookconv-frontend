## 4. 失败归因（30 天，这是本轮最有价值的发现）

| 维度 | 数字 |
|---|---|
| 总失败事件 | 114 |
| 其中 **文件 >4MB** | **79（69.3%）** |
| 引擎侧失败（`isEngineFailureCode`） | 48（42.1%） |
| 前置失败（大文件/直传/配额/空文件） | 66（57.9%） |
| 引擎侧完成率 `complete/(complete+engineFailed)` | **85.6%** |
| 桌面端整体完成率（含前置失败） | **34.1%**（引擎侧 83.3%） |

**epub→azw3 单格式对：30 天 48 次失败（占全部失败 42%），其中 33 次（69%）文件 >4MB，中位 5.30MB，最大 64.97MB。**

错误码分布（30 天）：`UNKNOWN` 30、`FILE_TOO_LARGE` 30、`DIRECT_UPLOAD_PUT_FAILED` 22（桌面 20 / 移动 2）、`CORRUPT_INPUT` 9、`DIRECT_UPLOAD_FAILED` 9、`INTERNAL_ERROR` 5、`CONVERSION_QUOTA_EXCEEDED` 5、`CONVERSION_UNAVAILABLE` 3、`UPLOAD_NOT_FOUND` 1。

**因果链（有证据支持，非推测）**：
1. 文件 >4MB 时走 R2 直传（上限 100MB）；
2. 直传在 PUT 阶段失败（`DIRECT_UPLOAD_PUT_FAILED` 22 + 诊断前缀里 `PUT:NETWORK`、`online=1`、`cspBlocked=false`）；
3. 失败后回退或直接被 4MB multipart 上限拦（`FILE_TOO_LARGE` 30）；
4. 用户在客户端就被拦的还有 39 次（`file_rejected_client`）。

⇒ **转换引擎不是瓶颈（85.6%），上传链路才是。** 这与项目 MEMORY §2「R2 直传链路是真 P0」完全一致，本轮用 30 天事件数据再次独立确认。
