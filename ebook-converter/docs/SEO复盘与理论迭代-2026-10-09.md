## 〇、执行摘要（6 条核心论断）

1. **本阶段（74 天）的主线是一次"算法性打击 + 渠道错位 + 度量失能"的复合事故**，而非单纯 SEO 优化。Google 因 2026-08-18 Spam Update 断崖 −89.8%（事件窗口 2,123→217 曝光），同期 Bing AI 引用逆势增长 → 形成"双渠道不对称"。
2. **最大的认知升级不是某个战术，而是"可证伪的度量方法论"的成熟**：贯穿全程的头号失败模式是「测量假象→误判→纠正」与「静默假成功」。本阶段把这两类失败从"踩坑"沉淀为一套**纪律+门禁体系**（反向验证、checked>0、UNKNOWN 降级、命中数断言），这是比任何单页优化都值钱的理论资产。
3. **三个被一手实测推翻的直觉**（均来自 URL Inspection / Jaccard / GSC 全量核对）：
   - "零曝光 = 未收录" ❌ → 实测 18 个零曝光页中仅 3 个真未收录（16.7%），14 个是"已发现未抓取"；
   - "同 query 多 URL = 内耗" ❌ → 12 组重叠页 TRUE 内耗 = 0（8-gram Jaccard 最高 0.026，阈值 0.4）；
   - "垃圾页/空白页" ❌ → "91 页 description 为空" 是判据只覆盖一种写法导致的**假失败**，真相是 81/121 页超长（平均 306 字符）。
4. **GEO 出现一个手册尚未收录的关键悖论——"一簇一代表"**：Bing AI 每个转换话题簇只引用 1–2 个代表页，簇内其余页**恒 0 引用**且与页面质量/FAQ/结构无关（mobi-to-epub 结构全面优于 epub-to-pdf，仍 0 引用）。"让零引用页被 AI 引用"对簇内页是**结构性无效 KPI**。
5. **度量口径在本阶段被两次打脸**：Bing AI VI 从 +147.8% 被新导出重算推翻为 −10.0%（单窗口陷阱）；Google VI −27.5% 因 recent7 仅 37 曝光只能说"方向向下"不能说幅度（小样本陷阱）。结论：单窗口 VI 极易被下一窗口推翻，必须滚动多窗口 + 标 near_threshold + "无信号≠无变化"。
6. **GA4 在新站/低流量期基本是"黑暗流量"**：google/organic 连续 3 次 = 0，bing/organic 全期仅 2 个会话（对应 7,067 次 Bing AI 引用）。新站阶段应以 GSC/Bing WMT 官方数据为权威，GA4 仅作辅助且须先治理（事件埋点 + 爬虫过滤）。

## 二、数据层面的核心发现与教训（一手数据 + 来源）

### 2.1 双渠道"背离 → 不对称"的真相
- **Google 断崖**：事件窗口 2,123→217 曝光（−89.8%，8/21→8/22）；加权 position 68→64 持平 + 活跃 page 14→3（−81%）→ 判**覆盖坍塌（A）非排名惩罚（B）**。
- **Bing 侧逆势**：Bing AI 累计引用 9/27 达 12,292、10-08 达 15,271（+9.8%）；Bing Web 69 天 2,284 曝光、10-05 VI +26.1%。
- **措辞纪律（G5）**：禁止"被 Google 处罚"；改用"Spam Update 后的表现变化 / Recovery hypothesis"。根因至今**未验证**（U_MANUAL_ACTION=UNKNOWN，U5 外链数据 UNKNOWN）。
- **教训**：渠道不对称是常态，但"背离"需满足三条件（符号相反+双方≥20%+末日差≤3天），否则只能说"不对称"（10-05：Google −27.5% / Bing Web +26.1% 反向成立；Bing AI −10.0% 不参与背离判定）。

### 2.2 覆盖坍塌的三态细分（URL Inspection 实测）—— 手册最大缺口
- 18 个零曝光页真实 `coverageState`（10-07，GSC URL Inspection API 实调 45 次）：

  | 状态 | 页数 | 含义 |
  |---|---|---|
  | Discovered - currently not indexed | **14** | 已发现未抓取（抓取侧问题） |
  | Submitted and indexed | **3** | **已收录** ⇒ 零曝光≠未收录 |
  | URL is unknown to Google | 1 | 尚未发现 |
  | Crawled - currently not indexed | 0 | — |

- **"0 impressions = 未收录"被实测推翻**（仅 16.7% 真未收录）。辅助证据：17/18 在 sitemap、仅 3/18 有 lastCrawlTime。
- **二级证伪（更关键）**：初判"14 页未抓取 = 权威/抓取预算问题"，红队判定 **UNPROVEN**——本数据集无法区分 crawl prioritization / internal linking / authority / freshness / scheduling。
- **教训**：诊断要过**两级证伪**：① 直觉假设是否被一手实测推翻；② 推翻后的因果解释是否也有证据。两步都标 UNPROVEN/REJECTED，禁止把"修复动作"当"根因已确认"。

### 2.3 GEO "一簇一代表" 引用集中悖论 —— 手册尚未收录
- 现象（MEMORY 0-C #26，10-08 b2）：Bing AI 每个转换话题簇（mobi↔epub、pdf↔epub…）只引 1–2 个代表页；簇内其余页**恒 0 引用**且与页面质量/FAQ/结构无关（mobi-to-epub 结构全面超 epub-to-pdf，仍 0 引用）。
- 26 个零引用 convert 页分两类：A 类簇内内耗 13 页（差异化目标=降重复率，**勿用被引衡量**）；B 类真无需求 10 页（azw3-to-pdf/chm-to-mobi/epub-to-jpg/png/rtf/word/zip/lit-to-epub/mobi-to-pdf/rtf-to-epub）。
- **教训**：GEO 差异化的 KPI 必须重定——对簇内页追求"被 AI 引用"是结构性无效目标；资源应投到**代表页双向承接 section** + B 类无需求页降级（301 合并 3 页 / noindex 4 页）。

### 2.4 内耗是假问题（Jaccard 判据）
- 12 组同名/跨目录 slug 重叠（非早前误判的 9 组），但 **TRUE 内耗 = 0**（8-gram Jaccard 最高 0.026，阈值 0.4）；62 个 query 分摊多 URL 但正文零重叠。判据自检同页自比 = 1.000 通过（`CANNIBALIZATION_REPORT.md` V2）。
- **教训**："同 query 多 URL" = 意图分化，≠ 内耗。内耗真伪判据 = 共享 query + 8-gram Jaccard>0.4，且判据须先测"同页自比=1.000"再采信。

### 2.5 GA4 黑暗流量 / 渠道归因不可信（新站/低流量期）
- GA4 `google/organic` 连续 3 次 = 0（8/23、8/25、9/1）；`bing/organic` 全期仅 2 个会话，对应 7,067 次 Bing AI 引用。
- 根因：seobotai 爬虫流量混淆真实用户 + 关键事件（file_upload/conversion_complete）未标定 → 漏斗不可测。
- **教训**：新站/低流量期 GA4 渠道归因≈噪声。权威数据 = GSC（Google）+ Bing WMT（Bing）；GA4 仅辅助且须先治理（事件埋点 + 爬虫过滤 + Bing 来源行人工核对）。

### 2.6 转化/技术可用性故障会"伪装成 SEO/内容失败"
- 转化链路故障链（10-04，叠加多因）：① 中文文件名→`Content-Disposition` 非 Latin1→`Headers()` TypeError→500→`conversion_failed`；② CloudConvert **402 额度耗尽**；③ **Vercel Hobby 60s 硬上限**（maxDuration=300 被静默忽略）→ >4.5MB 文件 413 进不了转换代码；④ epub→docx/doc/html 在 CC 任何引擎都不支持（空承诺）。
- `conversion_complete` 自 9/28 恒为 0 → **漏斗不可测**，间接让"SEO 改动是否起效"无法用转化验证。
- **教训**：技术可用性故障优先于 SEO 诊断。转化端/抓取端故障会伪装成内容失败，先排除技术可用性再谈 SEO。

### 2.7 度量纪律的二次迭代（VI 单窗口陷阱）
- 10-05：Bing AI VI 旧读 +147.8%（滚动窗口 vs 低基线尾部）被全量导出重算推翻为 **−10.0%**（恰在阈值边界 −9.99…，标 near_threshold）→ 实为高位盘整非崩塌。
- Google −27.5% 因 recent7 仅 37 曝光，只能说"方向向下"不能说幅度（小样本）。
- **教训**：单窗口 VI 极易被下一窗口推翻 → 滚动多窗口 + 7 日移动均值；near_threshold 显式标注；**"无信号≠无变化"**（−10.0% 是高位盘整）。

## 三、理论层迭代：对现有手册（v1.1 通用 / v1.2 实施）的具体修订建议

> 形式：手册现状 → 本期实证 → 建议新增/修订（定位 + 文案草稿）。优先级 P0=强烈建议本轮落地，P1=建议补充，P2=观察。

### T1 【P0】覆盖坍塌三态 + 两级证伪纪律
- **手册现状**：§1.2 把 A 型定义为"页面不被收录/展示"，未细分真实状态，也无"禁用印象数反推收录"红线。
- **本期实证**：2.2（URL Inspection 三态 + 二级 UNPROVEN）。
- **建议修订**：§1.2 新增 **§1.2.1 覆盖坍塌三态** + 红线：
  > 🔴 **零曝光页必须先用 GSC URL Inspection API 实测 coverageState，禁止用 impressions=0 反推"未收录"。** 三态：① Discovered-not-indexed（已发现未抓取）→ 抓取/权重侧；② Submitted-and-indexed（已收录却零曝光）→ 需求/排名侧，≠内容差；③ URL-unknown → 未被发现（sitemap/内链问题）。
  > 🔴 **两级证伪纪律**：任何诊断结论过两关——① 直觉假设是否被一手实测推翻（如"零曝光=未收录"被 16.7% 推翻）；② 推翻后的因果解释是否有证据（如"未抓取=权威问题"被标 UNPROVEN）。两步都标 UNPROVEN/REJECTED，禁止把"修复动作"当"根因已确认"。

### T2 【P0】GEO "一簇一代表" 引用集中悖论
- **手册现状**：§4.4/#6 仅说"引用向少数页面集中（Top5 占 63.9%）→ 对引用大户强化 FAQ"，未揭示"簇内页恒 0 引用"的结构性规律，也未警告 KPI 无效。
- **本期实证**：2.3。
- **建议修订**：§4.3 新增**原则 7：GEO 引用集中悖论（一簇一代表）**：
  > AI 引擎对同主题簇（如 mobi↔epub）只稳定引用 1–2 个代表页，簇内其余页**长期 0 引用且与页面质量/FAQ/结构无关**。含义：① 对簇内页追求"被 AI 引用"是结构性无效 KPI，差异化资源应投到**代表页双向承接 section**；② 真无需求簇（B 类）直接降级（301 合并 / noindex），勿用"被引数"衡量其价值。

### T3 【P1】内耗真伪判据（防假阳性诊断）
- **手册现状**：§2.3 意图→内容映射未警告"同名 slug 重叠 ≠ 内耗"，也无 Jaccard 判据。
- **本期实证**：2.4（12 组重叠 / TRUE 内耗=0 / Jaccard 0.026）。
- **建议修订**：§2.3 或 §1.2 增补**内耗真伪判据纪律**：
  > 🔴 "同 query 多 URL" = 意图分化，**≠ 内耗**。TRUE 内耗须同时满足：① 共享 query；② 8-gram Jaccard > 0.4。判据启用前必测"同页自比 = 1.000"验证有效性，否则判据本身静默失效。

### T4 【P1】算法恢复期 / 新站"发布节奏纪律"
- **手册现状**：§3.1 仅"spam 恢复期不批量 bump lastmod"；§2.6 发布阶段无节奏约束。
- **本期实证**：Batch 4 发布纪律（≤3 页/提交、≥24h 间隔、自动化每日执行不 push、禁回滚/禁调度器假数据），防止 spam 恢复期受罚重演（08-18 一次性批量触发惩罚）。
- **建议修订**：§2.6 增补**"算法恢复期发布节奏"**条款 + §3.1 强化：
  > 🔴 **算法恢复期（及新站冷启动期）发布纪律**：单批 ≤3 页 / 提交间隔 ≥24h / 自动化执行但不自动 push（人工复核）/ 禁回滚 / 禁编造调度器数据。批量改 lastmod 视为主动请求全站重抓，恢复期禁用。

### T5 【P0】VI 滚动多窗口 + "无信号≠无变化"
- **手册现状**：§6.2 有 VI 公式 + n>400 门槛 + 跨轮不可比，但未强制滚动多窗口，也无 near_threshold 与"无信号≠无变化"红线。
- **本期实证**：2.7（+147.8%→−10.0% 单窗口翻转；−10.0% 实为高位盘整）。
- **建议修订**：§6.2 增补：
  > 🔴 **单窗口 VI 极易被下一窗口推翻** → 必须滚动多窗口 + 7 日移动均值交叉看趋势，不以单窗口定叙事。
  > 🔴 **near_threshold 显式标注**：|VI| 落在阈值边界（如 −9.99…% 实测）必须保留边界标记，禁止四舍五入成"达标/不达标"。
  > 🔴 **"无信号 ≠ 无变化"**：VI 在 ±10% 内（尤其高位盘整）≠ 渠道崩塌，须看绝对量 + 移动均值。

### T6 【P1】GA4 黑暗流量：新站/低流量期以官方数据为权威
- **手册现状**：§4.7 有"引用≠流量"红线，但 §6.1 三层指标体系把 GA4 当结果指标来源，未警告低流量期 GA4 渠道归因不可信。
- **本期实证**：2.5（google/organic=0、bing/organic=2 会话）。
- **建议修订**：§6.1 或新增 §6.x **"新站/低流量期 GA4 黑暗流量"**：
  > 🔴 新站 / 低流量期 GA4 渠道归因≈噪声（爬虫混淆 + 事件未标定 → 漏斗不可测）。权威数据 = GSC（Google）+ Bing WMT（Bing）；GA4 仅辅助且须先治理（事件埋点 + 爬虫过滤）。**禁止用 GA4 渠道行证明/否认 SEO 效果**。

### T7 【P1】技术可用性优先于 SEO 诊断
- **手册现状**：§1.2 诊断纪律有"先技术后内容"，但未强调"转化端/抓取端可用性故障会伪装成内容失败"。
- **本期实证**：2.6（conversion_complete 恒 0 污染全站 ROI 度量）。
- **建议修订**：§1.2 诊断纪律增补第 5 条：
  > 🔴 **技术可用性故障优先于 SEO 诊断**：转化端（下载/上传/支付）或抓取端故障会伪装成"内容失败 / SEO 无效"。先确认转化漏斗与技术可用性健康，再谈内容/排名归因——否则度量本身已被污染。
