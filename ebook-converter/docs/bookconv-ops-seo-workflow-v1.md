## 五、横切执行纪律（约束所有环节）

### 5.1 git / 部署 ✅

- 双账号 SSH：旧账号走 `git@github-old:doujianwen/bookconv-frontend.git`（直连 HTTPS 会 502）
- **push ≠ deployed**：push 后 ~60-90s 三步验证（① parse ② 门禁 ③ 线上 strip `<script>` 再 grep）
- pre-commit 必 `git fetch` 防并行冲突；禁 force push；push 前查 `next-env.d.ts`/`tsconfig.json` 未被 build 重写
- 站内任何不存在路径返 200+兜底 HTML → 判死链禁只看状态码（查 `X-Matched-Path`）

### 5.2 门禁体系 ✅

publish-gate（Gate B）/ seo-critic / critic-layer.blog / llms.txt 一致性（Guides==博文数、Conversions==31）/ heading 唯一性 / `test:vi` / `audit:sync`（hermes-context 副本镜像同步，2026-10-11 新增：副本=只读执行上下文，漂移即 exit 1、文件缺失 exit 2，双向验证通过）—— 每个门禁挂载点必问「挂哪、怎么被调用、退出码真能传出吗」；CI 里不可判定项降级 UNKNOWN 不报 FAIL。

### 5.3 验证纪律 ✅（全文见 `MEMORY-附录-纪律详解.md`）

- 唯一真相=实测；「门禁存在」≠「任务完成」必实跑
- 头号敌人=静默假成功 → 命中数断言 + 真 dry-run + 独立通道复核
- 判据/门禁写完必反向验证（注入事故→exit 1，恢复→exit 0）
- 本地绿≠线上绿（按段扫+线上 curl 复核）

### 5.4 运维响应 ✅（SOP ⚠️ 未成文，见缺口 6.3）

- 事故基线：2026-10-01 全站转换失败波及 8 用户，T+1 才被 GA 日报发现
- 补救机制：GA4 `conversion_failed` 事件 + 飞书 Webhook（`FEISHU_WEBHOOK_URL`）实时告警；飞书发送失败有重试脚本
- 终端用户反馈：workbench feedback 表单 + admin 反馈看板闭环（⚠️ 真实使用信号目前为零）
