# New Site Playbook — 新项目十步复制清单（M10-2）

> 固化日期：2026-10-15。来源：SEO/GEO V2.0 方法论 §11 十步。
> 适用对象：任何一个新站（不限于电子书转换领域）。
>
> ⚠️ **边界声明（必读）**：本清单只复制**流程与纪律**，**不得复制 BookConv 的任何具体数字**——页面数量、URL 提交条数、关键词数、R_pre/R_post 记录数、时间线、到期日等全部是个案事实，换个赛道/域名/竞争环境后没有外推效力。每一步的产出物在新项目里必须从零实测生成。

## 使用方式

- 按顺序执行，第 N 步的「完成判据」不满足不得进第 N+1 步（步与步之间是依赖关系，不是并行清单）。
- 每步产出物建议放入新项目仓的 `docs/` 或专门台账文件，命名见各步。
- 每步完成当天在项目台账登记：日期 + 证据路径，防「声称已完成」漂移。

---

## Step 1 — 建 SEO 基线

**做什么**：新站上线首日采集全量基线——GSC/Bing WMT 注册并验证；记录索引页数、抓取状态（crawl=已抓/未抓/never）、初始排名快照、技术体检（HTTP 200 / canonical / sitemap / noindex）。

**产出物**：`docs/seo-baseline-<date>.md` + 原始导出 CSV 存档。

**完成判据**：
- [ ] GSC 与 Bing WMT 均验证通过（能看数据）；
- [ ] 全部 URL 有抓取状态分类（允许 never，但要计数）；
- [ ] 技术体检逐项实测断言（不是「应该没问题」）；
- [ ] 基线数字只出现在台账里，作为后续对比锚点。

## Step 2 — 固定关键词表

**做什么**：从产品面出发列出核心词 + 长尾词，记录搜索意图、优先级（P0-P3）、目标页。词表一经固定，改动需走变更记录。

**产出物**：`docs/keyword-register.csv`（列：词、意图、优先级、目标 URL、来源、备注）。

**完成判据**：
- [ ] 每个词都绑定一个目标页（无孤儿词）；
- [ ] 优先级有判定依据（搜索意图与产品能力重合度），不凭感觉；
- [ ] 词表进入版本管理，后续增删有 diff 可查。

## Step 3 — 竞品表

**做什么**：对固定词表里的 P0/P1 词逐个记录当前 SERP 前列竞品：域名、内容形态、覆盖角度、明显缺口。

**产出物**：`docs/competitor-register.csv`（逐词登记，非整体印象）。

**完成判据**：
- [ ] 覆盖全部 P0/P1 词；
- [ ] 每行有采集日期（SERP 是时点数据，必须标注观测日）；
- [ ] 明确标注哪些结论是实测、哪些是推断（案例边界纪律）。

## Step 4 — 找可提升页

**做什么**：基于基线 + 词表，找出三类页：有展示无点击（Title/描述问题）、有排名无进入 Top10（内容深度问题）、零抓取（发现问题）。逐页登记问题类型与改造方向。

**产出物**：`docs/page-improvement-queue.csv`。

**完成判据**：
- [ ] 每页归入且仅归入一个主因（多因写主因+备注）；
- [ ] 主因判定引用基线数字（曝光/点击/位置/抓取状态），不是「我觉得」；
- [ ] 队列有优先级排序。

## Step 5 — 每日优化（受节奏约束）

**做什么**：从队列取页执行改造，**每日 ≤3 页**（节奏上限防同质化与自我干扰），每页改后跑门禁。

**产出物**：每日台账行（页、改动、门禁结果）+ 代码提交。

**完成判据**：
- [ ] 每页改后有可执行门禁全绿记录（语法/内容完整性/重复标题等）；
- [ ] 单日不超过 3 页；
- [ ] 改动有 commit，可回滚。

## Step 6 — 每周复查

**做什么**：固定每周同一时间复查：本周改动页的曝光/点击/位置变化 vs 基线；把「改动→效果」配对记录。

**产出物**：`docs/weekly-review-<date>.md`。

**完成判据**：
- [ ] 只读数不改站（复查日禁止同时改内容，避免归因污染）；
- [ ] 每条效果结论标注观察窗口天数；
- [ ] 被证伪的改动如实记录（不美化）。

## Step 7 — 稳定后进 GEO

**做什么**：SEO 数据进入稳定窗口（排名/索引不再剧烈波动）后，才启动 GEO（生成式引擎可见性）：建立 prompt 集、测量基线（R_pre）、锁定 promptHash。

**产出物**：`docs/geo-prompt-set.md` + R_pre 测量记录。

**完成判据**：
- [ ] 稳定窗口有明确判据（如连续 N 天索引数波动 < x%——x 由新项目自定，不抄 BookConv 数字）；
- [ ] 每条 prompt 记录：引擎、测量日期、是否被引、证据截图/文件；
- [ ] 零补造：没测到就如实标 BLOCKED，不允许填假数据。

## Step 8 — Prompt 监测

**做什么**：按固定周期（建议 ≥2 周/轮，防止把噪声当趋势）重跑 prompt 集测量，记录被引变化。

**产出物**：R_post 系列测量记录（与 R_pre 同 schema、同 promptHash）。

**完成判据**：
- [ ] 测量 schema 与基线一致（可逐条 diff）；
- [ ] 引擎不可用时显式记录缺失，不跨引擎拼接结论；
- [ ] 连续两轮才有趋势判断资格，单轮波动不下结论。

## Step 9 — GEO 优化

**做什么**：对「竞品被引、本站未引」的 prompt，做内容侧动作：结论前置、可引用要点、结构化数据、可验证数据点；每轮动作量受 Step 5 同款节奏约束。

**产出物**：geo 动作台账（prompt → 动作 → 日期）。

**完成判据**：
- [ ] 每个动作能回链到具体 prompt 与测量记录；
- [ ] 动作后有下一轮测量验证（不做无测量的持续投入）；
- [ ] 不承诺「一定被引」，只记录「做了什么、测到什么」。

## Step 10 — 回写

**做什么**：每月把「被证伪的判断」与「被数据支持的判断」回写方法论文档，附日期与证据；同步校准本清单里不适配新项目的步骤。

**产出物**：`docs/methodology-changelog.md`。

**完成判据**：
- [ ] 每月 ≥2 条（判断原话 / 结果 / 证据路径 / 日期）；
- [ ] 对本清单的修订有 diff 记录（改了哪步、为什么）；
- [ ] 对外内容含案例边界声明：本站数据为个案事实/推断，不构成通用规律。
