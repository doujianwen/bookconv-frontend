## 第 2 章 Discover：用手册的四个维度做体检

> 手册 §5：Speed 速度 / Altitude 高度 / Depth 深度 / Range 广度。
> 手册同时提醒："不必每次使用四个维度"——但对"方法论本身"做体检，四个都必须过一遍，因为方法论是跨任务复用的。

### 2.1 速度 Speed —— 被返工吃掉

- 手册定义：更快完成已有任务
- 本项目现状：单点执行速度不慢（一天内可完成"诊断→红队→修订→二次审计"三轮）
- **真实损耗**：13 次反转 = 13 次重做。若单次诊断成本为 1，实际成本为 14
- 结论（`Inference`）：**速度瓶颈不在产出，在返工。返工率不降，任何提效手段都是把水倒进漏桶。**
- 这条最容易被忽略，因为它看起来"不是方法论问题"。但手册把 Speed 列在第一位是有道理的：**返工是唯一会吃掉全部其他收益的成本项。**

### 2.2 高度 Altitude —— 最大缺口，且是反转的**经济学原因**

手册定义：**从完成任务上升到实现业务目标**。

**缺口 A1｜结论不与决策绑定 ⇒ 错误的代价为零 ⇒ 没人有动力验证**

这是本文件的核心论断。请对照一次真实的反转：

| 轮次 | 关于"月访问量"的结论 | 如果这个结论成立，下周会做什么不同的事？ |
|---|---|---|
| 第 1 轮 | 323 访问 vs 目标 5,000，缺口 15× | ——没有 |
| 第 2 轮 | 323 是 users 不是 sessions，实际 376 | ——没有 |
| 第 3 轮 | 5,000 是模型假设，不是实测目标 | ——没有 |

> **三轮结论完全不同，三轮的行动完全相同（继续写内容）。**
> 一个改或不改都不影响行为的结论，**它不是诊断，是消遣**。
> 消遣可以错，错了没有成本，所以它就会一直错下去——**反转不是纪律失守的结果，是信息价值为零的必然症状。**

- 推论（`Inference`）：过去几个月所有"数据诊断"的信息价值（VOI）都接近 0，因为没有任何决策挂在上面。
- 因此纪律必然不 fire：**没有任何人有理由为一个不影响任何事的数字去跑一遍 5 项自检。**

**缺口 A2｜优化了一个商业价值尚未确立的指标**

- `Fact`：`conversion_complete` 自 2026-09-28 起恒为 0，已 27 天；全站收入观察值为 $0（但严格说等级是 `Unknown`，因为没有支付链路可测）
- `Fact`：方法论的全部承重指标是 曝光 / 引用 / VI / 会话——**没有一个指标指向"有人付钱"**
- `Inference`：这等于在一个"顶层价值未确立"的框架内部做优化。手册 §8 第 2 步问"真正要解决什么"——答案不是"更多流量"，而是**"这个站值不值得继续投入"**。
- 一个能回答后者的方法论，第一件事应该是设计**证伪实验**（花最小成本看有没有人愿意付钱），而不是把曝光从 217 拉到 2,123。
- 对照：同一套方法论在 WP 商业站（`geo-growth-site`）里有 `/partner/`、`wp_ggs_leads` 落库、¥999 Entry 报价——**那里有高度，这里没有**。这不是能力问题，是 bookconv 从规划阶段就没定义过商业目标，方法论忠实继承了那个空白。

**缺口 A3｜没有"这个结论会改变什么"的强制字段**

- 48 条判断纪律里，**0 条**要求回答"如果这个结论是错的，哪个决策会变"。
- 这一条同时是高度问题和验证问题：它既让方法论悬空，又抽掉了验证的唯一动机。

### 2.3 深度 Depth —— 实现层极强，统计层与元层缺失

手册定义：**采用专业方法、原始资料和验证**。

**先记账：深度是我们的强项，不能自我否定。**

| 证据 | 深度体现 |
|---|---|
| `r2.ts` 在模块加载期读 env，导致 `isR2Configured()` 与 `getClient()` 状态不一致 | 由新写的单测抓到，属真实潜伏 bug |
| `/convert/lit-to-epub` 三处配置冲突（middleware 301 / `ESP_CONVERT_SLUGS` / `sitemap.ts:216` 同名常量遮蔽 import） | 一路挖到行号，并识别出"两个错误互相抵消成一个正确" |
| `CTR_AUDIT_REPORT.md` §6"91 页缺 description" | 反向验证发现运行时兜底存在，实为文案缺口非结构缺陷 |
| `sitemap.xml` 0 条 `<loc>` | 追到 apex→www 301，实际 165 条 |

> 这四项没有一项是"看源码猜的"，全部是"跑一遍 / 跟一次重定向 / 读运行时"。**这就是手册说的"原始资料"**，做得比大多数团队好。

**缺口 D1｜统计深度缺一层：没有效应量下限（MDE）**

- 现有：有样本量意识（VI 的 n>400 门槛、小 n 用泊松区间）、有窗口纪律
- 缺失：**"这个差异是否大于噪声"的判据**
- 实证：`Fact` —— 移动端 engagement 29.5%（n=36 uploads）vs 桌面 56.9%（n=131），差 27.4pp。这个差在 n=36 上的 95% 置信区间宽度约 ±16pp，**两个区间几乎相接**。我们把它写进了改善清单第 1 条，但从未算过它是否可区分。
- 实证：`Fact` —— "Google 只有 2 个用户"被当成结论用过一轮。n=2 不是数据，是轶事。
- 后果：**MDE 缺失 ⇒ 把噪声当信号 ⇒ 在噪声上做决策 ⇒ 下一窗口必然反转。**

**缺口 D2｜时间轴深度缺失：没有预注册观察窗**

- 现有：会标注"recent7 仅 37 曝光"
- 缺失：**在取数之前就固定窗口与主要终点**
- 实证：Bing AI VI +147.8% → −10.0%（换窗口即反转）；323 vs 5,000 换过 3 个口径
- 临床研究早就解决了这个问题：**预注册 + 单一主要终点**。我们每次都是"先看数据，再决定哪个窗口讲故事"——这叫 p-hacking 的中文版。

**缺口 D3｜因果深度停在"机制核验"，没到"反事实"**

- 现有：会问"机制对不对"（很对，这是 T1 的贡献）
- 缺失：**不问"如果我不做，这个数会怎样"**
- 后果：所有结论都是"做了之后观察到 X"，没有一条是"不做也会观察到 X，所以 X 与我无关"。
- 这是广度问题（§2.4 C1）的孪生兄弟：没有反事实，就没有因果。

**缺口 D4｜最狠的一条：纪律自身没有存活探针（liveness check）**

- 现有：对代码门禁有反向验证、有 `checked>0`、有三态 exit code——**这套东西很成熟**
- 缺失：**这套东西从没用在"纪律"自己身上**
- 实证：F3。`self-audit-before-output` 死了 16 天，零告警
- 判据（可直接执行）：**任何纪律资产，若不能回答"你上次实际触发是什么时候"，一律视为未部署。**
- 这条比任何一条 SEO 纪律都值钱，因为它是元层的：**它保护所有其他纪律。**

### 2.4 广度 Range —— 只有 SEO 一个学科，且没有比较类

手册定义：**引入其他学科有效方法**。

**缺口 C1｜学科广度 = 0：13 次反转里 8 次是本学科解决不了的问题**

| 反转实例 | 缺的是哪个学科的方法 |
|---|---|
| 323 vs 5,000（分母/单位错） | 统计学 · 量纲一致性 |
| Bing 17×（跨窗口相除） | 计量经济学 · 可比性 |
| 月收入 $0 报成事实 | 决策论 · 证据等级 |
| "唯一规律"（n=1） | 统计学 · 样本外推边界 |
| 内容超额 4.7×（分母是规划目标） | 会计 · 口径定义 |
| 产能投错端（被数据反驳） | 运筹学 · 约束理论 |
| 97 页缺 description（静态字段） | 软件工程 · 运行时验证 |
| sitemap 0 条（未跟重定向） | 网络诊断 · 入口验证 |

> **规律（`Inference`）：8 次反转，0 次需要新的 SEO 知识；8 次全部需要另一个学科的判据。**
> 我们过去几个月的学习几乎全部投向 SEO/GEO 本学科（两本手册 2,108 行），而反转的原因 100% 在本学科之外。
> **这就是"广度"缺口的精确度量：投入方向与失败方向正交。**

**缺口 C2｜没有比较类（comparison class / peer set）**

- 现有：所有数字对**绝对目标**判生死（5,000 访问、VI ±10%、pos <10）
- 缺失：对**同龄站**判生死
- 后果：`Fact` —— 一个 90 天、165 页、零外链、零收入的新站，月访问 376 到底是"惨败"还是"正常"？**我们从未有过答案，因为没有对照组。**
- 没有对照组的直接后果：**任何一个数字都可以被解释成成功或失败，取决于当天的心情和叙事需要。** 这是 13 次反转的温床。
- 最低成本补法：不需要付费工具。用 Ahrefs/Semrush 的免费额度抓 5–10 个同赛道站（同类工具站、上线时间相近），建一个"同龄站基线"，每季度更新一次。

**缺口 C3｜反假设集恒定，从不扩展**

- 现有反假设集（几乎每次都在这 4 个里打转）：内容质量 / 抓取预算 / 权威度 / 内耗
- 从未进入过的反假设：
  - **需求本来就不存在**（关键词量是估算，不是事实）
  - **工具本身坏了**（实际发生过：CloudConvert 402 三次复发）
  - **关键词量估错**（Ahrefs 数字是模型输出）
  - **竞品拿走了**（从未做过竞品流量对比）
  - **渠道结构性不可达**（平台限制 vs 产品决策混淆）
- 实证：`Fact` —— djvu/chm/cbr/cbz/fb2/pdb 的 27 个 backlog 合计约 1,900–2,200 搜索/月，即使 100% 捕获也只有 570–660 会话/月。**这个反假设一旦出现，就直接推翻了"80K/月"投影的自洽性。** 而它出现在第 4 轮。
- 判据：**一个反假设集如果连续 3 轮没有新增项，它已经不是假设集，是信仰。**

## 第 3 章 Select：复杂度错配是总病根

> 手册 §7 三种任务复杂度：L1 简单 / L2 专业 / L3 复杂项目。手册原话提醒："判断任务复杂度，避免过度工程化"。

### 3.1 三档的判据（本项目化）

| 档 | 判据（满足任一即属该档） | 正确投入 |
|---|---|---|
| **L1** | 答案是一个数、一次查证、一次换算；错了改一个字段即可 | 直接做，1 次验证，**不红队** |
| **L2** | 需要专业方法 + 原始数据 + 反例检验；错了改一段分析 | 方法发现 → 取数 → 反例 → 证据分级 |
| **L3** | 涉及多因、多主体、跨时间、有资源分配后果；错了改路线 | 目标定义 → 方案 → 里程碑 → 权限 → 验收 |

### 3.2 本项目 6 个真实问题的错配判定

| 问题 | 实际档位 | 我们的处理方式 | 判定 |
|---|---|---|---|
| "323 和 5,000 差多少" | **L1**（一个减法） | 三轮红队、13 次反转、写成承重结论 | 🔴 **L1 问题用 L3 流程** → 烧掉全部产能 |
| "为什么流量没起来" | **L3**（商业模型+渠道+产品+竞争+时间） | 看一眼 GA4、查一次 GSC、定性为"内容不够" | 🔴 **L3 问题用 L1 处理** → 必然反转 |
| "补 97 个 meta description" | **L1**（一个批量赋值） | 写成改善清单第 1 组、当成结构缺陷 | 🟡 过度定性（实际是文案缺口） |
| "移动端转化率低于桌面" | **L2**（需显著性检验） | 直接写进改善清单第 1 条 | 🔴 跳档 |
| "直接上传 R2" | **L3**（跨端改造+容量+安全+回滚） | 正确：21 单测、tsc、build、三层回滚、CORS 前置 | ✅ **唯一正确分档** |
| "skill 是否在加载" | **L1**（一次 `ls`） | 从未做过 | 🔴 该做的 L1 被跳过 |

### 3.3 错配的机械后果（这是解释一切的那把钥匙）

```
L3 问题被 L1 处理
  → 用单点证据回答多因问题
  → 证据必然不足
  → 结论必然在下一次取数时反转
  → 反转被当成"纪律问题"追加新规则
  → 规则加在 L1 侧（因为好写）
  → L3 问题仍被 L1 处理
  → 循环
```

```
L1 问题被 L3 处理
  → 一个减法消耗三轮红队
  → 产能耗尽
  → 真正需要 L3 的问题（商业价值验证）无人处理
  → 方法论越来越厚，业务越来越薄
```

> **两条闭环合起来，就是过去几个月的全部真相。**
> 我们不是纪律不够，是**纪律被用在了错误的地方，而且用错了方向**。
> 手册 §7 那句"避免过度工程化"，在我们这里不是建议，是诊断结论。

### 3.4 附带发现：纪律的形态由上一场战争决定

- `Fact`：现有三类失败模式（归因过度延伸 / 统计过度精确 / 诊断未反向验证）全部成型于 2026-09-03 → 10-09 那场"spam update + VI 翻转"的战争，那是一场**统计战**
- `Fact`：本次会话 13 次反转的失效归类（见附录 B）中，**5 次属技术验证类**（静态≠运行时、入口未验证、时序错认），现有三类模式**未覆盖**
- 覆盖度：3 / 8 = **37.5%**
- `Inference`：**纪律总是落后一场战争。** 所以"根据上次事故补规则"这个做法，结构上只能覆盖上次的形状。
- 这不是说补规则错了，而是说：**补规则不能作为主要防御手段，因为它按定义只防已经发生过的形状。** 主要防御必须是"结构上强制填槽"的东西——槽位固定，内容自适应（见 §4.2）。

## 第 4 章 Apply：迭代方案——减法的加法

### 4.1 设计原则（三条，缺一不可）

1. **能被枚举的纪律才存在。** 48 条散文纪律 = 0 条纪律。新方案必须能被数出来。
2. **纪律必须挂在"结论产生的那一刻"，而不是"事后复盘时"。** 事后登记（claim-tier-register）在结构上无法阻止反转，因为反转已经发生了。
3. **纪律必须自带存活探针。** 不能回答"上次实际触发是什么时候"的纪律，一律视为未部署。

> 反面教材就在眼前：`self-audit-before-output` 三条原则都符合前两条，**唯独缺第三条，于是死了 16 天。**

### 4.2 交付物 1｜结论卡（Claim Card）——用 7 个空取代 48 条散文

**规则：任何含"结论/归因/数字/诊断/建议"的输出，必须先填这张卡。缺任一字段，该结论不得以肯定语气输出。**

| # | 字段 | 强制内容 | 它防的是哪个失效类 |
|---|---|---|---|
| 1 | **结论** | 一句话，≤40 字 | —— |
| 2 | **窗口 & 分母** | 起止日期 + 分母是什么（users/sessions/impressions/pages） | 口径错配、跨窗口相除 |
| 3 | **n** | 样本量 + 是否可区分于噪声（n<30 必须写"方向性，非精确"） | 小样本外推、MDE 缺失 |
| 4 | **数据源** | 具体到工具 + 导出文件名/API 名 + 取数时间 | 数据源选错、引用上轮摘要 |
| 5 | **反假设** | 至少 2 个替代解释，各自如何被排除（或标注未排除） | 归因过度延伸、反假设集僵化 |
| 6 | **决策挂钩** ⭐ | 若此结论为真 → 哪个决策变；若为假 → 哪个决策变。**若两者相同，此结论无信息价值，标记 `NO-VOI` 并不得作为承重结论** | 高度缺失、验证动力为零 |
| 7 | **等级** | `Fact` / `Inference` / `Hypothesis` / `Unknown` 四选一 | 该报 UNKNOWN 却报确定值 |

**为什么第 6 个字段是关键**：它是唯一同时修好"高度"和"验证动力"的字段。
- 填不出第 6 字段 ⇒ 这个结论不该做（省下产能）
- 填得出 ⇒ 有决策挂在上面 ⇒ 验证有回报 ⇒ 纪律自然 fire

> **这是整份文件最重要的一处设计。** 它把"要记得验证"这种意志力要求，换成了"填不出就别写"的结构性约束。

**存量回填测试**：拿 13 次反转逐条回填，若第 6 字段能填出的不足 3 条，则证明过去数月的诊断信息价值≈0（`Hypothesis`，需实测）。

### 4.3 交付物 2｜复杂度路由（3 问，输出前必答）

```
Q1 这个问题的答案，如果错了，是改一个字段，还是改一段分析，还是改一条路线？
    → 字段 = L1 / 分析 = L2 / 路线 = L3

Q2 这个问题有几个可能的原因？如果 ≥3 个且都能自圆其说 → 至少 L2，禁止 L1 处理

Q3 我对这个结论的投入，是否超过了 Q1 判定的档位？
    → 是 ⇒ 立即降档（过度工程化）
    → 否 ⇒ 检查是否漏了反假设（投入不足）
```

**强制约束（红线）**：
- 🔴 **L1 结论不得进入红队流程**。发现自己在为一个减法跑三轮审计时，立即停手。
- 🔴 **L3 结论不得由单点证据支撑**。至少 2 个独立数据源 + 1 个反假设被排除。
- 🔴 **每次复盘必须统计"错配次数"**（S4）。这是唯一能发现"把力气用错地方"的指标。

### 4.4 交付物 3｜反假设必答 5 条（广度补丁）
