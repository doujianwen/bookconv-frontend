## 1. 每节课的交付物清单（DoD）

每节课录制完成 = 以下六项全部齐备，缺一项不算完成：

| # | 交付物 | 格式 | 用途 | 负责人 |
|---|--------|------|------|--------|
| D1 | **`lesson-XX.chapters.json`** | JSON，见 §2 | 播放页「关键节点时间轴」的数据源；视频与图文的唯一锚点 | 讲师录制时产出 |
| D2 | **视频文件** | MP4，1080p，含 `.vtt` 字幕轨 | 主形态 | 讲师 |
| D3 | **图文正文** | Markdown，68ch 宽度，含代码块/提示词块/踩坑块 | 辅助形态 + 无障碍替代文本 | 讲师 + PM 校对 |
| D4 | **提示词文件** | `prompts/lesson-XX/` 目录，每个 prompt 一个 `.md` | 学员可直接复制使用；播放页右栏「本节资源」挂载 | 讲师 |
| D5 | **检查清单** | `checklists/lesson-XX.md`，对应本节验收项 | 学员自查；M3 安全清单的节级落地 | PM |
| D6 | **git commit 链** | 每个逻辑步骤一个 commit，message = chapters.json 的 label 草稿 | 可追溯；学员可对照 commit 历史理解步骤边界 | 讲师 |

> **D1 是 blocking 项**：没有 chapters.json，播放页最有价值的部件（关键节点时间轴）会降级隐藏（见 pages-visual-direction.md Edge 态），视频与图文变成两个割裂区块。这条写进 DoD 不是建议，是硬约束。

## 2. `lesson-XX.chapters.json` 规范

### 2.1 格式

```json
[
  { "t": 134,  "label": "初始化 Next.js 项目",        "type": "step" },
  { "t": 460,  "label": "写第一条 Cursor 指令",       "type": "prompt" },
  { "t": 902,  "label": "这里会卡住：环境变量没生效", "type": "pitfall" },
  { "t": 1204, "label": "部署到 Vercel",              "type": "step" }
]
```

### 2.2 字段说明

| 字段 | 类型 | 说明 |
|------|------|------|
| `t` | number | 时间戳，单位**秒**，从视频开头计。精度到秒，不要写 `02:14` 字符串 |
| `label` | string | 中文步骤名，≤16 字。同时是图文正文对应小节的标题（锚点 ID = `lesson-XX-step-N`） |
| `type` | enum | 仅三个值：`step` / `prompt` / `pitfall`，决定渲染图标 |

### 2.3 type 定义与录制对应

| type | 含义 | 图标（Lucide） | 录制时的标志 |
|------|------|----------------|-------------|
| `step` | 一个可执行的操作步骤 | `circle-dot` | 每个逻辑步骤结束**停顿 3-5 秒**再继续 |
| `prompt` | 给 AI 的一段指令（展示 prompt 全文） | `message-square-code` | 屏幕上出现完整 prompt 文本时 |
| `pitfall` | 会卡住的地方（真实踩坑，不是预设的） | `triangle-alert` | 出现报错 / 走弯路 / 回退重做时 |

### 2.4 录制习惯（让 JSON 几乎自动产出）

1. **每个逻辑步骤结束停顿 3-5 秒** —— 后期定位时间戳时一眼能看出步骤边界
2. **每步一个 git commit** —— commit message 基本就是 `label` 和图文版小标题的草稿
3. **踩坑照实录** —— pitfall 类条目的价值在于真实；如果录制中没踩坑，就不要硬编一个
4. **录制结束当天补完 JSON** —— 拖到第二天会忘时间戳精度

### 2.5 与图文正文的锚点关系

chapters.json 的每条 `label` 必须在图文正文中有对应的小节标题（H3），且该标题的 `id` 遵循 `lesson-XX-step-N` 规范。这样播放页点击步骤名能滚动到正文对应位置，点击时间码能 seek 视频——两种形态缝在一起。

## 3. 内容分层（抗过时，PRD §4）

每节课的内容必须按以下分层组织，录制和图文都遵循：

| 层 | 占比 | 内容 | 工具变了会失效吗 |
|----|------|------|-----------------|
| **稳定层** | ~70% | 方法论、Spec 写法、验收标准、诊断框架、需求拆解思路、架构决策原理 | 不会 |
| **易变层** | ~30% | 具体工具的操作步骤（Cursor 界面、Vercel 面板路径、命令行指令） | 会，按季度重录 |

**录制纪律**：稳定层与易变层在视频中必须口头标注（如「接下来这部分是工具操作，工具升级后步骤可能变，但原理不变」）。chapters.json 的 `label` 尽量用稳定层语言（如「初始化项目」而非「在 Cursor 里按 Cmd+K」）。

## 4. 两类学员的分层入口

同一节课，两类学员的入口不同：

| 学员类型 | 前置要求 | 可跳过的 | 必须看的 |
|----------|----------|----------|----------|
| A 类（零基础产品人） | 从 M5 环境工具链开始 | 无 | 全部，按顺序 |
| B 类（有代码基础） | 可跳过 M5 | M5 全部、M1 中「什么是 PRD」基础段 | M1 的 Spec 驱动段、M3 安全清单、M4 增长诊断、M6 的架构决策段 |

**实现方式**：chapters.json 不做两份，但在图文正文中用标注块区分：
- 「A 类必看」标注块：补充环境配置细节、概念解释
- 「B 类可跳」标注块：标记可跳过的段落，给出跳到哪个时间戳

播放页左栏导航行不区分 A/B，因为两类学员看的是同一节课，只是深度不同。

## 5. 真实数据使用纪律（P0 红线）

> 这条直接来自设计师要求 + PRD §0 判断二（诚实账本定位）。

| 规则 | 说明 |
|------|------|
| **所有数字必须有出处** | 格式：「数值 · 来源 · 日期」，如「287 次展示 · Google Search Console · 2026-08」 |
| **禁止编造数字** | 设计师文档中的「上线 47 天，自然流量 3,182 次」是占位示意，上线前必须替换为真实值 |
| **禁止无源大数字** | 「10,000+ 学员信赖」「帮助数万人」等无出处的数字一律禁止 |
| **真实数据优先于好看数据** | bookconv 的 0 点击、25 活跃用户是难看的，但它们是真实的，且是课程卖点的核心组成部分 |
| **截图必须是真实的** | bookconv 首页截图、Cursor 对话截图、Vercel 面板截图必须来自真实操作，不做抽象插画替代 |

## 6. 文案禁用词表

以下词汇在本项目全部内容中禁止使用（设计师要求 + P0 规则）：

| 禁用词 | 替代方向 |
|--------|----------|
| 「开启你的 AI 之旅」 | 写具体动作，如「跟着做完你会有一个能公网访问的产品」 |
| 「解锁无限可能」 | 写具体能力，如「学会用 AI 从 PRD 生成可执行代码」 |
| 「Welcome to」 | 直接说课程做什么 |
| 「赋能」 | 写具体帮谁做什么 |
| 「一站式」 | 写具体包含什么 |
| 「Sign up today」 | 写具体收益 + 具体动作 |
| 「Lorem ipsum」 | 不解释 |
| 任何 emoji | 用文字描述图标含义 |
