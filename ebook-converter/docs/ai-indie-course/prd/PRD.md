## 0. 给主理人的三个前置判断（先看这个）

### 判断一：这门课的真实差异化不是「AI 教编程」，是「上线之后怎么办」

市场上 AI 编程课已经严重同质化——全都停在「跑起来了」。而 Ahrefs 对 10 亿页面的研究结论是：**90% 的网页从 Google 拿到的自然流量是 0**。也就是说，学员按任何一门课做完产品后，最大概率的结局就是「上线了，没人用」。

**目前没有一门课教这一段。** bookconv 恰好有这段的一手真实数据。这是本课最硬的护城河。

### 判断二：必须放弃「成功学」定位，否则会被自己的案例证伪

bookconv 的真实数据（我已从本地 `数据分析/` 目录核验）：

| 指标 | 真实值 | 说明 |
|------|--------|------|
| GSC 页面层展示（14 天） | 287 | 持续爬坡 +21% |
| GSC 点击 | **0** | 第 4 次导出仍为 0 |
| GA4 活跃用户（4 周） | **25** | 其中 18 个来自中国（英文站，非目标用户） |
| 位置 1-20 的展示占比 | 19.8% | 已进可点击区但仍 0 点击 |

如果宣传语写「跟我做出月入 X 的产品」，第一节课打开 GSC 就穿帮。

**正确定位**：「我把一个真实上线站的全部账本摊开给你看——包括难看的那部分，以及我怎么诊断它。」
诚实在这个品类里是稀缺资源，因为竞品市场充斥虚假成功故事（调研中即发现「33 岁 PM 被裁 30 天靠 AI 月入 4 万」这类卖书软文，文中当事人自述「我也看不懂代码，运行不报错就行」）。

### 判断三：不「重跑 bookconv」，而是真实新建一个衍生产品（案例已确认）

主理人原方案是「让专家团真实重跑开发流程并录制」。问题是：bookconv 已上线一年，重跑是**重演**，不是真实决策——录出来是表演，学员能看出来，且失去了「真实踩坑」这个最值钱的素材。

**已确认方案**（主理人 v1.1 拍板）：真实新建的衍生产品 = **「转换兼容性实测报告页生成器」**。它复用 bookconv 仓库**已有的** `verifyConversion()`（conversion-verifier.ts:162）真跑格式对，把实测数据沉淀成每个转换对的独有内容页——既不编造数据，又天然产生可被 Google 收录的差异化长尾内容。

**这个选品为什么对**（产品视角）：
1. **真实而非表演**：用真实运行产出的实测数据，每页内容是 bookconv 这个真实引擎跑出来的真实验证结果，不是抄来的。
2. **合规护城河**：实测数据沉淀成独有内容，规避「批量生成模板页」触发 Google 内容政策风险（§8 边界条件里的硬约束）。
3. **复用已有能力**：`verifyConversion()` 已落地（见 §4 卖点支点 2），课程精力花在「内容系统 + SEO 派生」上而非重写引擎。
4. **教学价值高**：它本身就是一个「把已有能力包装成可被搜索发现的内容产品」的完整案例，恰好覆盖六阶段里的「调研→Spec→设计→部署→增长」全链。

bookconv 则作为**已有真实数据的参照系**，贯穿全程提供「一年后会变成什么样」的答案。课程同时得到：真实的过程（新衍生产品）+ 真实的结果（bookconv 一年数据）。二者缺一，课程都不完整。

## 1. 问题陈述

### 谁，在什么场景，遇到什么痛点

**场景 A — 零基础产品人**
有产品/运营思维，能写 PRD、能画原型、懂用户，但从「PRD」到「一个别人能访问的 URL」之间是断的。
现在的解法：看 vibe coding 教程 → 做出 demo → 卡住。
为什么不行（均来自真实差评，见 §3）：
- 教程按工具版本录制，工具迭代后步骤全失效（Coursera 学员：「课程基于 Cursor 1.x，2.x 已发布，`@Web` 都废弃了」）
- 号称零基础，实际跳步（学员：「老师太快，跳过了对没有编程背景的人必要的步骤……我照着她的方式写 prompt，免费额度中途就烧光了」）
- 学完不知道自己做了什么（Inflearn 学员：「我不知道刚才粘贴了什么、点了哪里、现在在哪一步……更不知道怎么变现」）

**场景 B — 有代码基础，想系统化 AI 协作**
会写代码，但用 AI 的方式还停留在「逐行让它补全」，没有形成流程。
为什么不行：
- METR 2025 年 7 月研究：资深开发者使用 AI 工具完成真实任务时**平均慢 19%**；2026 年 2 月的后续研究收窄了幅度，但复杂任务方向仍为负。
- 原因不是工具差，是**工具解决错了问题**——AI 把「规划」变便宜了，但卡住开发者的从来不是规划，是执行与收敛。

### 共同的真实痛点（去掉两类人的表层差异后）

1. **没有可复用的流程** —— 每个项目都从零试错，经验不沉淀
2. **产出的是 demo 不是产品** —— CMU 研究：AI 生成代码 61% 功能正确，但**只有 10.5% 安全**，功能正确的代码里 **82.8% 含安全漏洞**
3. **上线后没有增长闭环** —— 最大的断层，几乎无人教

> **需求挖掘结论**：用户嘴上说的是「教我用 AI 写代码」，真正要解决的是「让我一个人也能把一个想法走完从 0 到有人用的全程，并且下次还能复用」。代码只是这条链路上最不缺教程的一环。

## 2. 目标用户

### 主要画像 A：「有想法、没通路」的产品人（占预期学员 60-65%）

| 维度 | 描述 |
|------|------|
| 年龄 / 职业 | 26-38 岁，互联网产品/运营/项目经理，含在职副业与被裁转型两类 |
| 技术水平 | 能读懂 HTML/CSS 概念，不能独立配环境、不能 debug、没部署过 |
| 触发动机 | ① 职业不安全感（裁员、35 岁）② 想验证一个憋了很久的想法 ③ 同侪刺激（看到别人 AI 做出产品） |
| 真实痛点 | 环境配置就劝退；做出 demo 后不知道下一步；沉迷技术细节跑偏；上线后零用户 |
| 付费意愿 | **中高**，¥300-1000 区间决策快（对标其一个月咖啡钱/一次培训） |
| 决策门槛 | ① 「我这种真的能学会吗」② 「课程会不会很快过时」③ 「是不是又一个卖成功学的」 |

**这一画像最危险的坑不是不会写代码，是没有约束。** 调研中找到一篇极具代表性的自述（人人都是产品经理《失业产品经理转型独立开发者道心已碎》）：一位 6 年经验 PM 离职做独立开发，两年间——为了一个收藏插件去自研富文本编辑器（耗 3 个月）、为了聊天室去啃即时通讯高并发（耗 2 个月）、遭遇黑产批量注册 300 万账号与持续一个月的 CC 攻击，最终财务陷入危险。他的复盘原话：

> 「很多东西当局者迷，尤其在自己做东西的时候没有第三视角，也没有人及时点醒你，就会陷进去无法自拔……业务优先，不要重蹈我的覆辙。」

**产品含义**：这类学员需要的核心价值是「**外部约束 + 第三视角**」，不是知识点。课程必须内建「防跑偏」机制（范围冻结、砍需求清单、阶段验收关卡），这是内容设计的硬约束，不是加分项。

### 次要画像 B：「会写代码、流程没升级」的开发者（占预期学员 35-40%）

| 维度 | 描述 |
|------|------|
| 年龄 / 职业 | 25-40 岁，前端/后端/全栈，在职为主 |
| 技术水平 | 能独立开发，已在用 Cursor/Claude Code/Copilot，但用法零散 |
| 触发动机 | ① 想把 AI 从「补全工具」升级成「协作流程」② 想做独立产品但缺产品侧能力 ③ 焦虑（怕被会用 AI 的人替代） |
| 真实痛点 | 用 AI 反而更慢（METR 19%）；AI 代码不敢直接上线又不知怎么系统性验收；技术过关但不会选题、不会 SEO、不会定价 |
| 付费意愿 | **中**，对内容深度挑剔，¥200-600；极度反感「教我 Cursor 怎么装」 |
| 决策门槛 | ① 「是不是又一个 Cursor 入门」② 讲师是否真上过线（有无真实生产项目） |

**关键洞察**：B 类人**缺的恰好是 A 类人有的**（产品判断、需求收敛、增长），A 类人缺的恰好是 B 类人有的（工程收口）。这决定了课程结构——不做两套课，做**一条主线 + 两个分层入口**，让两类人在同一个项目上互补，也让社群天然有价值。

### 3.3 从竞品差评中提炼的市场空白（按价值排序）

1. **上线后的增长诊断，全市场空白** —— 所有课程止于部署。而 90% 的页面零流量，这是必然遭遇的墙。
2. **「外部约束」形态空缺** —— buildspace 关停后无人填补；而这恰是画像 A 的核心需求。
3. **抗过时设计缺失** —— 差评第一高频词是「过时」。竞品把课程绑死在工具版本上。
4. **AI 代码的安全与验收无人教** —— 82.8% 的「能跑的」AI 代码含漏洞，却没有课程给验收清单。
5. **真实数据缺席** —— 竞品清一色 toy example 或成功学，没有人敢把 GSC 后台 0 点击的截图放上去。

## 4. 我们的差异化

### 一句话价值主张

> **「跟着一个真实上线的产品，把从想法到有人用的六个阶段走完一遍——包括没人用的时候怎么办。」**

备选（更锋利，面向 A 类）：
> **「不教你写代码，教你一个人怎么把产品送上线，并且知道下一步该改什么。」**

### 五个不可复制的支点

| 支点 | 具体内容 | 竞品能否复制 |
|------|----------|--------------|
| **真实项目 + 真实账本** | bookconv 已上线一年：15 种格式 / 26 个转换对、37 篇博客 / 23 篇指南、Pro 订阅已跑通、GA4 + GSC 完整历史数据 | 难。需要真的运营过一年 |
| **真实工程复杂度**（不是 todo app） | 本地核验的真实技术栈：Next.js 16.2.10 + React 19.2.4 + Tailwind + next-intl(en/es) + **BullMQ/Redis 异步任务队列** + **AWS S3 大文件存储** + **Sentry 错误监控** + payments checkout/webhook + Zod 校验 + Redoc API 文档 + Vercel | 难。竞品案例多为单页 CRUD |
| **转换纠察层（已有能力，非待办）** | `verifyConversion()`（conversion-verifier.ts:162）：在 Calibre 报成功后自动内联校验输出——存在性/空文件/魔数格式匹配/文本丢失率，任一 CRITICAL 级发现即一票否决、不交付用户。由 queue.ts:315 和 conversion.ts:370/396 自动调用。**课程衍生产品「转换兼容性实测报告页生成器」正是复用它真跑格式对、沉淀实测数据** | 难。这是真实工程里才会有的「不信任上游」防御层，竞品 toy example 无此复杂度 |
| **诚实的失败数据** | 287 展示 / 0 点击 / 25 活跃用户，全程摊开，教诊断方法 | 不愿复制（伤营销） |
| **六阶段可迁移方法论** | 需求→调研→Spec→设计→开发→测试→部署，不绑定具体工具版本 | 可模仿，但缺真实案例支撑则空洞 |

> 事实备注（供架构师/课程文案使用，勿写错）：
> - 订阅状态管理 `subscription.ts` **已走 Redis 实现**（import getRedisClient，用 `sub:` 前缀键 + setex TTL），缺的只是 `REDIS_URL` 连接实例，不是待办功能。
> - 用户存储 `auth/storage.ts` 仍是**内存 Map**（`const users = new Map()`，第 15 行），未持久化——这是真实待办，也是课程讲「生产化」时的现成反面素材。

### 抗过时设计（针对差评第一高频词）

课程分两层，物理隔离变化速度：
- **稳定层（占 70%）**：方法论、Spec 写法、验收标准、诊断框架 —— 工具换了也不失效
- **易变层（占 30%）**：具体工具操作 —— 独立成短模块，承诺按季度重录，不与主线耦合

这一条要写进销售页，直接回应「会不会很快过时」这个决策门槛。

| M8 | **付费闭环**：checkout + webhook + 订阅状态一致性 | 6 | 2 | 80% | 3 | 3.2 | v2 |

| M10 | **生产可观测**：Sentry 错误监控与线上问题定位 | 5 | 1 | 100% | 2 | 2.5 | v2 |
| M11 | **异步任务队列工程**（BullMQ + Redis + S3 大文件） | 4 | 2 | 100% | 4 | 2.0 | v2 |
| M12 | **30 天陪跑 Sprint**（填补 buildspace 空缺） | 8 | 3 | 50% | 8 | 1.5 | v2（高价值高风险） |

> M12 分数低是因为 Effort 极高（需持续人力投入，不可规模化）且 Confidence 仅 50%（未验证）。**但它是长期护城河最深的一项**——建议 v1 先以「轻量版」验证：仅对付费学员开放阶段性提交 + 批量点评，不承诺一对一。

### MVP 范围（v1 首发）

按纪律收敛，v1 只承诺 **三件事**，模块服务于这三个承诺：

| 核心承诺 | 支撑模块 | 对应学员疑虑 |
|----------|----------|--------------|
| **承诺一：给你一套可复用的 AI 协作流程** | M1 + M2 + M7 | 「学完能不能自己做第二个」 |
| **承诺二：让你真的上线一个能用的产品（不是 demo）** | M6 + M3 + M5 | 「我这种真的能学会吗」
| **承诺三：上线后没人用，教你怎么诊断下一步** | M4 | 「是不是又一个卖成功学的」 |

> 承诺二的前置 blocking：M6 衍生产品「转换兼容性实测报告页生成器」进开发前必须通过 AC-6 样本书闸门（首批 30 页 + Project Gutenberg + 人工审核 + GSC 观察两周）。此闸门由架构师把关，PM 验收。

**进 Backlog（v2 及以后）**：M8 付费闭环、M9 i18n/SEO 系统、M10 可观测、M11 队列工程、M12 陪跑 Sprint、结业认证、学员作品集。

**明确不做（v1）**：不做多技术栈并行（只讲一条 Next.js 主线）、不做移动端/小程序、不承诺变现结果、不做直播。

## 7. 验收标准（Given/When/Then）

**AC-1 主线完整性**
Given 一名零基础学员按顺序学完 v1 全部 MVP 模块，
When 他跟随课程操作，
Then 他名下有一个可通过公网 URL 访问的、部署在生产环境的产品，且能说出这个产品解决谁的什么问题。

**AC-2 流程可迁移**
Given 学员已完成课程项目，
When 他被要求为一个全新的、课程未涉及的想法产出交付物，
Then 他能独立产出六阶段的阶段性文档（需求陈述 / 竞品清单 / Spec / 验收标准），无需回看视频。

**AC-3 抗过时**
Given 课程中使用的某个 AI 工具发布了破坏性更新（如 Cursor 主版本升级导致操作路径变化），
When 学员按课程操作失败，
Then 他能在配套图文手册中找到「工具变更应对」章节并自行恢复，且主线方法论模块无需重录。

**AC-4 安全验收（差异化硬指标）**
Given 学员拿到一段 AI 生成的、功能可运行的代码，
When 他执行课程提供的安全验收清单，
Then 他能识别出至少：密钥硬编码、缺少输入校验、缺少速率限制、权限校验缺失 四类问题中的三类。

**AC-5 增长诊断（差异化硬指标）**
Given 学员的产品上线 30 天后 GSC 显示有展示但点击为 0，
When 他执行课程的诊断流程，
Then 他能定位到问题属于「排名不够 / 标题与意图不匹配 / SERP 呈现不足 / 样本量不足」中的哪一类，并给出下一步动作，而不是盲目重做产品。

**AC-6 样本书闸门（课程衍生产品的 blocking 前置条件）**
Given 课程衍生产品「转换兼容性实测报告页生成器」进入开发阶段前，
When 架构师/讲师准备用 `verifyConversion()` 真跑格式对生成实测报告页，
Then **必须先备齐样本书清单并通过人工审核**：首批卡 30 页、样本书取自 Project Gutenberg 公共领域书目、每页实测数据经人工审核确认非编造、上线后 GSC 观察两周再决定是否扩量。**样本书不齐不得进开发阶段**——否则页面会退化成编造数据，直接引爆 Google 内容政策风险，这是硬红线。

## 8. 边界条件

| 场景 | 处理要求 |
|------|----------|
| **空状态** | 学员没有任何产品想法时——提供选题清单与「从自己的问题出发」筛选框架，不能让课程在第一节就卡死 |
| **错误状态** | 学员环境配置失败——每个环境步骤配「失败自查三问」；差评显示这是最大流失点 |
| **中途放弃** | buildspace 毕业率仅 7.6%——在第 2、4 阶段设置低门槛「小胜利」交付物，降低前期流失 |
| **额度耗尽** | 学员 AI 工具免费额度用光（真实差评场景）——课程需前置说明预算，并提供低成本替代路径 |
| **工具版本漂移** | 见 AC-3，稳定层/易变层物理隔离 |
| **两类学员节奏冲突** | A 类嫌快、B 类嫌慢——B 类入口提供「跳过章节」标记，A 类提供「慢速补充包」 |
| **案例数据变化** | bookconv 数据会持续变化（可能变好也可能变差）——课程口径固定为「截至某日期的快照」并标注，不做实时承诺 |
| **权限/隐私** | 展示真实 GSC/GA4 数据时需脱敏（不暴露账号、不暴露可被恶意利用的站点弱点） |

## 10. 数据埋点方案

课程本身就是第二个 MVP，必须能验证产品假设。

| 事件类别 | 必埋事件 | 验证什么假设 |
|----------|----------|--------------|
| 获客 | `page_view`, `pricing_viewed`, `sign_up_complete` | 流量来源、定价页跳出率 |
| 激活 | `lesson_first_play`, `first_deliverable_submitted` | 学员是否真的动手（不只是看） |
| 留存 | `session_start`, `lesson_completed`, `stage_completed` | **分阶段完课率——直接验证「六阶段」骨架是否合理，哪一阶段流失最高就是内容缺陷所在** |
| 转化 | `upgrade_click`, `payment_completed`, `refund_requested` | 定价是否正确；退款率是预期管理是否到位的直接信号 |
| 差异化验证 | `growth_diagnosis_module_completed`, `security_checklist_used` | 验证「上线后诊断」是否真是学员最看重的模块 |
| 异常 | `error_occurred`, `video_playback_failed` | 播放稳定性 |

**实现要求**
- 轻量 SDK（Mixpanel / Umami / 自建 `trackEvent()` 封装），bookconv 已有 GA4 实践可复用
- 事件命名：`{对象}_{动作}`，如 `lesson_completed`、`payment_completed`
- 每事件附带 `user_id`, `timestamp`, `device`, `course_version`, `learner_track`（A 类/B 类，用于分层分析）
- 不采集隐私数据（不上报 IP、不存学员项目原始内容）

**关键北极星指标**：**阶段完课率**（不是购买数）。因为本课的核心假设是「六阶段方法论有效」，只有学员真的走完阶段才算假设成立。
