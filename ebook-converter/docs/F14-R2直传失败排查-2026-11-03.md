# F14 R2 直传失败高位排查（2026-11-03）

> 来源：待办_2026-10-31 §七 F14（CORS 修复 + E2E 验证 PASS 后，DIRECT_UPLOAD_FAILED 在 11-01 仍 8 次未归零）。
> 验收：连续 3 日 ≤2 次/日，或定位根因并修复。

## 一、链路结构（源码确认）

直传走 **浏览器 → `POST /api/upload/presign` → 拿 presigned URL → 浏览器直接 `PUT` 到 R2**（不经后端，见 `src/lib/client/direct-upload.ts`）。
`DIRECT_UPLOAD_FAILED`（及 11-02 拆分的 `PRESIGN_UNAVAILABLE`/`PRESIGN_ERROR`/`PUT_FAILED`，单一事实源 `scripts/lib/ga-error-codes.mjs`）是**前端码**，后端日志看不到——
故排查重心不在 HK 后端日志，而在：① 直传链路当前是否健康；② 失败量趋势；③ 是否 CORS 之外的系统因素。

## 二、实测（生产端点，2026-11-03 18:30 GMT+8）

| 步骤 | 方法 | 结果 |
|---|---|---|
| GET 能力探针 | `curl https://www.bookconv.com/api/upload/presign` | `enabled:true, maxMB:100`，`diagnostics` 四项全 `true`（r2Endpoint/r2AccessKeyId/r2SecretAccessKey/backendConfigured） |
| POST 取 presigned URL | `curl -X POST ... -d '{"sourceFormat":"epub","size":1024}'` | 正常返回 `uploadUrl`（R2 签名 URL，900s 有效期） |
| PUT 到 R2 | `curl -X PUT <uploadUrl>` | **HTTP 200** |

→ **presign→R2 链路在生产端到端健康**，CORS 修复确认生效（R2 桶 `ebook-temp` CORS 规则仍在）。

## 三、失败量趋势（GA4 failedByErrorCode，真实数据）

- 11-01：DIRECT_UPLOAD_FAILED **8**（占当日失败 67%）——CORS 修复（10-31）+ E2E 验证（10-31）均 PASS 后仍发生，当时根因不可知（旧码未拆分阶段）。
- 11-02：DIRECT_UPLOAD_FAILED **1** + DIRECT_UPLOAD_PUT_FAILED **2** = **3**（PUT 阶段 2 次真实失败）。

→ 趋势 **8 → 3**，下降但未达验收（≤2 次/日）。11-02 的 2 次 `PUT_FAILED` 是真实 PUT 阶段失败（非 presign），与我本次 PUT 200 对照，属**间歇性**而非系统性。

## 四、结论与红队

**结论**：直传基础设施（CORS/R2 配置/presign/PUT）经 2026-11-03 生产自检确认健康；残留 `DIRECT_UPLOAD_FAILED` 为偶发（网络抖动 / 大文件超时 / 间歇性 R2 抖动），非系统性配置故障。当前不满足"连续 3 日 ≤2 次/日"验收（11-02=3），需继续观测。

**红队攻击**
- A1（CORS 修复未真生效）：GET 探针 + PUT 200 实锤生效，推翻"修复空转"。✅
- A2（R2 配额/限流是主因）：无 R2 控制台数据；当前 PUT 200、配置全 true，不支持"配额耗尽"假设；但**不可证伪**（需 Cloudflare R2 控制台核对 11-01/02 是否有 403/限速）。保留 UNKNOWN。
- A3（前端仍误分类）：11-02 已拆分 `PUT_FAILED`(2)/`FAILED`(1)，分类正确，非误报。✅
- A4（验收是否达成）：11-02=3 > 2，**未达成**；如实登记，不标 done。✅

**裁定**：链路健康确认 + 趋势向下，遗留"连续 3 日 ≤2"未达标 + 偶发根因需 R2 控制台（用户登录）或客户端带时间戳错误日志方能闭合。
**残余/下一步（需用户侧）**
1. Cloudflare R2 控制台核对 11-01/02 是否有 PUT 403/限速/超时（闭合 A2）。
2. 若失败持续：给 `direct-upload.ts` 失败分支补**带时间戳 + 网络状态 + 文件大小**的日志（当前仅 stage-typed，无上下文），便于定位偶发根因。
3. 维持观测至"连续 3 日 ≤2 次/日"再关闭 F14。

**注意**：DIRECT_UPLOAD_FAILED 是前端码、后端日志不可见；HK 后端日志（`/opt/bookconv-conversion/`、nginx `bookconv-access.log`）对本任务无直接证据价值，未做 SSH 拉日志（避免无效动作）。
