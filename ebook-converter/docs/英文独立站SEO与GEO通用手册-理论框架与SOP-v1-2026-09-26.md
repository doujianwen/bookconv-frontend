# 第零章 手册定位与证据等级体系

## 0.1 普遍性与个例的对应关系（本书的元规则）

任何 SEO/GEO 手册都面临一个根本问题：**由谁的实践经验写成、被什么样本验证？** 由单一站点经验写成的手册，最容易犯的错误是把"一个站的病历"包装成"所有站都能吃的药方"。本手册用三层结构杜绝这个问题：

```
┌─────────────────────────────────────────────┐
│  普遍性理论层（正文）                          │
│  · 适用于任何英文独立站的原则、模型、SOP        │
│  · 依据：官方文档（最高）、行业共识（中）、      │
│    逻辑推演（须标注）                          │
├─────────────────────────────────────────────┤
│  个例验证层（📦 验证框）                       │
│  · 单一站点（bookconv.com）的实测数据与结果     │
│  · 作用：证明理论在真实环境中"可操作、有效"      │
│  · 边界：n=1，不构成通用阈值，不构成统计规律     │
├─────────────────────────────────────────────┤
│  校准方法层（嵌在 SOP 中）                     │
│  · 教读者如何在**自己的站**上把通用方法          │
│    校准成本站阈值（probe → 分布 → 设线）        │
└─────────────────────────────────────────────┘
```

**四条元规则**：

1. **正文不含个案数值**。凡出现"82.5/天""31 页""-89.8%"这类数字，必然在 📦 验证框或 📈 行内锚点内（双形态定义见第 4 条后）。
2. **个案可以证伪理论，不能推广理论**。个例验证框里若出现与正文相悖的数据，优先修订正文理论；但正文的任何"建议值"都不因一个个例成立而升级为"标准"。
3. **对外引用必须分层**。引用理论时说"行业通用做法"；引用个案数据时必须声明"单站 62 天实测，n=1"。
4. **理论验证状态三档（v1.1 增补）**。本手册的理论按验证广度分三档，采信度相应区分：
   - **官方背书级**：有搜索引擎官方文档直接支撑（§4.8 全部条目、E-E-A-T、Query Fan-out）——最可依赖；
   - **逻辑自洽级（待多站验证）**：方法论程序（probe 校准、口径纪律、归因五纪律、命中数断言）——正确性来自内部逻辑而非归纳广度，逻辑上可迁移，但**本手册的实践验证广度 = 1 个案例**；
   - **单站归纳级（仅作假设）**：从个例归纳的模式判断（如"POST 阶段是最普遍盲区"）——在新站上应当作**待验证假设**，不当规律用。

**验证标注双形态定义（v1.1 增补）**：
- **📦 验证框**：独立的成块个案数据集，附于章节内，声明 n=1；
- **📈 行内锚点**：随文出现的单点实证佐证（一句话），必须带 n=1 标记；
- 两种形态之外的正文中，**不应出现任何个案数值**（v1.0 元规则 1 只认 📦 框，与 📈 锚点自相矛盾，已修正）。

# 第一章 理论框架：双渠道模型与通用诊断方法

## 1.1 双渠道基本模型

任何英文独立站同时暴露在两个获取渠道中，二者的底层机制不同，**必须分开归因、分开度量**：

| | 传统搜索渠道（Google/Bing Web） | 生成式引擎渠道（AI Overviews/ChatGPT/Perplexity/Bing AI） |
|---|---|---|
| 机制 | 爬取 → 索引 → 排名 | 检索（Retrieved）→ 引用（Cited）→ 信任（Trusted） |
| 输出 | 10 个链接的排名列表 | 带来源标注的合成答案（平均只引 2–7 个源【行业通用，约值】） |
| 核心信号 | 关键词、外链、技术 SEO、域名权威 | 实体清晰度、内容结构、事实密度、E-E-A-T |
| 度量 | 排名、曝光、点击 | 引用频次、引用份额 |
| 失败模式 | 排名低 / 未收录 | 不在候选池 / 不被选中引用 |

**推论 1（SEO 是 GEO 的门票）**：生成式引擎的检索阶段大量复用传统搜索索引（Google AI Overviews 用 Google 索引、ChatGPT/Copilot 用 Bing 索引）。排名越高、索引越健康，进候选池概率越大。**没有健康的技术 SEO，GEO 无从谈起。**【官方 + 行业共识】

**推论 2（渠道不对称是常态）**：两个渠道的算法独立运行，同一站完全可能"Google 断崖、Bing 增长"同时发生。**这不是全站惩罚，是渠道各自独立的表现。** 诊断与修复必须按渠道分开。📈 个例验证见 §1.4 验证框。

> 📌 **二分维度澄清（v1.1）**：上表的"传统 / AI"二分是按**输出形态与优化目标**（排名席位 vs 引用席位）划分的，**不是索引归属**。AI Overviews 的索引健康归传统侧管（Googlebot / 索引 / GSC 纳入），展示表现归 AI 侧度量——优化动作同源（§4.8），归因时按展示形态分开度量。

## 1.2 通用诊断模型：四类故障

任何"流量异常"，先穷举到以下四类故障，再逐类取证：

| 故障类型 | 机判特征（看什么） | 典型原因 |
|---------|-----------------|---------|
| **A 覆盖坍塌**（页面不被收录/展示） | **活跃 page 数暴跌 + 加权排名持平** | spam update、程序化内容同质化、lastmod 异常、索引被回收；**技术性子因（新手最常见，修复成本小时级）：robots 误挡 / 全站 noindex / 服务器 5xx / 抓取配额耗尽** |
| **B 排名惩罚** | **加权平均排名下滑 + 活跃 page 数稳定** | 算法针对性降权、链接惩罚 |
| **C 权威不足** | 排名长期卡在 30–80 名，页面优化已到位 | 外链/域名权威积累不足、品牌认知低 |
| **D 内容同质**（Scaled Content 嫌疑） | 大量模板页结构雷同、信息增量低 | 程序化批量生成、AI 批量产出无差异化 |

**诊断纪律**：

1. 🔴 **A 与 B 是互斥诊断**：加权 position 持平 + 活跃 page 暴跌 = 覆盖坍塌（A），不是排名惩罚（B）。两者修复路径完全不同（A 修内容/索引，B 等算法+申诉评估）。**排查次序：先技术后内容**——先排除 robots / noindex / 5xx / 抓取异常（小时级可修），再动内容层（周级工程）。
2. 🔴 **区分"内容问题"与"权威问题"**：页面优化天花板约到位置 30–40【行业通用】，位置 60–80 的词是权威问题，继续堆页面优化无效，必须靠外链。
3. 🔴 **算法性打击无人工申诉通道**：Google 的 Reconsideration Request **仅适用于 Manual Actions（人工处置）**。对 spam update 这类**算法性**打击，正确动作 = 修复可修复的内因 + 等待算法刷新 + 记录恢复时间线。（先查 GSC 是否有 Manual Action，再决定走哪条路。）
4. 🔴 **先修可修复的内因，再谈不可控的外因**。算法更新是外因，内容同质化是内因——内因是唯一可操作的杠杆。

## 1.3 程序化内容站的高危结构（Scaled Content Abuse）

模板批量生成的页面（convert 页、城市页、规格页等）是新站最常见的 spam 打击目标。通用的风险判据：

| 检查维度 | 低风险 | 高风险 |
|---------|--------|--------|
| **文本相似度**（词汇层） | 页与页相似度 <20% | 高度重复的文案复用 |
| **结构同质度**（骨架层） | 同模板但章节因页而异、信息增量真实 | 同一套 heading 模板 + 同一段 boilerplate，仅替换变量 |
| **信息增量** | 每页有该页独有的数据/场景/判断 | 换个词无新信息 |
| **规模 vs 权威** | 内容规模与站点权威匹配 | 新站 + 数百个薄模板页 |

> 🔴 **两种相似度必须分开检验**：全文文本相似度低 ≠ 没有结构同质问题。Google 的 Scaled Content 判据更接近**结构/骨架同质 + 信息增量**。一个站完全可能"文本不重复但骨架千篇一律"——这不矛盾，且是程序化站最隐蔽的风险形态。
> 🔴 **勿为 AI 刻意分块**【官方】：Google 官方明确"没必要为了让 AI 更好理解而把内容拆得支离破碎"。结构化是内容质量手段，不是碎片化理由。

## 1.4 个例验证：一次完整的"覆盖坍塌"诊断

> 📦 **以下为 bookconv.com 个案数据（n=1），仅验证 §1.1–§1.3 理论，不构成通用阈值。**

- **验证"渠道不对称是常态"**：2026-08-21→08-22 该站 Google 展示断崖（高位期日均 157.4 → 低位期 23.2，事件窗口 14v14 口径 2,123→217，−89.8%），同期 Bing AI 引用却持续增长（9 月日均引用达近 7 天 289.3，VI +58.8%）。21 个双渠道交集页加权排名 **Bing 5.7 vs Google 56.7**——同一批内容在两个渠道表现天差地别，证实"Google 单方面重排，非内容质量问题"。
- **验证"A/B 互斥诊断"**：断崖期该站加权 position 68→64（持平），但活跃 page 14→3（−81%）→ 判定覆盖坍塌（A），非排名惩罚（B）。修复方向随之确定：不做申诉、修内容内因。
- **验证"程序化页高危结构"**：52 个程序化页（30 convert + 22 guide）平均仅 4–6 个 headings、About 章节重复率 22%——**文本相似度实测仅 16.2%（证伪"全文克隆"），但结构同质指控成立**。断崖时间对齐 Google 2026-08-18 spam update，促成归因收敛：外因（算法）× 内因（结构同质）叠加。
- **验证"基线纪律"**：该站曾把爬坡顶点 157.4 误当"基线"得出 −85% 叙事——爬坡期的正确基线是曲线本身，顶点不是基线。此教训已上升为 §6.3 报告红线（"不裁剪基线造叙事"）。

# 第二章 关键词策略与内容架构 SOP

## 2.1 用户画像 SOP（数据交叉验证法）

**通用方法**：用户画像必须由三类独立数据交叉验证得出，禁止拍脑袋或纯靠 AI 生成：

```
画像 = GSC 关键词分布（用户实际搜什么）
     × 设备/地域分布（用户从哪来）
     × 产品功能边界（你能服务什么）
三者交集，才是可服务的真实细分。
```

每个细分产出四要素：**核心场景 → 入口关键词 → 对应内容类型 → 优先级**。优先级判据：意图明确度 × 流量规模 × 与产品功能契合度。

## 2.2 关键词四层分层模型【行业通用】

```
第 1 层  钱页词（Money Keywords）    —— 交易/对比意图，直接对应转化页
         目标：进前 30（靠外链 + 内链集权）

第 2 层  支柱词（Pillar Keywords）  —— 信息意图，对应支柱指南页
         目标：进前 20（靠内容深度 + 内链枢纽）

第 3 层  长尾/场景词（Long-tail）   —— 问答式，对应博客与 FAQ
         目标：被 AI 引用 + 长尾展示

第 4 层  品牌词（Brand）            —— 站点品牌名
         目标：守住 + 提升 CTR
```

**分层纪律**：
- 第 1 层用**外链深链**打；第 2 层用**内容深度 + 内链枢纽**打；第 3 层用**FAQ/结构化**打。
- 🔴 **不要用第 4 层的指标（品牌词 CTR）去证明第 1 层的成功**——各层 KPI 独立。

## 2.3 意图 → 内容映射方法【方法论】

为每个目标关键词建立一行映射：`意图 → 目标页 → 当前状态 → 动作 → 优先级`。

| 意图类型 | 判定特征 | 对应页面类型 | 内容结构 |
|---------|---------|------------|---------|
| 交易型 | `convert X to Y` / `X to Y converter` | 工具转化页 | 工具 + 步骤 + 对比表 + FAQ |
| 对比型 | `X vs Y` / `which is better` | 对比指南页 | 对比表 + 场景推荐 + Bottom Line |
| 信息型 | `how to` / `what is` | 博客 | 定义块 + 步骤 + Key Takeaways + FAQ |
| 决策型 | `best X` / `X alternative` | 决策指南页 | 工具对比表 + Pros/Cons + 定价 |

> 🔴 **映射表的数据必须实测**：AI 生成的意图规划稿常见三类幻觉——URL 结构错误、流量数字为推测、竞品数据"模拟推演"。使用前必须与 sitemap、GSC 实测交叉核对。

## 2.4 关键词选择标准与"新站判据切换"

**理想门槛**【行业通用】：搜索量 >100/月（US）、KD <60（新站 <40）、意图单一、商业价值匹配、内容契合。

🔴 **新站判据切换（通用方法论）**：新站没有 Ahrefs/KD 级别的数据可用，且其赢家词往往远低于任何搜索量门槛。**新站应以 GSC 实测曝光分布为主判据**：找出本站已有曝光的关键词簇，把资源集中到"已被 Google 注意到的词"上。

> ⚠️ **冷启动分层判据（v1.1 增补）**：上线 0–4 周 GSC 曝光≈0，主判据无数据可用——此阶段退回【行业通用】理想门槛 + 竞品缺口分析选词；GSC 出现稳定曝光分布（建议 ≥4 周数据）后切换为实测主判据。**判据切换是时间函数，不是二选一。**📈 个例锚点：验证案例自己前 3 周日均展示仅个位数起步（n=1）。

**推论（建新页 vs 优化老页）**：新站的常见陷阱是继续铺新页。**先算 ROI**：如果所有缺口词的合计曝光 < 单个现有赢家簇的曝光，则 P0 = 深化钱页 + 外链主攻，而非继续扩页。📈 个例验证：bookconv 全部缺口词合计仅 10 曝光，而单个 `mobi→epub` 簇 61 曝光（占 47%）——结论：停铺新页，转深耕。

## 2.5 内容结构规范【行业通用 + 方法论】

### 2.5.1 Title / Description

| 元素 | 规范 | 说明 |
|------|------|------|
| Title 长度 | ≤55 字符 | 主流 SERP 展示宽度约束【行业通用】；品牌名由全局模板追加 |
| Description 长度 | ≤155 字符 | — |
| Title 结构 | `[主关键词前置] + [差异化钩子]` | per-page title **不自带品牌后缀**（防与全局模板叠加成双品牌） |
| 摩擦词 | 工具页必带 `Free` / `No Sign-up` / `Instant` / `Safe` | 低 CTR 期的优化抓手 |

### 2.5.2 正文结构

```
H1（唯一，与 title 对应）
├── 定义/直答块（前 100 词内回答核心问题）  ← GEO 关键（Answer-first）
├── H2 主章节（每节 ≥1 个数据点）
│   └── H3 子章节（按需）
├── H2 Key Takeaways（3–6 条可引用要点）   ← GEO 关键
├── H2 FAQ（5–7 条 PAA 句式）              ← GEO 关键
└── H2 结论（复述关键词 + CTA）
```

**字数基准**【行业通用，仅作起点，须按 §4.6 probe 校准】：How-to 800–2,500；工具对比 ≥1,500；格式说明/对比 ≥500；深内容转化页 800–1,300。

### 2.5.3 内链规范

- ≥2 条**高质量**内链（质量优先于数量——机械凑数的第三条不如不要）。
- 质量定义：反向格式互链、相关支柱页、相关百科页。
- **枢纽策略**：首页/导航页作内链枢纽；博客向支柱页集权（pillar 策略）。
- 锚文本描述性，禁用 "click here"。
- 🔴 **防孤岛**：任何新页必须确认有入链。

### 2.5.4 E-E-A-T 信号清单

```
[ ] 作者署名 + credentials
[ ] lastVerified / lastUpdated 日期
[ ] 3–5 条权威外链（.gov / .edu / 行业权威）
[ ] 数据点标注来源与年份
[ ] 联系方式可触达（邮箱 / 社媒 / 实体页）
```

## 2.6 内容生产 7 阶段 SOP【方法论】

```
Phase 1  研究   关键词验证 → 竞品 Top3 分析 → 意图确认 → PAA 挖掘 → 3+ 权威来源 → 内链机会
Phase 2  大纲   独特角度 → H2/H3 结构 → Key Takeaways 规划 → FAQ 规划 → 目标词数
Phase 3  初稿   引言（钩子+路线图）→ 正文 → Key Takeaways → FAQ → 结论 → 内外链 → 作者块
Phase 4  SEO    关键词入前 100 词 → 优化 H2/H3 → LSI 词 → 图片 alt → title/desc → Schema
Phase 5  去 AI  删除 AI 词汇 → 变化句长段长 → 列表转散文 → 加缩写/破折号 → 朗读检查
Phase 6  终审   技术 SEO 清单 → E-E-A-T 清单 → GEO 清单 → Schema 校验 → 人工复核
Phase 7  发布   发布 → 提交 GSC → 建内链 → 1 周查索引 → 2–4 周查排名
```

**去 AI 化词表（必删）**：`leverage / utilize / delve into / landscape / realm / facilitate / robust / comprehensive / cutting-edge / game-changer / navigate / in today's world / it is important to note / needless to say`。

**内容增量同步规则（强制）**：新增/删除任何可索引页后，必须同步 4 处，缺一不可：

| # | 位置 | 动作 |
|---|------|------|
| 1 | 内容注册表/数据源 index | 新增注册 |
| 2 | sitemap | 验证条数 |
| 3 | `llms.txt`（如维护） | 手动补条目 ⚠️ 最易漏 |
| 4 | 内链/相关文章 | 确认非孤岛 |

**三数一致校验（通用命令模板）**：
```bash
curl -s 站点/sitemap.xml | grep -oE '/blog/[a-z0-9-]+</loc>' | sort -u | wc -l
curl -s 站点/llms.txt   | grep -oE '/blog/[a-z0-9-]+'       | sort -u | wc -l
curl -s 站点/blog | grep -oE 'href="/blog/[a-z0-9-]+"' | sort -u | wc -l
```

> ⚠️ 模板中 `/blog/` 为**示例路径**——替换为你站点的实际内容路径模式（`/guides/`、`/tools/`、`/resources/` 等），三处使用同一模式。

## 2.7 漏斗阶段内容覆盖审计法【方法论】

按 TOFU（认知）→ MOFU（考虑）→ BOFU（决策）→ **POST（售后）** 四阶段盘点内容覆盖率。**POST 阶段（帮助/排查/售后内容）是新站最普遍的盲区**——工具站尤其如此：用户搜"转换失败怎么办"时无页可承接，这些既是转化保护层也是长尾词来源。

📦 **个例验证**：bookconv 审计发现 TOFU 90% / MOFU 80% / BOFU 60% / **POST 仅 20%**——无 /help 聚合页、无失败排查指南。POST 缺口被列为 P0 内容缺口。

# 第三章 技术 SEO 通用 SOP

## 3.1 索引与抓取清单

- [ ] `robots.txt` 正确放行：不屏蔽静态资源；`sitemap.xml` / `robots.txt` / `rss.xml` 不被中间件/路由层拦截。
- [ ] `robots.txt` 放行目标 AI 爬虫（GPTBot / ClaudeBot / CCBot / PerplexityBot / Google-Extended 等）——⚠️ 注意：此清单针对**非 Google 的 AI 引擎**。Google 搜索内的 AI Overviews / AI Mode 依赖**既有 Googlebot + 搜索索引**，不需要单独放行"AI bot"（详见 §4.8）。
- [ ] 🔴 **GSC 纳入"生成式 AI 搜索功能"**【官方】：在 Search Console 启用生成式 AI 报告与展示资格——这是进入 Google AI Overviews/AI Mode 候选池的官方硬性前提之一，**页面已索引 ≠ 自动进入 AI 候选池**。
- [ ] `sitemap.xml` 由数据源自动派生，条数与内容注册表一致。
- [ ] 🔴 **sitemap lastmod 禁用 `new Date()` 类动态值**：每次构建都变化的 lastmod = 抓取提示失效（Google 会忽略不可信的 lastmod）。用内容真实的更新时间。
- [ ] 🔴 **spam 恢复期不批量 bump lastmod**：bump = 主动请求全站重抓，可能放大问题；文案纠错不动 lastmod。
- [ ] 未知 URL 返**真 404**（`notFound()` + 关闭兜底参数），不留 HTTP 200 软 404。

## 3.2 Canonical / hreflang / 多语言

- [ ] canonical 使用相对根路径逻辑，**绝不硬编码某个语言前缀**（多语言站经典泄漏源：中间件 rewrite 后语言检测返回默认值，canonical 泄漏成带前缀 URL，而该前缀 URL 又 301）。
- [ ] hreflang 三件套：`en` / 其他语言 / `x-default`；注意 Next.js 序列化为 `hrefLang`（大小写兼容校验）。
- [ ] 🔴 **hreflang 必须全路由覆盖**：根路由（不走 locale layout 的页面）单独设置。
- [ ] 🔴 **多语言上线前必须验证目标语种真的有对应查询**【方法论】：多语言版承接的查询 100% 是英语 = 语言错配内耗（抢主语言曝光、稀释权重），应暂缓或收缩。

## 3.3 结构化数据（Schema）

| 页面类型 | 常用 Schema |
|---------|------------|
| 工具/转化页 | `SoftwareApplication` + `Offer` + `HowTo` + `FAQPage` + `BreadcrumbList` |
| 博客 | `Article` + `FAQPage` |
| 指南 | `Article` / `HowTo` + `FAQPage` |
| 全局 | `Organization` + `WebSite` |

**真实性红线**【方法论，通用信任原则】：
- 🔴 FAQ Schema 从**结构化字段**生成，不从散文 "Q:/A:" 抽取；渲染只从一个来源取（防页面重复渲染两遍）；JSON-LD 内答案用纯文本。
- 🔴 **不编造 `sameAs` 社媒链接**——没有就留空 `[]`。
- 🔴 **不编造 `AggregateRating` / `Review`**——虚假评分伤信任且有法律风险。
- ⚠️ **Schema 的正确定位**【官方】：帮助富媒体搜索结果 + 对部分 AI 引擎的抽取更可靠；但 **Google 官方明确"生成式 AI 搜索不需要结构化数据"**——Schema 不是 Google AI 可见性前提（§4.8）。

## 3.4 程序化内容站专项 SOP

1. **上线前**：先评估"页数 × 差异化能力"，页数上限 = 你能保证每页真实信息增量的上限。
2. **每页强制差异化章节**：同模板页必须有因页而异的章节（该页独有场景、独有数据、独有判断）。
3. **首发行 probe**：对全站模板页统计 headings 数、字数分布、章节重复率，低于分布下限的页批量补强。
4. **结构同质自检**：抽样两两比对 heading 序列，boilerplate 章节占比过高即触发改造。
5. **规模纪律**：新站不要一次发布数百个薄模板页；分批发布 + 每批有质量门禁。

## 3.5 部署验证与 CI 门禁（通用原则）

- 🔴 **"站点能打开" ≠ "部署成功"**：部分托管平台（如 Vercel【个案实测】）构建失败时**静默继续服务上一版本**，其他平台行为各异（有的直接 5xx、有的自动回滚）。铁律与平台无关：push 后 ①全仓语法 parse ②跑门禁 ③**线上断言新内容真的出现**。
- 🔴 **门禁顺序**：语法全扫最先跑（语法错 → build 失败 → 部署冻结）；之后跑内容完整性、声明一致性、GEO 合规、重复标题、类型检查。
- 🔴 **判死链必须读重定向表**：canonical slug ≠ 数据层 key 的站，肉眼查 URL 会误报死链。
- 🔴 **批量脚本只允许"替换/定点更新"，禁止"追加整块"**；批量注入前先查同名/近同名标题；EOL（LF/CRLF）逐文件探测并保留。

## 3.6 数据口径纪律【方法论，全站通用】

- 🔴 **"日均"必须标分母**（近 7 天/近 30 天/全期），无分母的日均 = 不可引用。
- 🔴 **同指标多口径时先立权威口径**，其余口径标注指向权威口径，禁止并存两个"权威值"。
- 🔴 **`snapshot_date` ≠ 实际截止日**：导出文件的标注日期与数据实际覆盖日可能差 2–4 天，引用前必核窗口。
- 🔴 **GSC 三报告 impressions 互不自洽是常态**（日期=设备自洽 > 页面 > 查询）：**只有日期维度可作权威基准**；Top query ≠ 全量词库。
- 🔴 **小样本百分比方向不稳定**：n≈10 的窗口平移 1 天，+6.5% 可翻成 −13.2%。小样本只作方向参考。

# 第四章 GEO 理论框架与落地 SOP

## 4.1 GEO 定义与 SEO 的关系

**GEO（Generative Engine Optimization）= 让内容被 AI 引擎（AI Overviews / ChatGPT / Gemini / Perplexity / Copilot / Claude）发现、引用、复述。**

| 维度 | SEO | GEO |
|------|-----|-----|
| 目标 | 争搜索结果里的**排名位置** | 争 AI 摘要里**被引用的席位** |
| 输出 | 10 个链接的排名列表 | 带来源标注的合成答案（平均引 2–7 个源【行业通用，约值】） |
| 核心信号 | 关键词、外链、TDK、域名权重 | 实体清晰度、内容结构、事实密度、E-E-A-T、全网事实一致性 |
| 度量 | 排名、点击 | 引用频次、引用份额（Share of Voice） |
| 内容策略 | 围绕关键词创作 | 围绕问题与子查询（Query Fan-out）创作 |
| 权威来源 | 外链（Backlinks） | 提及与共引（Mentions & Co-citations） |

> **一句话**：SEO 争排名，GEO 争引用。AI 平均只引 2–7 个源，不在里面 = 完全不可见。
> ⚠️ 官方校准（§4.8）：对 Google 生成式 AI，上表"结构化数据"**不是前提**；结构化数据的价值在富媒体结果与部分非 Google 引擎。

## 4.2 管道模型：Retrieved → Cited → Trusted

```
阶段 1  Retrieved（被检索）  —— 进入 AI 候选池
        · 传统 SEO 基础仍是门票（索引健康 + 排名越高进池概率越大）【官方印证】
        · Google 渠道硬前提：已索引 + 符合摘要条件 + GSC 纳入生成式 AI 功能
        · 元数据完整（title / description / 结构化数据）

阶段 2  Cited（被引用）      —— 从候选池被选中
        · 事实密度 > 字数长度
        · 可引用格式：清晰小标题、定义型段落、FAQ、Key Takeaways
        · 权威信号：第三方引用、共引、E-E-A-T 显性标注

阶段 3  Trusted（被信任）    —— 用户点击/信任
        · 推荐上下文质量（品牌在正确场景被提及）
        · 品牌在多来源中描述一致（全网事实一致性）
```

> **关键认知**：这是**概率性系统**，同一问题每次可能引用不同来源。目标是"在长期中持续被引用"，不是追逐单次位置。AI 引用量月度波动幅度大（数十个百分点的常态波动属正常）【行业说法，未溯源，仅作预期管理用，勿当精确区间】。

## 4.3 六大核心原则

### 原则 1：优化实体，而非关键词
AI 有"三道脑"：LLM 聊天脑 + 搜索索引脑 + **知识图谱脑**（事实核查用）。实体信息不清晰 → 不被引用或被错误引用。落地：建 Entity Home（About 页声明"你是谁/做什么"）+ 全网事实一致性 + 页面内可见的实体关系。

### 原则 2：可见内容结构 > 隐藏的 JSON-LD
供应商实验【行业研究，证据等级有限】表明单纯嵌入 Schema JSON-LD 对 AI 检索提升有限；真正起作用的是**可见页面内容**里的 H1–H6、列表、表格、FAQ 区块。Schema 是基础不是银弹。（实战佐证见验证框：AI 助手可能"看不到"已有 JSON-LD 而建议"补 Schema"——先核实再动手，勿重复注入破坏已有 schema。）

### 原则 3：答案前置（Answer-first）
开篇 200 字内直接回答核心问题，为 AI 提供可即时提取的"摘要块"。段落 ≤200 字，清晰的 Topic Sentence。

### 原则 4：Query Fan-out —— 建主题集群，不建孤立页
AI 把复杂问题拆成多个子查询分别检索后合成【官方机制描述一致】。内容必须覆盖所有子查询 → 建**主题集群**（pillar + cluster）。

### 原则 5：事实密度 > 字数
可引用句 = **具体数字 + 命名来源 + 年份**。
```
✅ QUOTABLE: "Third-party testing found X achieved 90–95%, compared to 70–80% for Y."
❌ NOT:      "X is a popular choice."
```

### 原则 6：E-E-A-T 内容质量标准【官方框架】
Experience（第一手真实经验）/ Expertise（专业深度）/ Authoritativeness（权威背书）/ Trustworthiness（可信度）。Google 官方 AI 优化指南特别强调：**非同质化内容 + 第一手评价**（"基于个人亲身经历提供独特视角"）是生成式 AI 展示的核心内容信号。
（注：内部管理可用扩展维度如 Data 可信数据、Authority Proof 可验证证据，但对外统一说 E-E-A-T。）

### 各 AI 引擎来源偏好（渠道选择参考）【行业通用】

| AI 平台 | 主要数据来源 | 内容策略重点 |
|---------|------------|------------|
| ChatGPT | Web + **Bing 索引** | 域名权威 + 结构化数据 |
| Google Gemini / AI Overviews | Google 索引 | 强 SEO 基础 + 第一方高质量内容 |
| Perplexity | 搜索优先 + embedding 筛选 | 引用标注 + 数据来源清晰 |
| Copilot / Bing AI | Bing 索引 | Bing SEO + 第三方覆盖 |

**渠道选择方法**：先测后投——用 2–4 周记录各引擎对目标查询的引用构成，选择"自己能赢的池子"集中投入，而非平均用力。

## 4.4 GEO 资产 SOP

### 4.4.1 `llms.txt`（低成本对冲资产，非引用杠杆）【官方定调】

> 🔴 **定位红线（官方逐字）**：Google《AI Optimization Guide 2026》——"您无需为了在 Google 搜索（包括其生成式 AI 功能）中占有一席之地，而专门创建新的机器可读文件……**Google 搜索本身并不使用这些文件或标记**……**Google 搜索会忽略这些文件**。" 对 **Google 渠道 llms.txt 完全无效**。
> 2026 年实测数据【行业信源】：AI bot 访问中仅 ≈0.1% 请求 llms.txt；97% 的 llms.txt 从未被 AI 爬虫读取；无任何证据表明它影响 AI 引用。

**仍可维护的三个次要价值**（成本≈0）：① 与 sitemap/注册表的三数一致强制校验，防"新增页忘同步"事故；② 编写过程 = 一次内容审计（暴露孤岛页）；③ 对冲未来 agent 标准化的期权（当前真实使用方是编码 Agent 读开发者文档）。

**格式要点**：全覆盖（每个可索引页都列，不只首页）；绝对 URL；描述带差异点；含"关于/隐私/信任"段；静态文件须手动同步且 CI 必检三数一致。
**对外红线**：❌ 禁止把 llms.txt 列为"GEO 引用杠杆"或"AI 可见性措施"。

### 4.4.2 `robots.txt` 放行 AI 爬虫（针对非 Google 引擎）

确认目标引擎 UA 未被 Disallow（GPTBot / ClaudeBot / CCBot / PerplexityBot / Google-Extended 等），`curl 站点/robots.txt | grep -i gptbot` 验证。**再次强调**：这只影响非 Google 引擎的抓取；Google AI Overviews 走 Googlebot（§4.8）。`Google-Extended` 是服务 Gemini API/Vertex AI 应用层的独立爬虫，与 Search 内 AI Overviews 无关。

### 4.4.3 实体结构化数据

全局 JSON-LD：`Organization`（`areaServed` / `availableLanguage`）+ `WebSite`（`inLanguage`）。不编造 `sameAs`。

### 4.4.4 FAQ 结构化 → `FAQPage` JSON-LD

价值定位【官方校准】：① 帮助 Google 富媒体结果；② 对 Bing AI/其他引擎的问答抽取更可靠（结构化字段远比散文可靠）。**不是 Google 生成式 AI 可见性前提**。工程要求：结构化字段生成、单来源渲染、纯文本答案。

### 4.4.5 Key Takeaways + 可引用句

每篇 3–6 条要点，每条带具体数字/百分比，可独立成立；正文刻意埋"可引用句"（数字+来源+年份）。

## 4.5 页面级 GEO 质量评估框架【方法论】

对每类页面定义**要素清单 + 0–N 评分制 + PASS/WARN/FAIL 线**，接入 CI 门禁。通用模板：

```
要素维度（按页面类型取舍）：
  结构（headings 下限）/ 直答块 / Key Takeaways / FAQ（条数下限）
  / HowTo 步骤 / 对比表 / 质量清单 / 作者署名 / 内链 / 字数

评分 = 各要素 0–1 分加权
PASS（可发布）: score ≥ 及格线
WARN/FAIL（阻断部署）: 低于及格线 → exit 1（CI 拦截）
```

> ⚠️ **无 CI 的站点（v1.1 增补）**：等价形态 = 发布前人工过一遍评分清单，WARN/FAIL 同样拦截发布动作——门禁拦截的是"发布"，不是"部署工具"。

🔴 **阈值校准程序（先 probe 再设线，禁止拍脑袋）**：
1. 对全站该类型页面统计各要素**真实分布**（min/median/max）；
2. TARGET 取分布上四分位附近、WARN 取中位数附近、MIN 取下四分位附近；
3. 若现有页面**全部**低于预设线 → 说明线设错了（脱离现实），不是页面全错。
📈 **个例验证**：bookconv 曾预设"convert 页 ≥2000 词"，实测 31 页最高仅 1287 词 → 所有页误判 FAIL，门禁形同虚设。重新按分布校准（TARGET 1000 / WARN 600 / MIN_HEADINGS 8 等）后门禁才有效。**这些数值是该校准程序的输出，不是可移植的标准。**

## 4.6 GEO 落地 SOP（按 ROI 排序）【方法论】

```
①  技术 SEO 地基（可索引 + 不挡爬虫 + GSC 纳入生成式 AI）—— Google 渠道前提
②  robots.txt 放行目标 AI 爬虫 —— 非 Google 引擎前提
③  实体建设：Entity Home（About）+ Organization/WebSite Schema + 全网事实一致
④  内容结构：直答块 + Key Takeaways + 可引用句（数字+来源+年份）
⑤  结构化 FAQ 字段 + FAQPage JSON-LD（富结果 + 非 Google 引擎抽取）
⑥  主题集群覆盖 Query Fan-out 子查询
⑦  渠道聚焦：实测选定主力 AI 渠道集中投入
⑧  新增页后同步 llms.txt + 三数一致校验
⑨  部署后线上断言（等生效时间再 curl）
```

## 4.7 GEO 效果度量（KPI 体系）【方法论】

| KPI | 定义 | 工具/方法 |
|-----|------|----------|
| Citation Frequency | 品牌/页面在 AI 回答中被引用次数 | Bing WMT AI Performance 等 |
| Mention Share | 特定关键词 AI 回答中的提及占比 | 定期查询统计 |
| Recommendation Context | 被提及的语境（正/中/负） | 人工逐条分析 |
| Share of Voice | 与竞品横向占比 | 品牌监测工具 |
| Conversion from AI traffic | AI 引荐流量转化率 | GA4 / UTM |

> 🔴 **Citation Share 的分母 = 该 AI 回答的全部引用席位**（非全站），对外必须写清分母。
> 🔴 **引用 ≠ 流量（最重要的一条对外纪律）**：AI 引用是**可见性指标**，不是流量指标。引用量落到实际会话的转化率可以低到千分之一以下量级。📈 个例验证：bookconv 累计 9,012 次 Bing AI 引用，GA4 `bing/organic` 全期仅 2 个会话。对外材料禁止把引用数当流量承诺。

# 第五章 优先级判定与资源分配通用框架

## 5.1 优先级公式与判定纪律【方法论】

```
优先级 = 影响面 × 可修复性 ÷ 成本

P0  影响面大 + 立即可做 + 成本可控   → 本周做
P1  影响面大 + 需 1–2 周            → 本月做
P2  影响面中 + 长期                 → 排期做
P3  观察项 / 依赖前置条件           → 挂起，设复评估锚点
```

**四条判定纪律**：
1. 🔴 **先修可修复的内因，再谈不可控的外因**（§1.2 诊断纪律的优先级表达）。
2. 🔴 **技术 SEO 正常时，不追加技术投入**——此时低表现 = 排名竞争/权威问题，追加技术 SEO 是浪费。先跑诊断模型定性，再决定投入方向。
3. 🔴 **区分"内容问题"与"权威问题"**（§1.2）：决定是"写更多/更好的页"还是"建更多深链"。
4. 🔴 **发现"声明 ≠ 实现"先按法律权重排序**：要约（定价页）> 宣传 > 科普 > 文档。只改低权重面会制造"已处理"的假象——修复要么改声明、要么改实现，必须对着最高法律权重的那一面收口。

## 5.2 四阶段路线图模板【方法论】

| 阶段 | 主题 | 典型任务 |
|------|------|---------|
| Phase 0 地基 | 上线前 | 规范域/canonical/hreflang、sitemap 派生、Schema 全覆盖、llms.txt + bot 放行、CI 门禁、GSC/Bing WMT/GA4 接入、GSC 纳入生成式 AI |
| Phase 1 止跌与差异化 | 第 1–6 周 | 程序化页差异化改造（Tier-1 高价值页优先）、暗页复核、算法性打击的"修内因+等刷新" |
| Phase 2 内容深化与放大 | 第 2–4 周 | 转化页 Title 场景词、内链枢纽、引用大户 FAQ 强化、metaDescription 补齐 |
| Phase 3 外链与站外权威 | 第 3–8 周 | 内页深链（区分首页链/深链，只有深链计入内页 KPI）、六大战术（垂直编辑站 outreach / 死链替换 / 内容平台 / 社区 / GitHub / 未链提及转化）、锚文本分布控制 |
| Phase 4 缺口填补与长期资产 | 第 2–3 月 | POST 阶段内容（/help、排查指南）、漏斗缺口项、渠道重评估、多语言扩展（先验证语种查询） |

**外链通用纪律**：白帽红线（不买链/不群发/PBN/链接农场）；锚文本分布【行业通用】exact-match ≤15%、部分匹配 25–35%、品牌 20–30%、裸 URL 15–25%、泛词 10–15%；**验收口径 = 生效 1–3 月看月度斜率，勿用周排名衡量**；目录/发布站只给根域链接，对内页权重提升极有限。

## 5.3 验收与预期管理【方法论】

- 验收标准设**方向性验收**（趋势斜率），不设单点绝对值。
- 🔴 **算法性 spam 打击的恢复周期以月计**（行业经验 1–3 个月起）：内容修复后需等待下一次算法运行。30 天验收不达标 ≠ 修复无效。
- 评估看**主题簇总量**而非单页读数（单页小样本不稳定）。
- 每个挂起项设**复评估锚点日期**，到期强制决策（继续/放弃），防止"无限观察"。

## 5.4 资源分配框架【方法论】

多渠道站点的资源分配原则：
1. **修复性投入 vs 扩张性投入分开决策**——修复存量问题（如清除 spam 嫌疑）与新建增长线（如场景词新页）是两类决策，预算分开算，勿用"修复"挤占"扩张"，也勿因"扩张线已放弃"而停止"修复"。
2. **按"实测可赢性"分配**：同一对象在两渠道的表现检验（交集页对比法，§6.3）是最强的分配依据——同一批内容在 A 渠道排名 5、在 B 渠道排名 50+，说明差距在渠道侧而非内容侧。
3. **每一档分配配一个重评估锚点**（如 30 天后强制复盘）。

# 第六章 度量体系、数据纪律与归因方法

## 6.1 三层指标体系【方法论】

| 层 | 频率 | 指标 |
|----|------|------|
| **结果指标**（Outcome） | 月 | 自然点击/展示（GSC 日期维度）、AI 引用量、品牌词 CTR |
| **诊断指标**（Diagnostic） | 周 | 活跃 page 数（**去索引预警铁证**）、加权平均排名（区分排名惩罚 vs 覆盖坍塌）、暗页率、GEO 合规率、索引覆盖率 |
| **过程指标**（Process） | 日/每次发布 | 门禁通过率、内链数/页、外链新增数与类型、锚文本分布 |

## 6.2 变化率统一方法：可见性指数（VI）【方法论】

**公式（固定窗口，禁随意改窗口）**：
```
VI = (近 7 天均值 − 前 7 天均值) / 前 7 天均值 × 100%
```

**判定门槛与适用条件**：
- <10% 无信号；10–20% 弱信号；≥20% 成立——**但 ≥20% 阈值只适用 n>400 量级**；小 n 须泊松区间检验，否则是范畴错误。
- 🔴 **VI（7v7）与事件窗口（如 14v14）是两套数，禁互引**；VI 跨轮不可比（窗口不同）。
- 🔴 **VI 适用边界——除零/近零（v1.1 增补）**：分母窗口（前 7 天）均值低于最小样本量（建议 <30/周）时 **VI 不可计算**——新站冷启动期、断崖后归零的渠道、低频长尾词均命中此场景。此时改用**绝对量对比 + 泊松区间检验**，禁止硬算 VI 得出 ±数百百分比的垃圾数字。
- 📈 个例验证：bookconv 的 Google VI −13.2%（8.4 vs 9.7，n≈60–70）不满足 n>400 → 只能作方向参考不作判定；Bing AI VI +58.8%（n≈2000）满足门槛可判定。

**"渠道背离"严格三条件（同时满足才可称"背离"）**：① 符号相反；② 双方均 ≥20%（且满足 n 门槛）；③ 末日相差 ≤3 天。不满足时只能说"**不对称**"——术语纪律防止叙事先行。

## 6.3 归因五纪律【方法论】

1. 🔴 **跨渠道对比先做"同一对象在两边表现"检验**再聚合（交集页对比法）。
2. 🔴 **限流/采样砍范围后的比例结论必须全集重算**；对照组须类型匹配。
3. 🔴 **维度决定结论** ⇒ 归因先穷举维度（page/query/country/device）。
4. 🔴 **API 字段语义先反例证伪再当判据**；返回 0 行 ≠ 字段为 0。
5. 🔴 **未实测不写进对外材料**；个案数据必须标 n=1。

**报告红线**：
- ❌ 不用 UI 目视数据 vs CSV 导出数据对比
- ❌ 不跨窗口对比（分母漂移）
- ❌ 不用 n=3 分桶宣布"加速"（至少 7 天）
- ❌ 不把假设当规律（"⚠️ 待验"标记）
- ❌ **不裁剪基线造叙事**（爬坡顶点不是基线）

## 6.4 头号失败模式与唯一防线【方法论】

**自动化工具链的头号失败模式 = 静默假成功**：
- 编辑工具报 success 但实际没改（多行匹配静默失配）
- 门禁脚本扫 0 个文件报 0 错误（"通过"是假象）
- 批量注入落到目标区间之外（语法错/内容丢失）
- 验证依赖缓存，读到旧数据

**唯一防线 = 命中数断言 + 事后独立复核**：每次批量操作必须断言"改了多少处"（命中数 >0 且 = 预期）；改完后用独立路径（curl 线上、换工具、换人）复核。

## 6.5 报告节奏模板【方法论】

| 频率 | 内容 |
|------|------|
| 每日 | 双渠道增量与异常 |
| 每周 | VI + 排名 + 索引 + 门禁，趋势与动作 |
| 每月 | 结果指标 + 归因复盘，策略调整 |
| 每季 | 阶段验收，路线图迭代 |

| 6 | 新站以 GSC 实测曝光为主判据，建新页 ROI 低于优化老页（§2.4） | 缺口词合计 10 曝光 vs 赢家簇 61 曝光（47%） | ✅ 强验证 |

| 9 | Schema 非银弹，可见结构优先（§4.3 原则 2） | Schema 全覆盖但 AI 仍建议"补 Schema"；引用来自内容结构与索引 | ✅ 验证 |
| 10 | llms.txt 对 Google 无效、对引用无证据影响（§4.4.1【官方】） | 9,012 引用来自 Bing 索引与内容结构，与 llms.txt 无关 | ✅ 与官方一致 |

| 14 | 技术正常时不追加技术投入，瓶颈在内容/权威（§5.1） | 技术 SEO 全项正常 + 排名 50–80 → 投入转向差异化与深链 | ✅ 验证 |
| 15 | 声明≠实现按法律权重排序收口（§5.1） | R7 事故：定价页承诺 50MB 实际 10MB，曾只改文案侧未碰根因 | ✅ 教训实证 |
| 16 | 静默假成功 = 头号失败模式，命中数断言防线（§6.4） | Edit 静默失配/门禁扫 0 文件/注入落引号外等多次实际发生 | ✅ 教训实证 |

# 附录 B 通用工具与门禁设计

> 以下为门禁体系的设计蓝图【方法论】；实现命令与脚本因技术栈而异（bookconv.com 的具体脚本清单见单站实施版手册附录 B）。

| 门禁 | 通用设计 | 顺序 |
|------|---------|------|
| 语法全扫 | 对全部内容文件做 parse（模板串/引号/转义类错误），**最先跑** | 1 |
| 内容完整性 | 数据结构与注册表一致性校验 | 2 |
| 声明一致性 | 对外"声明 ≠ 实现"扫描（权益/承诺类文案） | 3 |
| GEO 合规 | 页面级要素评分（§4.5），PASS/WARN/FAIL | 4 |
| 重复标题 | 归一化比对全站 headings | 5 |
| 类型检查 | 静态类型（如 `tsc --noEmit`） | 6 |
| 部署断言 | push 后 curl 线上断言新内容出现 | 7 |

**数据工具设计要点**：GSC 取数走代理时注意 HTTP 客户端是否读代理环境变量；Bing WMT 各导出表含 1 空汇总行（交集前剔除）；GSC 生成式 AI 数据 API 拿不到，只能 UI 手动 CSV；Bing 每日导出必须同时保存全部 AI 相关表，否则无法跨期对比。

# 附录 C 通用避坑清单

> 从 bookconv.com 个案中抽象出的**普适性教训**（教训本身通用，事故细节见单站实施版附录 C）。

## C.1 内容与代码层
| 通用坑 | 通用防线 |
|--------|---------|
| 内容文件里的特殊字符破坏构建（模板串/引号/转义） | 语法全扫门禁 + 参照样板文件的写法 |
| 批量脚本"追加"而非"替换" → 重复内容 | 只允许定点替换；注入前查同名标题 |
| 多语言/前缀泄漏进 canonical | 语言感知逻辑集中一处，绝不硬编码前缀 |
| 编造结构化数据（评分/社媒链接） | 只用真实数据，没有就留空 |

## C.2 部署层
| 通用坑 | 通用防线 |
|--------|---------|
| 构建失败静默服务旧版本 | push 后线上断言新内容出现 |
| push 到不监听的仓库 | 确认部署目标链路 |
| 批量改后只看本地不看线上 | 部署生效等待 + 线上复核 |

## C.3 SEO / 数据层
| 通用坑 | 通用防线 |
|--------|---------|
| sitemap lastmod 用动态时间 | 用内容真实更新时间 |
| 把 UI 目视数据当导出数据对比 | 只用同格式数据 |
| 跨导出窗口对比 | 先核对分母/求和 |
| 小样本下结论 | ≥7 天或泊松检验 |
| 裁剪基线造叙事 | 先确认基线是否被裁 |
| "声明 ≠ 实现"只改低权重面 | 按法律权重排序收口（要约>宣传>科普>文档） |
| grep 关键词遗漏其他语言版本 | 修复后双语/全语言跑验证 |
