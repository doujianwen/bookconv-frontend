## 1. 触发条件（六问，任一为"是"才沉淀）

任务完成后问 6 句话，30 秒内答完：

| # | 问题 | 若"是" |
|---|---|---|
| Q1 | 这个决策后来可能被**别的项目**复用吗？ | 值得沉淀（职能四） |
| Q2 | 过程中**踩过坑**，且坑看起来"很合理"？ | 值得沉淀（失败案例） |
| Q3 | AI 在这里的表现有**可讲的模式**（好的或坏的）？ | 值得沉淀（职能三） |
| Q4 | 结论有**可复核证据**（命令/数据/哈希）？ | 可升 VERIFIED |
| Q5 | 有人问"你怎么做到的"，需要完整讲 10 分钟以上？ | 值得独立文档 |
| Q6 | 只是重复劳动 / 一次性操作？ | **不沉淀**，跳过 |

**判定输出只有两种**：`沉淀` / `不沉淀`。**没有"先记下来回头整理"**——那等于不沉淀。

## 2. 最小动作（两种，按重量选）

### 2.1 轻量：一行素材标记（95% 的情况）

在**已有的**开发记录 / 工作日志 / 任务复盘末尾追加一行：

```
[素材] 2026-11-02 | 分类:07-Debug | 状态:CURATED | 一句话: 0/14字节被误判为用户错误，
服务器直连实测推翻 | 证据: 诊断_转换失败_空文件与过小输入_2026-11-02.md §3 | 可公开:⚠️脱敏
```

字段固定 6 个：**日期 / 分类(01-20) / 状态 / 一句话结论 / 证据指针 / 可公开性**。

> 为什么是一行：因为一行可以顺手写；一张表会拖延；一个模板会放弃。

### 2.2 重量：独立案例文档（仅当 Q5 = 是）

放 `docs/learning-materials/` 下的 `cases/` 子目录（**首次产生案例时创建**，不预先建空目录），按 §2 的 17 字段结构填写，命名：

```
case-YYYY-MM-DD-<短横线英文slug>.md
```

完成后在 `BookConv-实战素材库索引-V1.0.md` 对应分类表格**加一行指针**。

## 3. 状态晋级（不许跳级）

| 晋级 | 条件 | 谁来做 |
|---|---|---|
| RAW → CURATED | 结构完整、可独立读懂（不依赖对话上下文） | 产出者本人，当次完成 |
| CURATED → VERIFIED | 补上**可复核证据**：命令输出 / 数据快照 / 文件哈希 / 可复现步骤 | **必须换人或换会话复核**（不能自己验自己） |
| VERIFIED → TEACHING_READY | 写清教学点 + 至少 1 个讨论题/练习题 + 公开性判定 | 课程设计时批量做 |

**降级规则**：结论被新证据推翻 → 立即降级，并在 `docs/training-materials/README.md` 勘误表加一条（保留旧结论 + 标现行结论 + 保留理由）。**不删。**

> 依据：现有勘误表机制（5 条已证伪结论仍保留）是项目最有教学价值的设计之一。

## 4. 证据回溯行（解决缺口 M-5）

凡新增/修改 SOP、手册、方法论，**末行必须写**：

```
> 证据回溯：<3-8 字结论> ← <证据文件路径>#<章节>（<日期>，<状态>）
```

示例：
```
> 证据回溯：push≠deployed ← _archived/ops-history/ops-execution/git-deploy-sop.md#L12（2026-08，VERIFIED）
```

> 规则理由：方法论文档若不写"来自哪条真实证据"，半年后无法判断它还成不成立，也无法在教学时给出可信出处。

## 5. 挂载点（不新增长任务）

| 节点 | 动作 | 耗时 |
|---|---|---|
| 每次实质任务收尾 | 答 §1 六问，是则写 §2.1 一行标记 | ≤30 秒 |
| 周评审（周一）末尾 | 扫本周标记，判断是否有 ≥1 条该升 CURATED / 该建独立文档 | ≤5 分钟 |
| 月度复盘（如 11/18 竞品深度） | 批量做 CURATED→VERIFIED 复核 + 更新索引表 | ≤30 分钟 |
| 课程/内容生产前 | 从索引取 TEACHING_READY 素材，不临时找 | — |

## 6. 反模式（明令禁止）

| 反模式 | 为什么有害 |
|---|---|
| 建 20 个空目录宣布"素材库建成" | 用结构冒充内容 |
| 为写课而额外开发功能 | 违背职能三"副产品"原则 |
| 把 AI 输出直接标 VERIFIED | 未经验证的经验会污染课程 |
| "先全部记下来，回头整理" | 回头 = 永不 |
| 复制原始证据到素材库 | 产生双份真相，改一处漏一处 |
| 删除被证伪的旧结论 | 摧毁最有价值的教学材料 |

## 7. 验收：机制真的在跑吗（可证伪）

机制不是文档，是行为。三个月后用三个问题自检：

1. `grep -r "\[素材\]" docs/ .workbuddy/memory/ | wc -l` → 是否 > 0 且随时间增长？
2. 素材库索引里 VERIFIED / TEACHING_READY 的数量是否在变？
3. 最近一次周评审记录里，是否出现过"本周无素材，跳过"？——**允许出现"无"**，因为机制允许空转；但**不允许连续 4 周无记录且无"无素材"判断**（说明机制已停摆）。
