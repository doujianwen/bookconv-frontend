## 一、服务器实测真相（Ground Truth）

| 项 | 实测值 | 对原方案的影响 |
|---|---|---|
| OS | Ubuntu 24.04.4 LTS，kernel 6.8.0-138，x86_64 | 无 ARM 构建风险（比 Oracle 路线 B 好）|
| 内存 | **3.6Gi** 总 / 716Mi 用 / 2.9Gi 可用；Swap 1.9Gi | 原按 4Gi 估算 → 下调 `MemoryMax` |
| CPU | 2 核（nproc=2）| 并发锁 1；`CPUQuota` 需保守 |

**关键修正**：原方案依赖 `docker-compose.yml` / `worker/Dockerfile`，但本机无 Docker。且 `worker/` 只暴露 `/health:3001`，**不提供 `/api/convert-internal`**——所以无论 Docker 还是原生，都**必须新写后端 HTTP 服务**（WP1）。

## 二、对原方案的三处修正

1. **后端形态**：Docker 不可用 → 推荐 **原生 systemd Node 服务**（零新增 daemon、攻击面最小、cgroup 上限用 systemd 原生指令）。备选：现装 Docker 跑 `worker` 镜像。
2. **内存上限**：3.6Gi 实测 → `MemoryMax=1.2G`（保守，留 ≥2.4Gi 给 OS+MariaDB+PHP+nginx+swap）。Calibre 峰值 0.5–1G 被 1.2G 兜住，且 systemd `MemoryMax` 触发的是 **cgroup 内 SIGKILL（仅杀 BookConv 单元）**，不会引发全局 OOM → GEO 安全（R1 正面化解）。
3. **临时文件**：单根 fs → Calibre 解压临时目录挂 **tmpfs（1G, noexec）**，转换输出 ephemeral 不落盘，根除 R2 磁盘占满。

## 三、最终隔离边界（六层，针对本机定稿）

```
HK 2C/3.6G 服务器（Ubuntu 24.04）
├── GEO 增长系统（ untouched ）
│   ├── /var/www/tuozhigeo        www-data:www-data（WordPress）
│   ├── mariadb 127.0.0.1:3306    mysql 用户
│   └── nginx server block: tuozhigeo（不动）
│
└── /opt/bookconv-conversion/     ← 单独文件夹，与 GEO 完全隔离
    ├── app/                      slim Node 服务（包 calibre.ts 转换逻辑）
    ├── .env                      （仅 CONVERSION_INTERNAL_SECRET）
    ├── data/tmp/                 tmpfs, size=1G, noexec（Calibre 临时）
    └── logs/
```

| 层 | 实现（本机具体值）|
|---|---|
| ① 文件夹 | `/opt/bookconv-conversion/*`，与 `/var/www` 物理分离 |
| ② 用户 | 新建 `bookconv-backend`（nologin），与 www-data/mysql 互不可读 |
| ③ 进程 | 独立 systemd 单元 `bookconv-conversion.service`，重启不误伤 GEO |
| ④ 资源硬上限 | `MemoryMax=1.2G` / `CPUQuota=70%` / `IOWeight=50` / `OOMScoreAdjust=800`（BookConv 优先被杀）；GEO 服务 `OOMScoreAdjust=-500`（受保护）|
| ⑤ 磁盘 | tmpfs 挂 `data/tmp`（1G, noexec），写满根盘风险=0 |
| ⑥ 故障 | Vercel 侧 failover → CloudConvert（后端死连不 503）+ 熔断 |

**安全通道（Vercel → 后端）**：Vercel 出口 IP 不固定，**无法用云防火墙锁 IP**。采用：
- **主选**：nginx 新增独立 server block（子域名 `convert.tuozhigeo.com` 或 `convert.bookconv.com`，需 DNS A + certbot LE 证书）→ `proxy_pass http://127.0.0.1:3001`，带 `client_max_body_size 50m` + `limit_req` 限速 + 透传 `CONVERSION_INTERNAL_SECRET`；后端进程**仅监听 127.0.0.1**，绝不公网直连。GEO 现有 block 不改（`nginx -t` 后 reload）。
- **备选（零 DNS）**：后端自签 TLS 直连 `https://43.129.176.38:3001`，Vercel 关闭证书校验。加密无身份认证，仅作 fallback。

## 五、上线顺序铁律（不可颠倒）

1. **WP4 failover 必须先合并并验证**（Vercel `route.ts`：后端失败/超时→回退 CloudConvert + 熔断）。否则后端故障 = 全站 503。这是 P0 前置。
2. 上机顺序（每步验收）：建用户/目录/tmpfs → 装 node+calibre → 部署后端 → 配通道 → 本机 `curl` 验 `/health` + 真实转换 → 私网联调 Vercel 预发环境 → 置 `CONVERSION_BACKEND_URL`（先预发验证）→ 监控 3 天 → 切生产。
3. **回滚**：`systemctl stop bookconv-conversion` + `CONVERSION_BACKEND_URL` 置空即全量回 CloudConvert。
