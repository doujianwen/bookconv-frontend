# GA4 重导 + 事件验证操作清单

**目标**：让下一份 GA4 导出带上真实转化事件数据，从而能跑「着陆页 → 上传 → 完成」漏斗。
**前置事实**：你新建的文件上传 / 转换完成自定义事件在 **2026-08-10**，而现有三份数据窗口止于 **2026-08-09** → 事件在窗口外，所以关键事件全是 0。重导 + 验证后才能谈漏斗。

---

## A. 重导 GA4（窗口必须覆盖 2026-08-10 之后）

1. 登录 GA4 → 右上角**日期范围**改成 `2026-08-10 ~ 今天`（至少 14 天，别再用 0713–0809）。
2. 重新导出这三份（和之前同一套报表）：
   - **流量获取** → 带来会话的主渠道组（默认渠道组）
   - **用户获取** → 带来用户首次互动的主渠道组（默认渠道组）
   - **参与度 / 着陆页** → 着陆页
3. **新增第 4 份（漏斗必需）**：报告 → 参与度 → **事件** → 导出，确认 `file_upload_*` / `conversion_complete` 有计数。
4. 全部导出为 **CSV**，发我。

> 口径提醒：届时报表里应出现 **Organic Search（自然搜索）** 渠道——如果还没有，说明 GSC 那边仍 0 点击，属正常，继续等。

---

## B. 验证自定义事件真在触发（P0，必须做）

1. GA4 → **管理** → **数据流** → 选网站数据流 → 打开 **DebugView（调试视图）**。
2. 另开标签打开 bookconv.com，**自己真实跑一次转换**：上传一个文件 → 等转换完成。
3. 回 DebugView 看事件流：应能看到你建的事件（建议名 `file_upload_start` / `conversion_complete`，**以你后台实际命名为准**）流入。
4. 若**看不到事件**：
   - 查 GTM / gtag 这段有没有部署到生产（本地能跑 ≠ 线上已发）；
   - 查事件名拼写是否和代码里完全一致（大小写敏感）；
   - 查是否绑对了这个数据流。
5. 备用验证：报告 → **实时**，自己转换一次，看实时事件里有没有出现。

---

## C. 把事件标记为「关键事件」（⚠️ 最容易被漏的一步）

> 即使事件在触发，没标记成关键事件，「关键事件数」那列**永远 = 0**，漏斗和转化率就永远算不出来。

1. GA4 → **管理** → **事件** → **关键事件** 标签页。
2. 找到 `file_upload_start` / `conversion_complete`（或你实际命名的转换完成类事件），**切换为「标记为关键事件」**。
3. 等 ~24 小时让配置生效，再重导（见 A）。

---

## D. 验证通过后，重新发我导出，我能做这些分析

| 分析 | 用到的数据 | 回答的问题 |
|------|-----------|-----------|
| 转化漏斗 | 着陆页 + 关键事件 | 着陆页 → 上传 → 完成 的转化率与流失点 |
| 渠道 × 关键事件 | 流量获取 + 关键事件 | 哪条渠道带来真实转换（外链值不值） |
| 着陆页 × 关键事件 | 着陆页 + 关键事件 | 哪类页面（博客/指南/转换页）转化最好 |
| 与 GSC 对齐 | GSC 查询词 + 着陆页 + 关键事件 | 哪些有机词真正带来转化（非只看展示） |

---

## E. 时间预期（别急）

- 事件需**累积数日样本**才有意义，建议重导窗口 ≥ 14 天。
- 不要导出 1–2 天就下结论（会和现在一样样本过小）。
- 同时顺手做 P1：给所有外链 / 社媒加 **UTM 参数**，消灭现在的 `Unassigned`（2 会话归因丢失，会低估外链效果）。

---

## F. 一句话自检

重导后如果「关键事件数」**还是 0**，按这个顺序查：
① 事件根本没触发（B）→ ② 触发了但没标关键事件（C）→ ③ 窗口又没覆盖到（A）。
三项全过，漏斗就能跑。
