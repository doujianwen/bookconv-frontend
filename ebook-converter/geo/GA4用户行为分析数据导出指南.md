# GA4 用户行为分析 · 数据导出指南（bookconv.com）

> 沉淀于 2026-08-10。用途：当需要把 GA4 数据导出给 AI/团队做用户行为分析时，按本指南的维度/菜单/格式导出，避免拿到一堆看不懂的报表。

## 0. 这份指南解决什么

GA4 里"看报表"和"导出能分析的数据"是两回事。本指南按**你想回答的问题**反向列出要导出的交叉表，针对 bookconv 这种转换工具站定制。核心原则：先定问题，再定导出维度，而不是把整站数据 indiscriminately 倒出来。

## 1. 前置检查（决定分析深度）

先确认 GA4 是否给「文件上传 / 转换完成」打了**自定义关键事件**：

- **有** → 能看到真实转化漏斗（访问 → 上传 → 完成）
- **没有** → 只能分析到"页面互动层"（浏览/滚动/点击），看不到真转化
- 没做埋点 → 先补一次，再导出才有意义

> **本项目状态**：GA4 自定义关键事件（文件上传/转换完成类）已于 **2026-08-10 新建**。此前无埋点，只能分析到页面互动层；现在转化漏斗分析（③）已可做。

## 2. 导出清单（按优先级）

### ① 必导：自然搜索着陆页表现
- **位置**：GA4 → 参与度 → 着陆页，渠道筛选器选「自然搜索」
- **维度/指标**：着陆页路径 | 会话数 | 活跃用户 | 跳出率 | 平均参与时长 | 关键事件数（若有）
- **格式**：CSV
- **用途**：哪些自然着陆页带来最多参与？哪些高意图词着陆页跳出率高？→ 直接决定内容深化 / 外链权重优先级

### ② 必导：渠道对比
- **位置**：GA4 → 获客 → 流量获取
- **维度/指标**：渠道（organic / direct / referral / social）| 会话 | 用户 | 参与率 | 关键事件
- **格式**：CSV
- **用途**：确认 organic 占比与质量，与 GSC 搜索表现交叉验证

### ③ 进阶：站内转化漏斗（需自定义事件）
- **位置**：GA4 → 探索 → 漏斗探索
- **步骤设**：转换页浏览 → 上传点击 → 转换完成 →（可选）注册/付费
- **格式**：漏斗步骤表 CSV
- **用途**：30 个转换页的转化断点卡在哪一步（本项目自定义事件已建，此层现在可做）

### ④ 进阶：路径分析
- **位置**：GA4 → 探索 → 路径探索，起点选 `/convert/*`
- **格式**：用户去向表 CSV
- **用途**：内链加权（azw/lit/chm→mobi 等）是否真把流量导到高价值页（博客/指南/定价）

### ⑤ 可选：设备 / 技术
- **位置**：GA4 → 用户 → 技术 → 设备 / 平台
- **格式**：CSV
- **用途**：移动端行为差 → 指向 Core Web Vitals 或响应式问题（本项目 CLS 已优化至 0.003，可验证效果）

## 3. 导出给我的方式

- **单个报告**：GA4 右上角「导出」→ 下载 CSV / Google Sheets（最简单）
- **整站 / 时间序列**：连 Looker Studio 后导出，或用 GA4 Data API 拉（免费版额度够用）
- ⚠️ **BigQuery 每日导出仅 GA4 360 付费版**有，免费版别走这条路
- 文件发我即可，我直接读 CSV 分析

## 4. 与 GSC 的配合

- GA4 看"用户进来后干嘛"，GSC 看"用户怎么搜进来"
- 两者按着陆页 / 查询词对齐 = 完整图景
- 本项目四批 SERP 分析用的 GSC 数据，正好能和这份 GA4 交叉验证

## 5. 标准事件命名建议（供埋点参考）

若需统一/补全事件名，建议：

- `file_upload_start` — 用户选文件/拖拽
- `file_upload_complete` — 上传成功
- `conversion_start` — 点击转换按钮
- `conversion_complete` — 转换成功返回结果
- `conversion_error` — 转换失败（诊断漏斗漏点）

> 具体名称以 GA4 后台实际配置为准；导出前请先确认事件已标记为"关键事件"且开始收集数据（新事件需累积数日才有样本）。
