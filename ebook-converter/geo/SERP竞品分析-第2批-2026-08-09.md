## 4. 贯穿性发现：MegaConvert 程序化多语言矩阵（本批头号情报）

跨 13 词搜索反复出现**同一类对手（程序化矩阵 cohort）的本地化页面网络**：

- `epub → azw3`：MegaConvert nl / it；iFormat 同跑
- `mobi → epub`：MegaConvert sv / id / nl / es
- `lit → epub`：MegaConvert pt；**iFormat.io / FileCraft 同 cohort**
- `azw → mobi`：MegaConvert es / fr / zh
- `mobi → epub`（西语）：MegaConvert es 矩阵页

**打法本质（已升级为行业 table-stakes，非 MegaConvert 独有）**：用 hreflang + 模板化页面，对每个 `[语种][格式]to[格式]` 长尾生成独立 URL，靠**页面量 + 语种覆盖 + 内链矩阵**吃下非英语长尾。这正是它们排在我们前面的真实原因（而非"匿名小工具站"——Batch 1 报告曾误判，本次复搜纠正）。

> ⚠️ **矩阵已是行业级 table-stakes**：本次复搜证实 **iFormat.io**（lit-converter hub + 多格式页 + 批量 + 信任四件套）、**FileCraft**（模板化 10 源 / 31 标矩阵）同样在跑同一打法。故准确表述应为「我们落后于**程序化矩阵 cohort**」，而非单点落后某一家。

**我们的对照短板**：i18n 框架就绪（en/es），但仅 `/es` 激活；其余语种零覆盖。→ 这是比单页 on-page 优化大得多的**战略杠杆**，且与「首页外链」同级，应在路线图标高位（受你「首页外链优先」节奏约束，但须显位标注，不在此批 on-page 范围）。

**可执行首步（多语言矩阵）**：按 GSC 各语种展示量优先级，激活 N 个语种的转换页本地化（i18n 已就绪，边际成本低）；首期可先用西语矩阵（es）对标 MegaConvert es，已验证可行。
