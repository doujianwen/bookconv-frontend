# 05｜BookConv 每日经营管理规范（CEO 日常管理）

## 1. 每日经营任务安排（CEO 每天 1-3 项）

候选池（按当前经营风险排序，CEO 每日从中指定，禁止"只跑已有自动化"充数）：

1. **GA4 真实用户行为核读**：读 `_wb_tmp/ga4-fetch-status.json` 新鲜度 + 巡检日报中「上传→完成/失败」与 UNKNOWN 归因，指定 1 个转化堵点。
2. **SEO/GEO 机会执行**：从周度主表 Query×Page 机会中挑 1 条，落地为页面/标题/TDK 动作（不是只记录）。
3. **Bing 提交队列健康**：核对 `_wb_tmp/bing-submit-progress.json` 增量是否真的提交（抽查 1 条 URL 在 Bing 收录）。
4. **失败自动化止血**：按 03 报告 F 类清单核销一项（如三合一分析失败原因）。
5. **外链推进**：`BookConv_500_Backlinks_Master.csv` 中推进 1 条候选→已联系→Live Verified 状态迁移（当前无自动化承载，靠人工+会话执行）。

每项任务必须写明：目标/执行账号/完成标准/证据要求/截止时间/验收方式。

## 2. 《BookConv 每日经营结果》模板（存 `WB-BC-20261115-01/每日经营结果/YYYY-MM-DD.md`）

```
# BookConv 每日经营结果 YYYY-MM-DD
1. 原计划：
2. 实际完成：
3. 达成目标：
4. 未完成及原因：
5. 已修复问题：
6. 仍存在问题：
7. 实际经营成果（GA4/GSC/Bing/外链/产品 五行数据，均标数据日期）：
8. 明天最重要的一件事：
```

填写纪律：只写有证据的行；没有就写 UNKNOWN/无；禁止把自动化运行成功填进第 7 行。

## 3. 状态五层口径（指挥台与日报统一）

CONFIG_ENABLED（配置启用）→ CURRENTLY_RUNNING（有真实运行证据）→ EXECUTOR_COMPLETED（执行器回执完成）→ BUSINESS_OUTCOME（业务结果产生）→ INDEPENDENTLY_VERIFIED（独立验收）。**只允许由证据驱动逐级上升，禁止跳级、禁止用 CONFIG_ENABLED 冒充 RUNNING。**

## 4. 归档链

每日经营结果 → 当日 23:00 日志归档（node 路径修复后）→ 全局 worklogs → 周五由 CEO 汇总周报。归档失败即 P0（当日必须人工补记）。
